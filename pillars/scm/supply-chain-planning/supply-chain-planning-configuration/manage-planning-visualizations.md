# Manage Planning Visualizations

- **Task code:** CUSTOM_PLANNING_VISUALIZATIONS
- **Purpose:** Find, create, edit, duplicate, or delete a Visualization for a supply plan, including its requested data, filters, layout, and access when creating or editing.
- **Execution rule:** The user completes the approved change manually in Oracle Supply Chain Planning's Visualizations and Analysis Sets page or, for metadata updates and review, from an opened existing Visualization, whether a table or graph; no API, import, automated configuration, or browser automation.

Use the standard manual workflow in [shared.common.manual-tasks](../../../../shared/common/manual-tasks/SKILL.md).

Provide manual steps directly from this task using the user’s supplied values. Stay within the documented guidance, identify missing details, and do not create separate guides or project artifacts solely to explain the steps.

## Manual steps

1. Identify the target plan, requested operation (Find, Create, Edit, Duplicate, or Delete), and Visualization name; for Duplicate, identify the new name. For Create or Edit, establish the business question, measures, dimensions and hierarchy levels, filters, Table or Graph choice, layout, and Public or Private access. For a graph, identify its type and intended axes, slices, groups, or series. Resolve any missing choice that changes the result before entering it. Check the active plan and leave unrelated plan setup unchanged.
2. In Oracle Supply Chain Planning, open **Navigator** > **Supply Chain Planning** > **Supply Planning**. Open the target plan, then choose **More** (...) > **View More** in its header. Under **Actions** > **Pages and Visualizations**, open **Visualizations and Analysis Sets**. For Create, choose **Create Visualization**. For an existing Visualization, find its row before choosing the requested action.
3. To find a Visualization, search by the requested name using the search field or **Name** facet. The keyword field can also match descriptions, so verify the row's full **Name** and **Type**. If several rows match, narrow by Name and Type. If the expected row is absent, review active search chips and plan-type filters, including the default plan-type filter; adjust only the filters needed and search again.
4. To duplicate, find the source and select exactly one matching row, then choose **Duplicate**. In the drawer, replace the proposed Copy-suffixed **Name** with the requested new name. Review **Description**, **Access**, **Enabled in Plan Type**, and **Group**; the drawer requires Name, Access, Enabled in Plan Type, and Group, and rejects a name already in use. Choose whether to **Copy user-specific layout changes** and which available **Links to Copy**: links to other tables, graphs, and pages; links from them; or links to external systems. Copy only what the requested result needs. Select **Save**, then find the new row and confirm that the source row remains.
5. To delete, find the exact row and select only that row; **Delete** can act on every selected row. Recheck its full Name and Type immediately before choosing **Delete**. The action is available only to the owner or creator; if disabled, stop for the access limit. Read the confirmation dialog, which states that deletion cannot be recovered, and confirm only for the intended row. Search again with the relevant filters to verify that row is gone while accounting for similarly named rows.
6. Create and Edit open the Visualization editor with **Properties**, **Data**, **Layout**, and **Comparison** tabs. In **Properties**, enter the name and a useful description. Choose the group, **Enable in Plan Type**, Visualization Type, and Public or Private access as requested. Use **Table** for a pivot grid or **Graph** for a chart. On an existing Visualization, the Table or Graph choice is locked; use the graph-type control in Layout when editing a graph. Use **Comparison** when the requested result needs one and the selected type offers it.
7. In **Data**, select the requested measure or measures, then only the dimensions, hierarchies, and levels needed for the result. Check the selected counts. A Data selection does not set its final position in the Layout. After selecting dimensions in **Data** > **Hierarchies**, open **Data** > **Unassociated Members**. This tab lists the dimensions selected in Hierarchies. Review or select the required unassociated member for each listed dimension, and recheck the tab if the selected dimensions change.
8. Set requested **Measure Criteria** in **Data** after selecting the measure and dimensions. Choose **Add**, a selected measure, the available **Condition**, and **Basis**. Enter a value or comparison measure where required; **Between** needs a second value, while empty and not-empty conditions need neither a basis nor value. Set decimal places only if needed. For every criterion, including a single criterion, open **Levels**, select each dimension whose calculation level matters, and choose its hierarchy and level. The application aggregates the measure at the selected level combination before evaluating the condition. Use requested evaluation levels when supplied. If they are missing and the choice changes the result, resolve the intended levels; do not silently reuse the Layout levels because criterion evaluation levels can differ from displayed levels. For multiple criteria, set **And or Or**; do not mix the operators within one Visualization. Review the measure, condition, basis, values, decimal places, and Levels in the criterion list. If the tab is unavailable or a criterion is incompatible, revisit the measure and dimension choices.
9. Set requested member filters in **Data**. For explicitly named members, open **Members**, choose the applicable dimension, hierarchy, and level, and select the required members manually. For an attribute-based rule, open the separate **Member Criteria** subtab, then choose the dimension, hierarchy, level, attribute, condition, and value when required. Do not direct the user to find Member Criteria within **Members**. Check matched-member counts, returned names, and the filter summary.
10. Before setting a requested time window, check whether each selected measure is associated with the Time dimension. If none are time-related, **Time Members** is not applicable; do not configure a time filter or imply that one changes those measures. Otherwise, open **Data** > **Time Members** and choose the hierarchy and level. Use **Automatic** to derive the displayed period range from the current plan options at the selected level; do not enter dates or relative counts for this choice. Alternatively, use a relative range from plan start or today with Before or After and nonnegative period counts, a **Range** with From and To dates inside the plan limits, or explicit periods from the selected-level tree. If the Visualization mixes time-related and non-time-related measures, the time selection applies only to the time-related measures; use **Show Unassociated** for the Time dimension to control whether values from measures without Time are hidden or displayed as unassociated. Check the displayed period range or **Show Selected**. Correct any date or relative-range warning before continuing.
11. After selecting the measures, dimensions, and requested filters in **Data**, select the **Layout** tab in the same Create/Edit editor. For a Table, place fields by their handles into **Columns**, **Rows**, **Filter bar**, or **Hidden layers**, in the requested order. For a Graph, choose the offered **Graph Type** in **Visualization Properties**. For bar, line, area, or combination graphs, assign hierarchies or **Measures** to X and Y; use Y2 only for individual measures when offered and needed. Set titles, labels, scales, and combination shapes where requested. For pie, set the slice hierarchy and label and hover formats; for bubble, a hierarchy and distinct X, Y, and size measures; for treemap or sunburst, the structure, levels or hierarchy, sizing and color measures, depth or rings, and hover format; for radar, **Group**, **Series**, and 3 to 10 selected measures. Put requested graph filter **Levels** under Layout **Filters**. When a hierarchy is assigned to the X or Y axis, do not assign all its selected levels to Filters; retain at least one level for the axis. Resolve incompatible selections by removing the conflicting filter level or changing the axis hierarchy while preserving the intended result. These controls are separate from Data member and time filters. Resolve any blocking validation error before saving. In **Layout** > **Visualization Details**, configure **Legend Position**, **Show Data Labels**, and **Legend Interaction** when available for the selected graph type. Set **Legend Position** to **Bottom**, **Left**, **Right**, or **Top** to suit the requested layout. For data labels, choose **Always** when values should remain visible or **Only on mouse over** when values should appear on hover, where offered. Set **Legend Interaction** to **Click to Drill** for drilling into the selected data or **Click to Hide** for hiding the selected series. Use only options available for the selected graph type. If a preference is unspecified, retain the current setting unless clarification is needed. Review the configured legend, label, and interaction settings here; verify their rendered behavior using the context-specific review procedure in step 13.

    For bar, line, area, and combination graphs, explain the axis selections and their expanded options when guiding an axis update:

    - **X Axis** and **Y Axis** offer hierarchies selected in **Data** or the **Measures** group. Configure both axes, place Measures on one axis, use no more than three selections across X and Y, and do not repeat a selection. **Y2 Axis**, when offered, accepts individual measures only.
    - Under each applicable axis, expand **Show More** to configure its title, label rotation, and automatic or manual scale where offered. Describe these controls as part of the axis guidance rather than only listing the axis assignments. Use the label-rotation choices shown in the application; this task does not enumerate their exact values or assume every axis and graph type offers the same controls.
    - For an automatic scale, let the application determine the bounds and increments. For a manual scale, enter the requested minimum, maximum, and increment in the available fields. Check X, Y, and Y2 separately wherever scale controls appear; minimum must not exceed maximum, and the increment must be positive and smaller than the available range.
    - For a combination graph, choose **Area**, **Bar**, or **Line** for each measure's shape where offered. Retain existing titles, rotation, scales, and shapes when no change is requested. Verify the resulting labels, scale, and series using the context-specific review procedure in step 13.

12. If **Comparison** is requested and enabled, open the **Comparison** tab in the Create/Edit editor. For an already open table or graph, choose **Actions** > **Edit Properties** > **Comparison**. Configure either waterfall or trend analysis; they cannot be displayed together.

    - For waterfall, select **Display waterfall analysis**, then select the requested archive periods.
    - For trend, select **Display trend analysis**, then specify the number of archives to include.
    - For a requested MAPE calculation, select **Use MAPE calculations** in the chosen analysis section. The archives must already have been created with **Enable for MAPE calculations** selected. Verify that the selected archives meet this prerequisite; incompatible archives prevent saving. If suitable archives are unavailable, report the missing prerequisite rather than selecting ordinary archives or silently clearing the MAPE option.
    - Resolve any Comparison banner. Review and save using the applicable context in step 13. **Apply** and **Apply and Close** are available only when editing metadata from an opened existing Visualization, whether a table or graph, not when creating or editing from **Visualizations and Analysis Sets**. Applying changes for review does not establish that they were saved. After saving, reopen the Visualization and confirm that the chosen analysis, MAPE option, and archive selections remain.
13. Review Properties, Data, filters, Layout, and any requested Comparison together. Saving a Table or Graph is prevented while any validation error or conflict remains unresolved, including errors or conflicts in Properties, Data, filters, Layout, or Comparison. Resolve all validation errors and conflicts and correct any field or layout warning. Adding a criterion to the list does not persist the Visualization change. Choose the review and saving procedure for the current context:

    - **Create from Visualizations and Analysis Sets:** Preview is not available in the Create flow. Complete the configuration checks, select **Save and Close**, confirm success, then open the saved Visualization to review the rendered result. Do not direct the user to a Preview control or to **Apply** or **Apply and Close** during Create.
    - **Edit from Visualizations and Analysis Sets:** Preview through **Apply** or **Apply and Close** is not available in this editor either. Complete the configuration checks, select **Save and Close**, then open the saved Visualization to review the rendered result. Editing an existing row here is distinct from editing metadata from an opened Visualization.
    - **Edit metadata from an opened existing Visualization:** Open the already created table or graph so that its rendered content is displayed, then choose the Visualization's **Actions** > **Edit Properties** and the applicable metadata tab, such as **Data**, **Layout**, or **Comparison**. After making the requested edits and resolving validation errors, select **Apply** to review the changes in the opened table or graph while keeping the metadata editor open, or **Apply and Close** to apply the changes and close the editor. These actions provide the preview equivalent in this context; there is no separate Preview step to locate. Review the updated table or graph and return to **Edit Properties** for further corrections as needed. **Apply** and **Apply and Close** apply changes without saving; use **Save and Close** to persist the intended metadata changes. Confirm persistence by reopening the Visualization and checking its settings.

    In the rendered result, confirm values, table rows and columns or graph labels and series as applicable, filter controls, graph legend placement and interaction when applicable, and any requested Comparison. Verify that each Measure Criterion has the intended effect at its selected Levels. If a problem is found, correct the settings and repeat the review procedure for the current context. After saving, confirm the success message or find the exact Name and Type with relevant list filters applied, and reopen the Visualization to verify that the requested settings, criteria, and Levels remain.

## Manual validation

- For Find, verify the exact Name and Type, accounting for description matches and active plan-type filters. For Duplicate, verify that exactly one source row was selected, the new name is unique, the required drawer fields and requested copy choices are set, and a separate new row appears with the intended type, access, plan types, group, layout, and links while the source remains. For Delete, verify the selected row and owner or creator access before confirming; afterward, verify that the intended row is absent with relevant filters applied.
- For Create or Edit, confirm a unique name, at least one enabled plan type, the intended Table or Graph type and access, at least one measure, and the requested dimensions, hierarchy levels, and filters. Recheck Layout if Data selections changed.
- Check each Measure Criterion's selected measure, condition, required values, decimal places, and combination logic. For every criterion, verify the intended evaluation dimensions, hierarchies, and levels, including when only one criterion exists, and confirm in the rendered result, using step 13's context-specific review procedure, that the condition is evaluated at that aggregation grain. Check manually selected names under **Members**. For an attribute-based rule, verify the dimension, hierarchy, level, attribute, condition, value, and match count under the separate **Member Criteria** subtab; correct an unintended zero match or incompatible-filter message. For Time, verify each selected measure's dimension relationship, skip **Time Members** when none are time-related, confirm that **Automatic** shows the plan-derived range at the selected level, and check that mixed-measure display matches the **Show Unassociated** choice. Check relative ranges, date ranges, and explicit periods against the plan limits.
- For a Table, verify the fields and their order in each pivot-grid zone. For a Graph with X and Y controls, verify both axes, **Measures** on one axis, no more than three selections across them, no duplicate selection, and compatible Layout filter levels. Check manual scale bounds and increments on each available axis and complete the required fields for the selected graph type.
- For graph Layout filters, verify that each hierarchy assigned to an axis retains at least one selected level outside Filters. An unresolved filter/axis conflict prevents saving. Correct the selections, clear all remaining validation errors and conflicts, then review and save using the applicable context in step 13. Confirm that the saved layout persists after reopening.
- For graphs with axis **Show More** controls, verify each requested title, label rotation, automatic or manual scale, and combination measure shape in the rendered result using step 13's review procedure. For a manual scale, check the required minimum, maximum, and positive increment on each applicable axis. After **Save and Close**, reopen the Visualization and confirm the requested axis settings persist.
- For a Graph, verify the selected **Legend Position**, **Show Data Labels** behavior, and **Legend Interaction** in the rendered result using step 13's review procedure, including whether clicking a legend item drills into data or hides its series as requested. After **Save and Close**, reopen the Visualization and confirm these settings persist.
- For Comparison, verify that only one of waterfall or trend is displayed, with the requested archive periods or number of archives. When **Use MAPE calculations** is selected, confirm the archives were created with **Enable for MAPE calculations** selected and resolve any incompatible-archive validation before saving. After **Save and Close**, reopen the Visualization and verify that the analysis, MAPE option, and archive selections persist.
- Follow step 13's review procedure: for Create or Edit from **Visualizations and Analysis Sets**, save and open the Visualization to inspect the rendered result; only metadata editing from an opened existing Visualization, whether a table or graph, offers **Apply** or **Apply and Close** as the preview equivalent. Confirm values, labels or series as applicable, filter controls, and any requested Comparison. Verify that no validation errors or conflicts remain on any tab; saving is prevented until all are resolved. Correct any tab or validation message and repeat the applicable review procedure. Do not treat applying changes as proof of persistence. After saving, confirm the success message or find the Visualization in the list, accounting for list filters. Record its saved name and plan, type, access, key data selections, filters, and layout, along with any verification limit.

# Configure Planning Analytics Reference Lookups

## Purpose

Use these read-only Oracle Fusion REST lookups to retrieve the documented
dimension-catalog, dimension, hierarchy, planning-measure-catalog, planning-level, and level-attribute data
needed when configuring Planning Analytics. These lookups do not authorize a
write.

## Execution Boundary

Create, update, and delete operations are out of scope for these reference
lookups. Route those operations only through `core.data-loader` using the
task's registered REST business objects, `dimensionCatalogs`,
`planningMeasureCatalogs`, and `planningLevels`. Use the lookup nodes in this file only to read and
resolve existing catalog, dimension, hierarchy, measure-catalog, and level-attribute identity, and supported attribute names.

## Branch Execution Rules

| Situation | What Happens |
|---|---|
| Preflight selection | Identify the exact requested object and action. Require the inputs of that resolver before calling Fusion. If a child identifier is missing, return missing and identify the parent/collection lookup needed; do not guess or execute unrelated branches. |
| Explicit list request | Select the collection resolver for that object. Complete all pages and return complete, including an empty completed collection; do not demand a selected item identifier. |
| Requested identity | Require exactly one matching identity according to the selected resolver. Return found on success, not_found for zero exact matches, ambiguous for multiple matches, or mismatch for contradictory returned identity. Never take the first result. |
| Incomplete retrieval | Return failure for transport, authorization, malformed responses or incomplete pagination. Do not interpret these as an empty list or missing identity. |
| Collection or item completion | Use that lookup's own terminal; never continue into another catalog, hierarchy, measure or group solely because it follows in the resource file. |
| Catalog deletion evaluation | Select find_dimension_catalog_by_id or find_planning_measure_catalog_by_id for the requested catalog type and require an exact CatalogId. After a successful identity lookup, return delete_requested instead of found and run only the matching deletion gate. Missing required deletion evidence blocks the gate; never default it to safe values. |
| Deletion-gate completion | Return eligibility facts only. The invoking core.data-loader workflow still owns mutation preparation, validation, approval and execution. No terminal authorizes or performs deletion. |
| Supported-name validation | For creation/name validation, retrieve existing attributes as a collection; the candidate new AttributeName is not an existing-item selection filter, so its absence does not block creation-name validation. After the existing-attribute lookup, select the item or organization supported-name resolver through CPA.SELECT_LEVEL_ATTRIBUTE_NAMES. Return complete when retrieval is complete, even if the candidate is absent; the validation node classifies invalid or unresolved names. |

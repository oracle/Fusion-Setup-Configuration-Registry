# Manage Planning Measures Input Validation

### Seeded-state interpretation

For retrieved Planning Measure `IsSeeded`, FSCR interprets `1` as Yes
(seeded/predefined), and both `0` and `2` as No (custom/non-seeded). Apply
this rule consistently to existing-measure validation, update, delete,
Source List eligibility, and duplicate-source classification. A live metadata
description listing only `1=Yes` and `2=No` does not invalidate a returned
`0`: accepting `0` as No is an explicit FSCR interpretation rule. Preserve
the exact returned value and metadata in evidence; normalize only for rule
evaluation. Do not rewrite the baseline or insert this normalized value into
a create or update payload. Missing, null, unreadable, or unsupported codes
remain blockers. Non-seeded status alone does not bypass dependency,
editability, adapter, validation, or approval requirements.

### Duplicate payload field contract

For duplicate-origin `MeasureCalculationType`, capture source field presence,
exact value, and returned type. A missing field is not null: stop if source
evidence is missing. Resolve its create support, type, nullability, and
precision from the selected live REST schema and Data Loader attribute
metadata; incompatible contracts block the handoff. Under the current
integer/Number contract, retain `7` as an integer, not a string, float, or
boolean. For workbook/DAT transport, use its declared numeric representation
and retain the type evidence; text serialization alone does not authorize a
string REST value. Preserve an explicit source null only when the selected
adapter supports it; never replace it with zero, an empty string, omission, or
a default. A different live type requires a supported lossless mapping.
Recheck its copied value and type in the prepared source and immutable payload
before approval, then verify the saved value and type by readback.

For duplicate-origin `GoalValues`, do not copy the source value. Send
`"GoalValues": null` in a REST create payload; if Data Loader cannot represent
null, omit the field without blocking duplication. Do not substitute zero or
an empty string. Do not report `GoalValues` omission or preservation as a
duplicate outcome.
For duplicate origin, retain `RestAction=POST` solely as an ADF_REST Data Loader
control in every create source row, including copied associations. Omit
`RestAction` from Fusion REST JSON payloads constructed by the host. For the
selected Data Loader route, verify its registered ADF_REST type/import support,
RestAction in the live loader schema, and POST in every create row. Reuse the
existing session's schema validation; these checks satisfy this task's control
contract without inspecting server-internal JSON transformation or requesting
adapter attestation. Missing/wrong controls or unsupported metadata block;
a generated sample alone does not replace the live schema/source checks.

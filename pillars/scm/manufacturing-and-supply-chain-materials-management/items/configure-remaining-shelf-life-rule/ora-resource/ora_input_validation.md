# Configure Remaining Shelf Life Rule Input Validation

## Authoring Status

This contract requires POST RestAction and mutation HTTP method for every declared Remaining Shelf Life Rule operation, including header and detail create, update, delete, and detail-only flows. RemainingShelfLifeRuleId is mandatory and automatically generated by the owning skill exactly once per request during source preparation in the existing Data Loader schema required format. Every sheet and populated parent/child record within that request must use the same canonical generated value. Generation and propagation are owned by ora_defaulting_rules.md and occur before capture; do not ask the user to provide the value. Captured sources are validated without modification. Explicit header updates may supply Description, DemandAnchorDateType, or CategorySetId individually or together; preservation of all other header attributes is enforced by ora_design_enforcement.md. Header-creation and new-detail field checks retain their stated applicability. The registered business object is remainingShelfLifeRest. The REST endpoint generates MRSLRuleId for new headers and MRSLRuleDetailId for new details; these are distinct from the mandatory RemainingShelfLifeRuleId and do not substitute for it. DemandAnchorDateType resolves through ORA_MSC_SP_UI_MRSL_ANCH_DT when creating a header or explicitly updating that attribute. Apply the concrete checks below to the records, schema, and execution settings already captured and validated by Data Loader. This policy uses the existing declared execution route and registered components. Declared read-only lookup requests retain GET.

The task-local Rule ID inventory is MRSL.DEFAULT_DATALOADER_REQUEST_FIELDS, MRSL.DEFAULT_DEMAND_ANCHOR_DATE_TYPE, MRSL.RESOLVE_RULE_HEADER, MRSL.LIST_RULE_DETAILS, MRSL.VALIDATE_INPUT, MRSL.RESOLVE_DEMAND_ANCHOR_DATE_TYPE, MRSL.RESOLVE_DEMAND_CLASS, MRSL.RESOLVE_CATEGORY_SET, MRSL.RESOLVE_INVENTORY_ITEM, MRSL.RESOLVE_ORGANIZATION, MRSL.RESOLVE_CATEGORY, MRSL.RESOLVE_CUSTOMER, MRSL.RESOLVE_CUSTOMER_SITE, MRSL.RESOLVE_GEOGRAPHY, MRSL.RESOLVE_ZONE, MRSL.ENFORCE_DETAIL_OBJECT, MRSL.CHECK_EXECUTION_READINESS, MRSL.VALIDATION_COMPLETE, MRSL.HANDLE_FAILURE, and MRSL.RETURN_ISSUES. These nodes validate readiness only; runbooks and core.data-loader retain processing, payload, approval, and submission ownership.

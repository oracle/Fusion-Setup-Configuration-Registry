# Configure Remaining Shelf Life Rule Defaulting

The owning skill, through the existing runbook and core.data-loader source-preparation workflow, must generate exactly one RemainingShelfLifeRuleId per request using the existing Data Loader schema required format and propagate that same value across every sheet and populated parent/child record before source capture. Retain this canonical generated value in the request context and reuse it on repeated preparation passes for that same request; do not ask the user to provide it or generate another value per sheet, component, file, or record. The owning workflow must also apply the request defaults below before the load session captures the source and execution settings. POST is the required RestAction and mutation HTTP method for every declared task operation, including header and detail creation, updates, deletions, and detail-only changes. For the selected creation flow, retain the populated remainingShelfLifeRest parent record with all three request fields, including for a header-only request. HTTP headers used to call Data Loader do not populate these file fields. Incomplete or conflicting captured data requires corrected preparation and a fresh session; task rules cannot change the captured source or execution settings.

## Defaulting Boundaries

| Situation | What Happens |
|---|---|
| Captured request linkage | When Task Hook evaluates an already captured source, require the retained canonical skill-generated request value and validate every populated record against it under ora_input_validation.md. Do not generate or fill missing values, overwrite conflicts, or regenerate the canonical value during captured-source evaluation. Missing generation context or any missing, schema-invalid, or different record value blocks preview and submission. Return the source for corrected preparation, a fresh validation session, and fresh approval. |
| Request generation and repeated preparation | The owning skill generates RemainingShelfLifeRuleId once using the existing registered Data Loader schema, retains the value in the request context, and reuses it across all source files, sheets, components, and populated records within that request. Do not regenerate during repeated checks or preparation passes, use separate parent-level values, substitute MRSLRuleId or MRSLRuleDetailId, infer the value from a rule name, or invent a fixed constant or UUID format. This is a skill-generated linkage value, not user input or a Fusion-generated business identity. |
| An existing rule header is updated | Do not default Description, DemandAnchorDateType, CategorySetId, or any other omitted business header attribute. An omitted anchor-date update never becomes Arrival. Required technical request defaults retain their stated applicability; preservation of existing business attributes is owned by ora_design_enforcement.md. |

## Sources

- Developer instruction: RemainingShelfLifeRuleId is mandatory and automatically generated by the owning skill exactly once per complete request using the existing Data Loader schema required format, constant across all sheets and populated parent/child records for every supported operation, and propagated before capture. Do not request the value from the user. It remains distinct from Fusion-generated MRSLRuleId and MRSLRuleDetailId. Missing generation context or missing/invalid/different values blocks preview and submission; captured-source corrections require fresh preparation, validation and approval.
- Developer instruction: header updates must preserve all attributes the user did not request to change, including demand anchor date type and catalog in a description-only update.
- Developer instruction: RestAction, Content-Type, and REST-Framework-Version are mandatory. Always prepare the Data Loader file with RestAction POST, Content-Type application/json, and REST-Framework-Version 9.
- Developer instruction: always use POST RestAction and mutation HTTP method for Configure Remaining Shelf Life Rule, including update and delete flows. This task-specific policy overrides generic operation-based method defaults; read-only lookup contracts remain GET.
- Existing Data Loader session contract: apply preparation changes before source capture; changed or incomplete captured data requires corrected source preparation and a fresh validation session.
- Developer instruction: DemandAnchorDateType defaults to Arrival, and the defaulting logic must be used only in the create flow of a remaining shelf life rule.
- Developer instruction: DemandAnchorDateType must resolve using ORA_MSC_SP_UI_MRSL_ANCH_DT. Arrival is a display meaning; its numeric code is not hardcoded here.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Organization read endpoint | Use /fscmRestApi/resources/11.13.18.05/inventoryOrganizationsOpenLOV with GET; supply the exact organization identity filter through a separate q query value |
| Transaction catalog read endpoint | Use /fscmRestApi/resources/11.13.18.05/electronicSignatureTransactionTypes with GET and separate limit=500 and onlyData=true query values; do not add fields=TransactionTypeCode,SignatureMode,EnabledForAllOrgsFlag |
| Preferences parent read endpoint | Use /fscmRestApi/resources/11.13.18.05/electronicSignaturePreferences with GET and a separate q=OrganizationId={OrganizationId} query value after replacing the organization placeholder |
| Preferences child read endpoint | Use /fscmRestApi/resources/11.13.18.05/electronicSignaturePreferences/{SignatureOrganizationId}/child/electronicSignatureTransactionTypes with GET after resolving the parent key; supply child selection and collection parameters separately |
| Signature mode lookup read endpoint | Use /fscmRestApi/resources/11.13.18.05/genericLookupsLOV with GET and separate finder=LookupTypeFinder and q=LookupType='ORA_EDR_SIGNATURE_MODE' query values |
| All organizations or OrganizationId -1 | Bypass ordinary-organization LOV validation; retain the protected scope and apply design restrictions. Existing parent/child reference resolution is still required for child updates |
| ID validation fails but name/code is also supplied | Do not fall back to name/code after failure of a supplied ID |
| Transaction catalog pagination | Fetch the standalone catalog once with the developer-requested limit=500 and process all response.body.items. This decision does not change parent or nested-child collection retrieval rules |
| SignatureEnabledFlag-only update | Do not invoke signature-type editability or type-label lookups; parent/child reference resolution must still read EnabledForAllOrgsFlag for the scope eligibility policy |
| Explicit ORA_DEFERRED or ORA_INLINE for a type update | Always read child editability first; a supported direct code bypasses only the generic label lookup |
| Nonapplicable lookup step | Return not_required and perform no request; continue to the next declared node without inventing extra calls |

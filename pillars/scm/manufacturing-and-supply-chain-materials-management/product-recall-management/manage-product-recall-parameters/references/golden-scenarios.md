# Product recall parameter golden scenarios

Reviewed on 2026-10-23 for task ORA_MANAGE_PRODUCT_RECALL_PARAMETERS and skill version 0.1.1. These synthetic cases provide review evidence for assisted task guidance. They do not execute Fusion, certify server validation, or duplicate the validator in pillar code.

## Baseline and method

Use conceptual business fields, not an invented payload. Baseline: selected project and Run Book host agree; the final immutable upload artifact and verified Data Loader preflight contain the approved requested values; required access, exact references, current-state reconciliation and target method/field metadata are evidenced; user intent and all applicable design gates are satisfied. Selected singleton updates use server-returned keys. Each case changes the named baseline fact only. Unknown or unavailable metadata remains a blocker. Supplied current-state facts are simulated evidence, not a fabricated lookup endpoint.

Review [input](../ora-resource/ora_input_validation.md), [lookups](../ora-resource/ora_reference_lookups.md), [dependency](../ora-resource/ora_dependency_readiness.md), [default](../ora-resource/ora_defaulting_rules.md), [design](../ora-resource/ora_design_enforcement.md), and [error](../ora-resource/ora_error_handling.md) rules. Follow their [compiled registry](../ora-resource/ora_rule_registry.json) outcomes and require successful prerequisites. An offline trace check confirms all listed graph paths and handler/terminal prerequisites. The reviewer evaluates the conditions against source rules; the trace check does not implement those domain conditions.

The node prefix RECALL.PARAMETERS is omitted in the table. DONE-READY-FOR-PREVIEW means preflight passed, with approval still pending in core; it is not import success. All synthetic identities are described by match counts, without names, IDs, credentials or environment addresses. No customer values, captured source snapshots, previews, fingerprints or approval objects are stored here.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Configured Fusion REST host differs from the active project Run Book host | Stop before the first describe or GET. Do not treat a match returned by the other pod as a project identity or retry through another host. |
| REST version differs from the public-documentation example | Use the version returned by Data Loader describe metadata for the target environment; retain the public path only as a reference. |
| A path requires ParameterValueId | Obtain it from the preceding collection read. Oracle documents that clients must not generate item path keys. |
| A singleton record already exists | Ask the user for the desired replacement values, use find_existing_recall_global_params or find_existing_recall_item_validation_organization, and pass that returned ParameterValueId to the Data Loader update record. Do not POST a second singleton record. |
| A record needs a lookup value such as an organization, owner, subinventory, locator, or cost center | Resolve it through the Data Loader describe-backed reference mechanism before preview; do not guess IDs or display-name mappings. The traceability default marker -1 is excluded from actual-organization lookup; its existing-row identity is reconciled by find_existing_recall_parameter_rows. |
| A dependent field is supplied | Resolve in this order: generic lookup code when applicable; inventory organization; subinventory; locator; business unit; ledger; then public worker for an owner or coordinator. Each resolver requires one exact current result. |

## Traceability Source Boundary

The default marker -1 and exactly-one-default rule are developer-supplied task semantics corroborated by the 2026-10-23 screenshots and database extract described in ora_input_validation.md. Do not treat the extract as current target state or infer runtime identities from it. Use the declared collection read for live default and exception reconciliation. Positive-ID exceptions override the default only for their specific organization; exceptions do not count as additional defaults.

Documentation checked on 2026-10-23: the [26D SCM documentation hub](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/26d/api.html) links its SCM REST guide to 26C. The linked [26C Get all groupings](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/26c/fasrp/op-recallproducttraceabilitygroupings-get.html) documents the collection, fields and pagination, and [26C Get all organizations](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/26c/fasrp/op-inventoryorganizations-get.html) documents queryable OrganizationId. A 26D recall-topic page was not available for verification; these REST references do not document the -1 sentinel or default uniqueness, which remain explicitly developer-sourced.

## Authoritative Read-Only Sources

- Oracle SCM REST, [Get all organizations](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/26c/fasrp/op-inventoryorganizations-get.html), documents the inventoryOrganizations GET collection, queryable OrganizationName/OrganizationCode, and returned OrganizationId, OrganizationCode, OrganizationName, Status, and InventoryFlag. Confirm the target pod's describe contract before a call.
- Oracle HCM REST, [Get all workers](https://docs.oracle.com/en/cloud/saas/human-resources/farws/op-publicworkers-get.html), documents the publicWorkers GET collection, queryable DisplayName, findByWorkerAttr DisplayName/PersonNumber variables, limit, offset, and onlyData. [Access Worker Directories](https://docs.oracle.com/en/cloud/saas/human-resources/farws/Accessing_Worker_Directories.html) describes publicWorkers as a read-only directory of active workers. Finder results remain candidates until exact-match and uniqueness checks pass.
- Oracle SCM [Set Up Recall Parameters](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/26b/faims/set-up-recall-parameters.html) and [Derive Containment Task Owners](https://docs.oracle.com/en/cloud/saas/readiness/scm/26a/inv26a/26A-inventory-wn-f43671.htm) document organization-only fallback mappings, organization plus one department or subinventory dimension, and multiple task owners. The target pod's describe contract remains the final payload-shape check.

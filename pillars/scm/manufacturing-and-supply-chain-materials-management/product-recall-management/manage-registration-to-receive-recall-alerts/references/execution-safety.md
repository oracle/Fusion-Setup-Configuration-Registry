# Registration execution safety

These are prerequisites for the assisted registration workflow, including sample generation. They do not implement a transport, authentication service or loader. The selected implementation workflow supplies the project, environment, profile and Run Book/task identity. Missing evidence stops the affected operation; no browser or direct REST substitution is authorized.

## Private staging and disclosure

Before opening a populated source or invoking Data Loader preparation, require an explicitly approved, current-user-owned private staging directory outside the repository and every project workspace. Its canonical path and all ancestors must be verified without traversing symlinks. Require exclusive user access (directory mode 0700 and file mode 0600 on Unix, equivalent private ACLs on supported platforms), no links, no shared writers and no existing destination or temporary-file collision. The caller must establish these conditions before the core helper writes; checking permissions afterwards is insufficient. If the platform or selected workflow cannot establish them, stop and report the missing private-storage capability.

Keep the credential source, prepared archive, Data Loader preflight and internal Task Hook preview/envelope in this private location. Data Loader's normal preflight saves a generated archive beside its source; therefore the source directory must already meet the private staging gate. Do not use the project fallback for a credential-bearing source. For an explicit ZIP, retain its exact validated bytes in the same private location. Use a new staging directory for a corrected request and never overwrite a pending archive. These files are temporary import approval material, not project exports or reusable evidence. Retention and removal require the owning workflow's declared policy and authorization; this skill does not silently delete source files.

Inspect names, mappings and error/preview contracts before processing credentials. Never use a client secret, refresh token or access token in a filename, command argument, environment variable, rule issue, change description or project artifact. Do not print source rows or raw helper responses. Task Hook's `finalData` is restricted to the exact archive SHA-256 and a non-sensitive operation summary: task/business-object name, create/update intent, environment label, row count and field-presence facts. Its API accepts arbitrary JSON, so the assisted caller must enforce this restriction rather than assume the provider sanitizes arbitrary data. `ruleResults` contain field names and pass/fail facts, never values or server payloads.

Before a credential-bearing live request, establish that its actual provider suppresses or redacts credential values and encoded archive content in success output, server errors and logs. If that cannot be established for the selected operation, stop with a disclosure-contract blocker. Do not claim that a generic OAuth-token redactor also covers registration payload secrets. A blocked credential-bearing operation does not authorize importing blank or invented credentials.

Only sanitized task outcomes, digests and error classifications belong in project records. Never copy private sources, prepared bytes or internal previews to project evidence. Blank, unpopulated sample workbooks may use the declared project artifact directory.

## Containment and source inspection

Bind source, archive and envelope paths to the approved private staging root, and blank-sample outputs to the selected project's declared artifact directory. Canonical containment must hold after absolute paths and traversal are resolved. Reject symlinks, hard links, unexpected paths, existing output/temp collisions and overwrites before invoking helpers, and recheck containment and ownership before approval/submission. A mismatch stops the request. The trusted, exclusively owned directory prevents another writer replacing a helper's temporary path during preparation.

Use Data Loader's supported source validation and archive inspection. Reject absolute, traversing, duplicate or symlink archive members, nested/opaque unexpected content and unsupported formats before loading. Do not extract an archive to bypass validation. Inspect XLSX as data through the core reader; reject macro-capable documents, VBA, embedded executable objects and external-content execution. Never launch Office or enable macros. If content cannot be safely inspected, stop that source and request a supported clean source.

Evaluate input and design rules against the prepared archive covered by the preflight digest. Before approval, changes to the intended load require a new preflight and Task Hook cycle. After approval, the core `--approved-preflight-envelope` path verifies the retained archive and context; it does not reopen the original source. Missing or changed bytes invalidate approval.

## Environment, transport and operation ownership

Use the same explicit selected properties/profile across Data Loader, Task Hook, profile-options and feature lookup calls. Never repair authentication by switching environments, changing scopes or replacing trust. Authentication and cache management belong to the governed core OAuth service; no token files or token contents belong in this package or project. The managed cache is outside the repository, private and keyed to its OAuth/service context. Its identity and expiry checks must pass before reuse.

Route profile-option reads through `core.fusion-api.apps-common.profile-options`, and feature GETs through `core.fusion-api.fsm-rest-client` with the shared REST client. Credentials may go only to the selected authorized HTTPS origin with certificate verification. The core client validates initial URLs, redirects and pagination destinations, including scheme, hostname and port; do not bypass those checks or forward credentials to a returned arbitrary link. Profile corrections and feature opt-in changes run through their named owning workflows and approval gates, outside this task-rule graph.

Before import preparation, resolve the registered business object's operation family from the selected workflow's authorized metadata/contract. The business-object name alone does not determine it. Registration writes use Data Loader only. If metadata identifies an ApplCore POST/PATCH/PUT target, the workflow must first select the applicable `core.fusion-api.apps-common` nested skill and complete its eligibility, identity, privilege, payload and approval gates. If no applicable nested skill or verifiable target exists, stop with a routing-contract blocker; Data Loader ownership alone is insufficient. This package does not assert that registrationForRecallAlerts has an ApplCore contract. Do not infer an exemption from unrelated profile-options guidance.

The v3 rule graph contains input checks, read-only lookups, design rules and terminals; none selects a registration write. `validateCredentials` has no verified operation or executable workflow in this package and remains blocked. Do not infer a method or side effect from its name.

Invoke only the public CLIs documented by the selected core skill, from trusted repository paths and the intended skill working directory. Do not add the source/staging directory to Python's import path, import private core symbols, load code from a workbook/archive, or execute user-provided helper paths. Generic parsing, transport, token storage and polling stay in core.

## Recovery

Follow Data Loader's approval workflow once, including its explicit same-request auto-approval rules when applicable. No additional pillar approval is required for the same Data Loader action. Submit only its verified immutable artifact and unchanged Task Hook envelope. Do not retry uploads, initiation or actions with uncertain side effects automatically. Preserve sanitized external IDs and the failure class; reconcile the state through the owning core workflow before any explicitly authorized retry. Use the core timeout policy and report last status, elapsed time and next-check path. No task-rule waiver can waive these security or route-selection gates.

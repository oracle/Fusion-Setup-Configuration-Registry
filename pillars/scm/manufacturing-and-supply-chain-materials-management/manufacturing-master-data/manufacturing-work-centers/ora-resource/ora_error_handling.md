# Error Handling

The **Server-managed create reconciliation** contract in ora_design_enforcement.md is the single owner of create eligibility, immutable expectations, post-load completion, and GET-only recovery.

For a mixed Work Center request, including an FSM delta, inspect every independent parent during local validation. Report each invalid parent and keep it out of the reviewed upload source while preparing compatible valid stages. Duplicate or missing parent identities, failed shared metadata or authentication, and unsafe source boundaries still block the entire batch. A submitted batch with loader errors or an uncertain result requires core Data Loader diagnostics and exact target readback before a corrected source can be prepared; local validation continuation does not imply that Fusion will partially commit or continue processing after a server-side error.

## Error Situations

| Situation | What Should Happen |
|---|---|
| Fusion reports a missing ResourceId/Name although the approved source contains them | Identify this as a business diagnostic returned by Fusion during loading. Compare each immutable DAT header/value mapping with exact target master-resource evidence and bound expectations under WC.CALENDAR.RESOURCE_CREATE_BATCH. Distinguish a missing or invalid source identity from an unresolved loader or product-side identity rejection. Preserve the actual message and failed request; obtain row keys, the adapter-generated per-row request and response, and downstream loader trace before assigning the failure to a particular server component or changing valid IDs. A populated DAT proves source presence, not that the downstream request retained the value. Do not default, replace or omit identities, invent generated keys, or impose a one-row workaround as a repair. |
| A newly prepared resource-create batch has missing, duplicate or mismatched identities, misaligned fields, or incomplete expectation coverage | Stop before preview as input_validation under the Existing-parent resource-create artifact contract. Report the affected source rows and fields; rebuild the complete compatible batch with exact per-row identities and values, then rerun core validation. Multiple valid resource rows are supported. Preserve any historical accepted archive unchanged; no synthetic WorkCenterResourceUniqID or SourceRef identity is an approved repair. |
| A resource-create load fails with ResourceId/Name rejection and exact bound readback confirms requested associations are absent | Apply WC.CALENDAR.RESOURCE_IDENTITY_REJECTION regardless of batch size. Retain the failed request and trace next action, and block automatic retry and corrective re-preparation of those unchanged associations until reviewed loader or server evidence identifies a specific correction. Preserve verified matching associations and omit them from future creates; unrelated remaining work may proceed after ordinary inspection and stage gates pass. |
| A resource-create load reports both loaded and failed rows | Apply WC.CALENDAR.FAILED_RESOURCE_INSPECTION and inspect_failed_work_center_resources. Display total, loaded and failed counts and per-resource readback outcomes; preserve successful associations. No correction may proceed from aggregate counts alone or while any readback is conflicting or incomplete. |
| A status response contains generic wrappers, placeholders or nested business details | Display resolved business diagnostics and actionable next steps. Extract distinct nested detail messages, prefer resolved MessageText then Message for non-FSM logs, and retain raw logs privately. Suppress unresolved placeholders and generic HCM diagnostic-test boilerplate in the user-facing summary. If no detail is available, say so and request the existing job trace. |
| Core consumes submission envelopes after accepting the load | Before submission, retain an exact private preflight copy bound to the approved preflight digest; verify it before failed-resource inspection or any correction. Preserve archive, preview, expectations and original receipt. Stop on missing, changed or unsafe evidence; never reconstruct approval envelopes or retroactively fabricate preflight evidence. |
| A required input, date, Boolean, unit value, or normalized operation scope is invalid | Exclude the affected parent from a mixed batch, continue local validation of independent parents, and route its evidence to WC.CLASSIFY_FAILURE. If no eligible parent remains, stop before source preparation. |
| A candidate REST Data Loader WorkCenterResource source serializes Available24HoursFlag as True, False, or any literal other than exact lowercase true or false | Stop at input validation. Correct the REST source serialization under ora_input_validation.md, rebuild the immutable artifact, and rerun core.data-loader validation before a new approval; do not resubmit the failed ZIP. |
| A declared final resource-shift source has a header-only, missing, duplicate, mismatched, or wrong-operation resourceShifts child record | Stop at input validation, apply the create/update/delete contract for the requested operation, rebuild the exact source, and restart core.data-loader preflight; do not request approval or substitute POST for PATCH/DELETE. |
| A Data Loader ZIP member has no top-level workCenters METADATA section | Stop at input validation and add the template-recognized top-level metadata section without inventing a work-center data row. Revalidate the changed archive before requesting approval. |
| An intermediate calendar-association or availability-conversion source is represented as the completed resource-shift operation | Stop before approval, retain the requested operation, resource, shift, units when applicable, and route as pending, then re-read the completed state before preparing the next source. |
| A declared lookup route, field, finder, or returned identity conflicts with its documented contract | Stop and classify the issue before changing source data; do not invent a substitute path or key. |
| A prerequisite resource, production calendar, or calendar shift is not yet persisted | Stop before preview. Use a prior approved state-establishing load, re-read with the declared GET lookup, then prepare a separate assignment load. An absent target resourceShifts row is expected for the documented POST create path. |
| A final resourceShifts source includes a prerequisite WorkCenterResource PATCH | Stop as input_validation. Move the prerequisite update to a separately validated stage with verified numeric WorkCenterResourceUniqID; omitting that row alone never satisfies an unresolved availability prerequisite. Re-read after success before preparing the final child source. |
| A final resourceShifts create or update targets a resource whose fresh persisted Available24HoursFlag is true | Stop before final approval at WC.DESIGN.TO_SHIFT. Retain the requested assignment, resolve the verified resource-update identity, and use a separately approved availability-conversion stage followed by a successful re-read. |
| Persisted availability is null, missing, or unknown before a final resourceShifts create or update | Stop as catalog_or_metadata_mismatch; obtain authoritative resource-state evidence before approval. Never infer false from a source row or a requested conversion. |
| An override-resource update or conversion to 24-hour availability has a nonempty or incomplete resource-wide assignment scan | Stop before approval at WC.DESIGN.TO_24_HOURS_OVERRIDE. Report the complete remaining count when known, or the incomplete evidence and originating failure. Use separately approved cleanup when requested, then repeat the complete scan; do not substitute a single-shift finder, treat a partial result as empty, or infer approval to delete assignments. |
| A new WorkCenterResource association is requested using a resource name or code | Use resolve_active_production_resource before source preparation. A failed or ambiguous lookup blocks preview; preserve the resolver's failure class. Never fall back to an existing-association query, another organization, or another identity field. A supplied ResourceCode uses its declared exact master lookup directly. |
| A new WorkCenterResource association has only untyped ResourceIdentifier without a supported identity, lacks parent organization context, or has conflicting supplied identity fields | Stop as input_validation. Request only the missing or conflicting input. ResourceCode plus OrganizationId or OrganizationCode is supported and derives ResourceName and ResourceId; do not ask for either after a successful exact active match. Untyped ResourceIdentifier-only create-time resolution remains unsupported. |
| A successful Data Loader override-resource create returns an explicitly null or blank WcProdCalendarId | Apply WC.CALENDAR.RESOURCE_CREATE: record valid nullable state, preserve the accepted request and source, and complete the ordinary bound parent/resource/shift readback. Do not classify the blank field alone as an error, require a calendar-specific lookup, or hold later override creates. Other missing or conflicting requested values still require correction. Never replay the accepted POST or infer a PATCH. |
| An override-resource readback returns a nonblank WcProdCalendarId different from the selected ProductionCalendarId | Apply WC.CALENDAR.RESOURCE_CREATE: preserve expected and observed IDs and report the affected readback as incomplete. Keep the accepted successful load immutable and resume declared no-write verification after review; do not accept the conflict through an alternate action, replay the POST, or infer a PATCH. |
| A name-based or code-based new-resource source omits or changes the resolved ResourceId, repeats a resource for the same parent, or substitutes an assignment surrogate | Stop as input_validation. Rebuild using New resource source mapping in ora_input_validation.md and rerun core.data-loader validation; do not change BO mandatory flags or invent an ID. |
| An exact typed resource name/code or override-calendar shift name has zero or many matches | For a read-only verification, disclose the factual absent or ambiguous state. For a mutation, stop before preview and ask for one exact identifier; never try another identifier type automatically. |
| An untyped ResourceIdentifier has zero matches from both exact queries, many matches from either query, a returned-field mismatch, or name/code queries that resolve different resources | Disclose resource_absent, resource_ambiguous, or resource_identifier_conflict. Stop before preview; the declared dual-query resolver is not a license to choose between different records. |
| A WorkCenterSubInvType value is supplied but the exact live workCenters Data Loader template or component attribute is absent or read-only | Evaluate WC.RECON.TYPE in ora_design_enforcement.md. Only that eligible create may omit the write field while retaining the exact immutable expectation. All other cases stop as catalog_or_metadata_mismatch. |
| A work-center create source has WorkAreaCode but omits WorkAreaId or WorkAreaName, or either derived field differs from the one active Work Areas row resolved for OrganizationCode and WorkAreaCode | Stop as input_validation before preview or approval. Re-run verify_active_work_area, rebuild the workCenters source with WorkAreaCode, WorkAreaId, and WorkAreaName from that same result, and revalidate the immutable artifact. Do not replace the Data Loader route with a direct REST write. |
| The registered Data Loader WorkCenterResource update field is a numeric local surrogate but Fusion does not expose a supported record-value resolver for it | Stop before DAT preparation as catalog_or_metadata_mismatch. A direct WorkCenterResource item GET may establish only a REST item identity; it does not convert that identity into a loader value. Correct the BO registration, refresh the object metadata/template, and re-run source validation. |
| A direct WorkCenterResource item GET is attempted with a generated, constructed, or otherwise undocumented item key | Stop and use the exact parent-scoped collection resolver. Follow only a returned self/canonical URL; if no link is returned, classify as catalog_or_metadata_mismatch. Do not use the result as a Data Loader surrogate without a registered mapping. |
| A declared GET returns Not Found after the supplied identifiers were validated | Preserve sanitized evidence, stop, and reconcile the persisted work-center/resource/calendar state; do not retry a write. |
| The immutable artifact changes or is not approved | Stop before upload or initiation and restart the core.data-loader validation and approval path. |
| A loader operation is uncertain, timed out, or failed | Preserve the request ID and sanitized status evidence; use the core Data Loader status and diagnostic workflow without resubmitting automatically. |
| Fusion rejects a productionCalendars row as application owned | Resolve its target plant ManufacturingCalendarId and selected calendar identity. For an FSM plant row, rebuild a fresh source with that row excluded and its exported dates recorded only as observations. For an explicit request to create, update, end-date or delete the plant association, reject the operation under WC.CALENDAR.PLANT_IMMUTABLE. Do not replay the failed archive or require the plant's exported interval as a replacement-source completion condition. |
| An FSM plant-calendar interval differs from target state | Exclude the identified plant row under WC.CALENDAR.PLANT_HISTORY and continue validating other rows. Record why it was excluded. Do not synthesize an end-date write, block source preparation solely for this difference, or report the excluded interval as applied. |
| Fusion rejects an existing override AssociationStartDate change with WIS-4440558 | Compare the exact accepted row with the fresh persisted ProductionCalendarId, MfgCalendarId and start date. If the start date was unchanged, rebuild a PATCH with only other explicit supported changes or omit a no-op row. If it truly changed, retain the requested difference as unresolved; Fusion allows a start-date edit only under its future-start rule. Do not silently substitute today's date, change an existing association into a POST, or retry the same ZIP. |
| Fusion rejects calendar business dates during the approved REST load, including WIS-4440541 | Preserve the exact requested dates, request ID, server error code/message and row-level partial results. Classify a failed loader request as process_failed or a direct Fusion error as fusion_api_error. Keep the task incomplete. A correction requires user-reviewed dates, a new immutable source, fresh core validation and separate approval; never silently normalize business eligibility or replay the failed archive. |

## Error Classifications

| Result Category | When Used | Next Action |
|---|---|---|
| input_validation | Required identifiers, including a create-time OrganizationCode and WorkAreaCode pair or its required resolved WorkAreaId and WorkAreaName, date format, Boolean source serialization, unit value, operation scope, staged-assignment disclosure, or final child-record coverage is absent or invalid. | Correct the request or rebuild the exact source before source preparation. |
| catalog_or_metadata_mismatch | A route, finder, field, action, identity contract, local Data Loader surrogate mapping, or result outcome is undocumented, stale, or conflicts with retained source evidence. | Stop, correct the task contract from an authoritative source, and revalidate. |
| auth_expired_or_invalid | The shared client receives 401 or 403 attributable to expired or invalid authentication. | Let the core client perform its one permitted refresh; if it still fails, stop with sanitized evidence. |
| authorization_or_privilege | Authentication is valid but Fusion denies the required read or Data Loader privilege. | Stop and request the required least-privilege access; do not retry locally. |
| transport_or_environment | TLS, network, configured host, or other environment transport failure prevents a declared read. | Stop, preserve sanitized stage evidence, and correct the environment or transport condition; do not replay a write. |
| fusion_api_error | A declared GET with validated identifiers returns a Fusion API error, including Not Found. | Preserve sanitized response evidence, reconcile current persisted state, and correct input or contract before a new validation cycle. |
| process_timeout | A Data Loader request does not reach a terminal state in the permitted window. | Report request ID, last status, elapsed wait, and next status-check path; do not resubmit automatically. |
| process_failed | A Data Loader request reaches a failed terminal state or partial outcome. | Retrieve sanitized status and available error details through core.data-loader, preserve partial-success evidence, and correct source before a new approval. |
| artifact_persistence | Immutable artifact, preview, or sanitized diagnostic evidence cannot be persisted or verified. | Stop before upload, repair artifact persistence, and regenerate validation evidence. |
| approval_blocker | Exact immutable artifact lacks approval, differs from the approved digest, or destructive scope is not approved. | Stop and obtain approval for the exact validated artifact. |

## Classification Handoff

| Input to WC.CLASSIFY_FAILURE | Required Output | Handling Rule |
|---|---|---|
| Any failure, blocked, or unsupported transition | Exactly one Result Category from Error Classifications, redacted evidence, affected Rule ID, and one safe next action | Classify from the originating node and observed response. |
| No declared category fits the observed failure | catalog_or_metadata_mismatch with redacted evidence and affected Rule ID | Use the deterministic fallback outcome; do not emit an untyped failure. |
| Auth refresh remains unsuccessful | auth_expired_or_invalid or authorization_or_privilege, based on the shared-client result | The task must not perform its own retry. |
| Loader status is missing, timed out, or failed | process_timeout, process_failed, or artifact_persistence, based on available status and diagnostic evidence | Preserve request ID and sanitized evidence before returning the terminal result. |

## Disclosure Rules

| Gate | What Must Be Shown |
|---|---|
| Failure | Canonical failure class, stage, sanitized message, affected rule or Data Loader status, and one safe next action. |
| Calendar-resource failure | Resolved or unresolved route, sanitized resource/calendar identity evidence, generic name/code match counts and basis when used, and the blocking result. |
| Read-only calendar-resource verification | Resolved work center and calendar context; exact resource, shift, and assignment match counts; and the factual present or absent state, with no source preparation or upload. |
| Staged resource-shift preview | Whether the source is intermediate or final; requested create/update/delete operation; completed state changes; the retained pending resource, shift, units for create/update, and route when intermediate; and the next required re-read or source-preparation step. |
| Existing-parent resource-create preview | Apply WC.CALENDAR.RESOURCE_CREATE_BATCH. Show every included association in the immutable load with its WorkCenterId and ResourceId, requested values, and expected outcome. Identify excluded and deferred associations with reasons, completed verified outcomes, and the next required readback for every accepted member. Preserve compatible batches; do not impose serial preparation or claim that changing batch size resolves an unexplained Fusion rejection. |
| Override-resource 24-hour conversion | AssignmentScanComplete, RemainingAssignmentCount when known, whether a fresh post-cleanup scan was completed, and the safe next action. |
| Data Loader timeout or failure | Request ID, last status, elapsed wait when known, actionable diagnostics, and the next safe status-check path. |
| Approval preview | Immutable artifact name and SHA-256, work-center scope, selected route, and required approval. |
| Work-center create preview | Business-supplied OrganizationCode and WorkAreaCode, exact-match result, and confirmation that the source carries the corresponding WorkAreaId and WorkAreaName. |

## Refusal Rules

| Situation | What Must Not Happen |
|---|---|
| WorkCenterResource identity is needed | Use only a Fusion-returned self/canonical URL for the declared direct REST item GET. If no such URL is returned, stop rather than constructing or substituting WorkCenterResourceUniqID or WorkCenterResourceShiftUniqID. The REST item URL is not a numeric Data Loader surrogate without a registered mapping. |
| Required persisted prerequisite resource, production calendar, or calendar shift is absent | Do not predict a future prerequisite or submit a same-cycle assignment source as if the prerequisite were verified. An absent target resourceShifts row permits only the documented POST create with exactly one matching source row; it does not permit a PATCH with a blank surrogate. |
| ResourceId or ShiftId is absent but a supported name or resource code is supplied | For a new WorkCenterResource association, use resolve_active_production_resource; for an existing association or resourceShifts operation, use resolve_work_center_resource_by_name_or_code. Do not silently change an explicit ResourceName into ResourceCode, or a calendar shift Name into a different field. For untyped ResourceIdentifier in a supported existing-association branch, run only the declared pair of exact queries and accept only a one-sided or same-record result. |
| A final override-calendar resource-shift create, update, or delete is requested | Require the exact operation-specific child record before approval; a header-only section, an unmatched row, or an intermediate stage is not completion. Do not require units for deletion or substitute POST for update/delete. |
| A final resourceShifts create or update lacks fresh persisted Available24HoursFlag=false evidence | Do not approve the final source. A requested false value or an unverified conversion result is insufficient. This gate does not prevent a delete cleanup or read-only verification. |
| An override-resource update or conversion sets Available24HoursFlag=true | Do not approve without a fresh complete resource-wide scan proving zero assignments. A provided ShiftId must not narrow this evidence; missing, stale, malformed, or partial scan evidence is not an empty result. |
| Any lookup contract is undocumented or conflicting | Do not infer an endpoint, query, action body, field, or response mapping. |
| Authentication, authorization, transport, or API failure occurs | Do not perform a task-local retry beyond the core client's permitted authentication refresh. |
| Data Loader result is uncertain or timed out | Do not automatically retry, re-upload, or re-submit the artifact. |
| Direct REST write is proposed | Do not issue a direct REST write; use the centralized core.data-loader workflow. |
| Work-center create payload has only WorkAreaCode, or has an ID or name that did not come from verify_active_work_area | Do not preview, approve, upload, or initiate it. Resolve the exact active Work Areas row and rebuild the Data Loader source so the workCenters REST payload includes WorkAreaCode, WorkAreaId, and WorkAreaName. |
| A candidate REST Data Loader WorkCenterResource source contains an Available24HoursFlag literal other than exact lowercase true or false | Do not preview, approve, upload, or initiate it. Normalize the supplied logical value under the REST input-validation contract, regenerate the source, and revalidate the immutable artifact. This REST serialization refusal does not apply to native FSM CSV flags governed by Native FSM CSV contract in ora_input_validation.md. |
| Artifact differs from approved immutable source | Do not upload or initiate the load; restart validation and approval. |

# Dependency Readiness

The **Server-managed create reconciliation** contract in ora_design_enforcement.md is the single owner of create eligibility, immutable expectations, post-load completion, and GET-only recovery.

## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---|---|---|
| 1 | Work-center branch | For create, resolve the active Work Areas row from OrganizationCode and business-supplied WorkAreaCode, retain its WorkAreaId and WorkAreaName with the code in the workCenters source, and resolve any new named or coded resources through resolve_active_production_resource. Then resolve any existing-work-center and locator evidence applicable to work_center and verify any supplied WorkCenterSubInvType against the exact live Data Loader template and component attributes. |
| 2 | Calendar-association branch | Resolve the existing association state and schedule-override flag only for calendar_association. |
| 3 | Calendar-resource branch | Resolve route and parent organization; for a new WorkCenterResource association, accept a supplied numeric ResourceId or resolve a supplied ResourceName or ResourceCode through resolve_active_production_resource. Confirm the new-resource source mapping before approval. For existing associations and resourceShifts operations, resolve a supplied name/code/generic identifier when needed, then read the persisted resource and route-specific shift state. |
| 4 | Staged resource-shift completion | When the original outcome includes a resource-shift assignment, treat calendar association and availability conversion sources as intermediate state-establishing stages; re-read their successful state before preparing the final assignment source. |
| 5 | Final resource-shift source | For a declared final assignment, let input validation confirm that the exact preflight source contains the route-specific matching child record before approval. |
| 6 | Immutable Data Loader artifact | Confirm the core.data-loader validation result and exact artifact identity for artifact_review; core.data-loader separately enforces this prerequisite before every import. |

## Dependency Classification

| Result Category | When Used | Can Run Lookup/Create? |
|---|---|---|
| Satisfied | The scope-specific dependency and immutable artifact evidence is confirmed. | Yes |
| Blocked | A required identifier, route, persisted resource or shift row, numeric Data Loader surrogate, paired source, or artifact cannot be confirmed. | No |

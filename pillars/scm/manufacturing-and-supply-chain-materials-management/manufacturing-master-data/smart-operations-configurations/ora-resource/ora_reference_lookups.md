## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Selected value, target, artifact or required current result is missing | Stop before the lookup or Fusion mutation. Historical source completeness does not establish current evidence or permission for a new call |
| Live metadata and JSON representations differ | Retain original values and JSON types. Only the exact documented setup-flag forms in verify_manufacturing_plant are interpreted; every other schema/identity deviation stops. Do not repair Fusion data to satisfy a client type assumption |
| Evidence is reused | Reuse only same-target, same-identity, full-field results for the current request; retain provenance and timestamp. Historical cross-target results do not authorize a new call |
| Checking current Business Object associations | Use the documented BOSS relationship resource and exact task/object short codes under verify_smart_operations_business_objects; complete page coverage is mandatory and task CSV flags remain separate. Current contract recovery is not a current association result |

## Lookup Contract Details

| Situation | What Happens |
|---|---|
| Task CSV support | Use the declared setupTasks lookup and flag precedence from setup_task_csv_support.py:csv_export_import_flag. Only Y is supported. Do not use resolve_task's local-catalog fallback or first-match selection. Require one exact task identity and complete coverage. |
| Standard REST paging | Use core.fusion-api.rest-api-client with REST-Framework-Version: 9. Require items, Boolean hasMore, matching offset and a positive returned limit. Advance by that limit until hasMore=false. Stop on malformed, repeated, non-progressing or partial pages and execution-window expiry. No task-local retries, first-row selection, request bodies or writes. |
| BOSS collection shape | Use taskBusinessObjects with $limit=1000. Advance $offset by the actual row count; finish only on a valid page with fewer than 1000 rows. Accept a JSON array or one unambiguous collection array under items, results, rows, data or value. Reject malformed/ambiguous containers, non-object rows, repeated pages, non-progressing offsets, excess rows, incomplete retrieval and execution-window expiry. Do not require invented ADF page metadata or use a reporting wrapper's empty/dropped-row fallback. |
| BOSS request route | Delegate /api/boss to the shared BOSS client with boss_scope, its scope-separated managed token cache, configured HTTPS restBaseUrl, query encoding and REST-Framework-Version: 9. Do not use the default standard REST token or copy the helper implementation. |
| BOSS field selection | Explicitly request $fields=task.taskShortName,task.taskName,businessObject.businessObjectShortName,businessObject.businessObjectName. Select exact task/object short codes over complete coverage, retain returned names and the task self link, and reject missing nested identities. Task names, $id and filenames are not identity substitutes. |
| Required definitions | Retain the three existing approved definition codes in verify_smart_operations_business_objects. Record additional associations without inventing an exactly-three-only rule. CSV-support flags do not prove Business Object associations. No export or whole-list display is needed for this lookup. |
| Setup values and approval | Confirm selected-target metadata before a future authorized run. Historical procedure examples supply no organization, UOM, percentage, reason, language, row-count or approval defaults. Task validation remains read-only; preview, approval and submission remain with the Data Loader. |

# Field Service Technicians Input Validation

Current capability gate: the task SKILL.md permits metadata/sample and explicitly requested status only. Complete business/reference reads and create/update/delete preparation are unsupported. Return blocked (invalid at input validation) before external activity or source preparation; the remaining domain contracts do not enable those operations.

The task skill identifies `ORA_RCL_FIELD_SERVICE_TECHNICIANS` and the registered BO identifier `technicianSubinventories` (UI name Technician Subinventories). The reviewed APEX registration and published live Data Loader template establish the columns, TechSubinventoryId surrogate, and PartyId/StockLocationId user key. These source contracts describe create-only assignments, an EnabledFlag-only update, a narrowly scoped default usable repair and deletion of one uniquely resolved existing assignment, conditional on the capability gates below. Other updates require separately reviewed operation guidance.

## Data Loader Operation Contracts

Validate exact registered columns and key flags through core.data-loader before source preparation. PartyId identifies the technician and StockLocationId identifies the organization/subinventory combination. Condition and ConditionCode are read-only assignment evidence; requested condition must match the selected stock location.

Create uses RestAction=POST. EnabledFlag-only update uses exactly RestAction=PATCH, returned TechSubinventoryId and the requested Boolean flag. One selected deletion uses exactly RestAction=DELETE and returned TechSubinventoryId; core.data-loader must verify the registered delete operation and emit its supported delete directive. Operation values are loader columns, not alternate execution routes.

All operations below require a future reviewed Data Loader reader and complete current assignment, technician and stock-location reference evidence selected by the task Reference Read Workflow. Obtain the complete unfiltered result through the task-selected core.data-loader reader and its declared reference reads; missing or invalid evidence blocks before preview or import. Missing registration blocks preparation until environment-owner repair outside this skill and Data Loader revalidation. No other executor is permitted.

Oracle's [Field Service Technicians setup guide](https://docs.oracle.com/en/cloud/saas/service-logistics/26b/fasgs/overview-of-field-service-technicians-setup.html) requires default usable and defective stocking locations. The observed Data Loader business error RCL_NO_DEF_USABLE_SUBINV rejects a create that leaves the technician without a default usable assignment. The check below detects that missing prerequisite; it does not establish additional enabled-state or cross-organization transition rules.

## Reviewed Default Usable Repair

When the user selects an existing usable assignment to resolve a missing default usable prerequisite, core.data-loader may prepare exactly RestAction=PATCH, TechSubinventoryId, DefaultFlag=true and EnabledFlag=true. This is a separate operation from the EnabledFlag-only test update. The registered surrogate and both flag columns must be verified against the live template. Oracle's [stocking-location editing guidance](https://docs.oracle.com/en/cloud/saas/service-logistics/26a/fasgs/edit-stocking-locations-assigned-to-technicians.html) describes the enabled and default preferences. No broader field update or default reassignment is authorized by this repair contract.

# Error Handling

## Error Situations

| Situation | What Should Happen |
|---|---|
| Local checkpoint history or current-state persistence fails | Stop with artifact_persistence, the failing checkpoint_archive or checkpoint_write stage, retained artifact references and a storage-recovery action. Snapshot terminal history before atomic current-state replacement so either failure retains the prior current checkpoint. Preserve any completed snapshot; do not repeat a Fusion operation or silently continue. |
| Data Loader failure evidence would be saved | Core persistence is authoritative: render the report, keep diagnostics and counts in active memory, and save no core failure report, log, summary, dashboard or failure run record unless the user requests a specific file. Authorized logs from user-requested core status checks follow that separate policy. Pillar checkpoints retain identity, IDs, continuation/dispatch markers, terminal outcome flags and decisions only; do not embed core failure contents. Later recovery without a report requires a fresh user-requested check for the same accepted ID and environment; no automatic read or resubmission. |
| Authentication or transport handling is required for a declared operation | Delegate authentication, token refresh, HTTP transport, and technical retries to the executing core skill: core.fusion-api.rest-api-client for metadata/readback, core.data-loader for loads, or core.fusion-api.ess-job-submitter for rebuild submission. Do not wrap a failed core invocation in a pillar-level retry. Preserve core’s failure stage, classification, and diagnostics; apply the index-specific stop and continuation rules. Failed or uncertain index changes must not be automatically resubmitted; a subsequent attempt requires the applicable workflow checks and approval. |
| The request names multiple indexes or an attribute's index cannot be assigned unambiguously | Stop before index-specific lookup or payload preparation. Ask the user to select one index and its attributes for this invocation; do not split or queue the input. |
| Captured Data Loader rows contain a different IndexName, another business object, or invalid POST codes | Stop before Task Hook preview and approval with input_validation. Correct the source, then repeat Core preflight, archive-row validation and Task Hook preview for the active canonical index. |
| The selected index load, readback, or ESS result is pending, failed, or uncertain | Report its status and next user action. Do not resubmit or start a different index as a continuation of this invocation. |
| Business object is blank or differs from productManagementESIndexedAttributes | Stop and request the exact registered Data Loader business object. |
| Core Data Loader registration or metadata validation fails or remains incomplete for productManagementESIndexedAttributes | Stop before sample generation or import planning; report core's failed stage, diagnostics, and unresolved requirements. |
| User-provided index name is absent, has no exact LookupCode-or-Meaning match in ORA_EGP_PM_ES_INDEXES, or matches multiple unique LookupCodes | Stop before the action-specific lookup and payload preparation. Request a disambiguated index name; do not choose a LookupCode. |
| Index scope is absent, or scope resolution returns zero or multiple candidates | Stop before payload preparation. Request index, group, and object names or codes; do not infer a target from the attribute name. |
| Index scope resolution returns exactly one candidate and the user omitted group or object scope | Stop and present the candidate IndexName, GroupCode, and ObjectCode for user confirmation. Do not continue to exact attribute validation until it is confirmed. Fully supplied, uniquely matching scope requires no extra confirmation. |
| Seeded index metadata is unavailable, malformed, or includes an invalid SeededIndexedAttributes identity | Stop before addition-delta calculation. Correct the index name or obtain a valid metadata response; do not infer seeded attributes. |
| Existing indexed-attribute lookup is unavailable, malformed, or returns a row without a complete code identity | Stop before addition-delta calculation. Do not assume that an attribute is absent. |
| Addition delta is empty and no removals are requested | Do not prepare Data Loader rows. For a rebuild-only request, this means every seeded identity is already indexed. Persist and validate the empty delta without --require-data-loader. Record Data Loader as intentionally skipped, prepare the exact ESS payload and persist ess_approval_pending before review unless the user explicitly confirms ESS is not required. Empty deltas and business review are not blocked failures. |
| Data Loader change is pending or uncertain | Do not prepare or submit ESS. Report status and wait for a requested check or reconciliation. |
| Data Loader change has a confirmed terminal failure | Present the complete core report and retain partial-success counts in active memory. Persist only the permitted pillar data_load_failed checkpoint; saving a core failure report requires an explicit request for a specific file. Without an authorized report, validate fresh user-requested in-memory status evidence through --reconcile-stdin with user_requested_status_check=true. Then ask whether to proceed with rebuilding the current index despite failure. A proceed choice permits payload preparation only; require separate fresh exact-payload ESS approval. A decline stops without submission. Rebuild does not repair failed rows. |
| Addition and removal requirements overlap under the delta design rule | Stop with input_validation before source preparation or approval. Identify the original addition/removal request positions and resolved scope; ask the user to choose add or remove. Preserve the request until corrected, then resolve and validate it again. Do not silently drop either operation or infer replacement. |
| A nonempty delta reaches the Data Loader gate | Require the validated request, calculated delta, resolved removal evidence, digest-bound archive-row identity validation, a live create contract for POST rows, and core Data Loader approval before import. Follow core.data-loader’s existing preflight, Task Hook and approved-artifact submission contract. If approval is absent, stop at REQUEST_DATA_LOADER_APPROVAL. After an accepted Request ID, stop at WAIT_DATA_LOADER_STATUS until the user requests a check. A pending check returns to that wait terminal. A terminal successful status permits VERIFY_LOADED_ATTRIBUTES; a confirmed terminal failed status routes to DECIDE_FAILED_LOAD_REBUILD; uncertain status stops at HANDLE_ERROR. Resume this gate from the durable task record; do not recalculate the post-import delta, re-upload, or infer consent. |
| A terminal successful Data Loader status is returned | Preserve the complete core status report, then read back every requested change for the exact canonical IndexName. If all changes verify, prepare the ESS payload and request fresh approval in the same reply. |
| Post-load readback is missing a submitted addition or its resolved subtype, lacks required subtype evidence, retains a submitted DELETE AttributeId, or returns another index | Persist a blocked continuation state with the readback evidence. Do not prepare or submit ESS. |
| ESS delegation envelope is invalid or differs from the approved submission | Stop before invoking core.fusion-api.ess-job-submitter. Report input_validation for malformed contract fields or approval_blocker for absent approval or changed approved details. Never mark an unapproved envelope approved or refresh its hash to conceal a payload change; require fresh approval for changed submission details. |
| ESS rebuild approval is absent | Present the exact ESS payload, target environment, and index impact; stop until the user explicitly confirms submission. |
| Existing-index removal resolution returns zero or multiple records, supplied name/code/subtype selectors conflict, or a supplied AttributeId differs | Use the complete declared existing-index lookup and all original selectors. Stop before preparation on incomplete metadata or an unresolved target. Show the conflicting selectors or distinguishing candidate names/codes; do not synthesize an ID or ask for a name that a supplied code already resolves. |
| Available-attribute lookup for an unsatisfied request returns zero or multiple matches, or its response does not include items | Stop before POST payload preparation or import planning; do not infer the attribute code or target context. |

| A new execution request follows a terminal blocked review checkpoint with no Data Loader Request ID or ESS submission/uncertain dispatch evidence | Archive the old state with --start-new even for the same index, repeat validation, and obtain fresh approvals. Never carry prior approvals or external IDs forward or use this path for pending or uncertain external actions. |
| A blocked accepted load is reconciled by a user-requested core status/readback check | Require confirmed core evidence bound to the saved environment, request fingerprint, canonical index and accepted Request ID. Use --reconcile-stdin to record data_load_pending or data_load_succeeded; for readback_verified also require confirmed successful load and exact verification of the original submitted delta. Retain core diagnostics in active memory unless a specific failure file was requested; preserve only pillar reconciliation markers and authorized references. With no authorized report reference, require user_requested_status_check=true and confirmed in-memory evidence from the fresh core check; do not upload or initiate again. |
| A blocked ESS dispatch is confirmed accepted | Record ess_submitted only with confirmed core evidence for the original approved payload fingerprint, environment and canonical index plus its accepted ESS Request ID. Preserve dispatch history; no replacement submission or new approval is implied. |
| Legacy or unidentified uncertain dispatch lacks immutable evidence | Keep blocked. Obtain original registered artifacts and exact core evidence through the active workflow; do not fabricate environment/request/payload bindings, reset state or infer an accepted request from a similar job. |

## Error Classifications

| Result Category | When Used | Next Action |
|---|---|---|
| input_validation | POST codes, including a nonblank metadata-derived ObjectSubTypeCode, are missing, differ from the uniquely resolved metadata record, or supplied names and codes conflict | Stop before approval. Keep findings in the live Task Hook result; require fresh Core preflight, archive validation and Task Hook approval after source correction. |
| catalog_or_metadata_mismatch | Live create describe metadata is missing or malformed | Stop before POST preparation and obtain the declared create contract. |
| Fusion API | EGP-2776245 reports no matching available attribute | Compare the captured submitted identity with available metadata and the live create contract before proposing a retry; never automatically resubmit. |
| input_validation | The request names multiple indexes, has ambiguous attribute-to-index assignment, or its captured rows contain a different IndexName | Select one index and correct its request or artifact before any Fusion mutation; do not split, merge, or skip indexes automatically. |
| input_validation | The business object value is blank or does not exactly match the task contract | Correct the business object and restart validation. |
| catalog_or_metadata_mismatch | Core Data Loader reports a registration or metadata mismatch for productManagementESIndexedAttributes | Resolve the requirements reported by core and require successful core validation before continuing. Preserve core's failure classification for other failures. |
| input_validation | User-provided index name is absent or does not resolve through an exact LookupCode-or-Meaning match to one unique LookupCode in ORA_EGP_PM_ES_INDEXES | Provide a disambiguated index name, then restart index validation. |
| input_validation | IndexName is absent, or the available-attributes lookup cannot resolve exactly one scope candidate | Provide index, group, and object names or codes, then restart scope validation. |
| input_validation | RestAction DELETE cannot resolve one existing backend record from all supplied name/code/subtype selectors and optional ID, or supplied selectors conflict | Show the unresolved or conflicting selectors, or candidate names/codes for ambiguity; request only the missing distinction and restart removal validation. Do not request names merely because codes were supplied. |
| approval_blocker | One existing or available metadata result supplies one scope candidate for omitted group or object scope, but the user has not confirmed it | Present the candidate scope and wait for explicit confirmation before exact attribute validation. |
| catalog_or_metadata_mismatch | A POST indexed attribute cannot be uniquely validated from indexAvailableAttributes | Correct the indexName request body or requested attribute context, then verify one exact available attribute. |
| catalog_or_metadata_mismatch | Seeded metadata or existing indexed attributes cannot be represented as complete AttributeCode#GroupCode#ObjectCode identities | Correct the live metadata contract before calculating a delta. |
| approval_blocker | A required Data Loader change has succeeded, or Data Loader was intentionally skipped for an empty delta, but the exact ESS payload has not received fresh confirmation | Present the rebuild payload and wait for approval. |
| process_failed | A terminal successful Data Loader status cannot be verified by exact-index readback | Preserve the readback evidence and correct the index data before any ESS preparation. |

## Disclosure Rules

| Gate | What Must Be Shown |
|---|---|
| When multiple indexes are supplied | State that this skill accepts one index per invocation and ask which index and attributes to process now; do not present a queued execution plan. |
| Before any Data Loader sample generation or REST import planning | The exact business object, registration-verification status, and any unresolved lookup fields. |
| Before the available-attributes lookup | The supplied index name, whether LookupCode or Meaning matched, the unique returned LookupCode, lookup type ORA_EGP_PM_ES_INDEXES, and lookup Meaning as display evidence. |
| Before payload preparation for an added indexed attribute | The target index, group, object, requested attribute name, and available-attribute validation result. |
| Before addition-delta payload preparation | The seeded identity count, requested-addition identity count, existing identity count, and resulting addition count; do not expose backend IDs. |
| Before payload preparation for an indexed attribute removal | The target index, original supplied selectors, resolved attribute/group/object names and codes, subtype when present, and backend-issued AttributeId resolved directly from Product Management Indexed Attributes. |
| After scope resolution returns one candidate for omitted group or object scope | The candidate index, group, object, source attribute name, and a request for explicit scope confirmation. |
| After an accepted Data Loader initiation | Emit the accepted Request ID, not-checked state and exact opt-in status question in commentary before the final initiation report. The final answer contains only Core's unchanged complete report. If commentary is unavailable, defer the invitation to a later interaction; never query status automatically. |
| After a successful terminal Data Loader status | The unchanged complete core status report, post-load readback result, target environment, affected index, rebuild impact, exact immutable ESS payload, and fresh approval question. |
| After a confirmed terminal failed Data Loader status | The unchanged complete core status report, error logs, successful/failed counts, target environment, affected index, accepted Request ID, rebuild impact, and explicit proceed-or-stop question. After a proceed choice, present the immutable ESS payload for separate fresh approval. |

## Refusal Rules

| Situation | What Must Not Happen |
|---|---|
| The request or captured rows contain multiple indexes | Do not build its Task Hook preview or submit it through Data Loader or ESS; do not upload, initiate, submit a rebuild job, or silently select an index. |
| A different index is requested after this invocation | Treat it as a separate request with fresh input validation and approval gates; never carry approval or an external Request ID across indexes. |
| Core Data Loader has not successfully validated the registered business object and required metadata | Do not bypass core validation, build a payload, generate an import plan, or attempt a Fusion write. |
| Index-name lookup is unverified, missing, or ambiguous | Do not call indexAvailableAttributes, use a lookup Meaning as IndexName, build a payload, or initiate a Data Loader workflow. |
| Available-attribute validation is unverified for RestAction POST | Do not infer an attribute code, target context, or payload. |
| RestAction DELETE has no uniquely resolved existing record for all supplied name/code/subtype selectors, has conflicting selectors, or has a mismatched supplied AttributeId | Do not build a delete row, reuse an AttributeId from another record, or initiate a Data Loader workflow. |
| Scope resolution is unconfirmed, missing, or ambiguous | Do not populate GroupCode or ObjectCode, build a payload, or initiate a Data Loader workflow. |
| The addition delta is empty and no removals are requested | Do not initiate Data Loader. Do not skip ESS unless the user explicitly confirms it is not required. |
| A Data Loader change is pending or uncertain, or terminal failure has no explicit proceed choice | Do not prepare or submit ESS. Only confirmed terminal failure plus an explicit proceed choice may bypass the success/readback prerequisite; separate exact-payload approval remains mandatory. |
| A successful Data Loader status has not yet completed exact-index readback | Do not end the index-management response at the status report or prepare an ESS approval prompt. |

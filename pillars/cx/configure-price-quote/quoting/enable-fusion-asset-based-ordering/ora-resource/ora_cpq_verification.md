# CPQ Verification

## cpq-verification

CPQ submission is not completion. Only an explicit user request triggers the
existing Core status helper for the exact saved request and selected target.
Pending stops without polling. Failed/unknown status blocks the companion.
Require successful load status plus fresh GET readbacks of the selected process,
enableFusionABO=Yes and the exact fixed defineFieldsForModifyActionFunction value.
Normal enablement imports all three settings; function-only recovery imports
only the fixed function, but verifies all three final values through GET.
Bind submission and verification to the same project, target and non-executable
workflow ID. Never infer load success from readbacks or authorize a second import.

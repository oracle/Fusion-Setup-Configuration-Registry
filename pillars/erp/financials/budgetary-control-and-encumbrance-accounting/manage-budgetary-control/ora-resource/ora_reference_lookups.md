## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| Default or code derivation | Use current FSM metadata and CSV templates first, supported read-only Fusion metadata second, Oracle documentation third, and Enterprise Data Model documentation fourth. |
| Entity existence | Treat Enterprise Options, Enabled Ledger, GL attributes, segment values, cash accounts, journal sources/categories, business units/functions, transaction sources/types, and document types as mandatory pre-create checks. |
| Read-only access | Use only shared auth and FSM REST primitives for a supported read; preserve sanitized evidence and never store credentials, tokens, or headers. |
| Current-state validation | For a mutation candidate, immutable preview, import, or post-import verification, use a fresh populated same-task export created after the latest known setup mutation. For a read-only answer, a downloaded same-task archive may be authoritative only when its process ID and timestamp are recorded and affirmative evidence shows that no setup mutation occurred afterward. Elapsed time alone never proves currency. If the mutation boundary is unknown or no supported source is available, record the value as unresolved and block validation. |
| Unsupported read contract | Record the value as unresolved and block preview; do not invent an endpoint or submit an import to discover it. |

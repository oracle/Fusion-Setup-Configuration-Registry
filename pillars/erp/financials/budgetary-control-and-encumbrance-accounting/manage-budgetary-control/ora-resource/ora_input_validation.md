## Read-Only Lookup Request Interpretation

| Request Shape | Required Result | Evidence Rule | Resolver |
|---|---|---|---|
| Any request whose answer depends on current Manage Budgetary Control setup data | For a mutation candidate, preview, import, or post-import verification, create a fresh populated same-task export after the latest known setup mutation. For a read-only answer, reuse the latest populated export only when its process ID and timestamp are recorded and affirmative evidence shows that no setup mutation occurred afterward. Elapsed time alone never proves currency. | Record the export process ID, package timestamp, and mutation-boundary evidence used for the assertion. When the mutation boundary is unknown or currency is otherwise uncertain, obtain a fresh populated same-task export. Never use an export that predates a known setup mutation. | resolve_existing_budgetary_control_setup |
| A request for a lookup-backed attribute names a ledger or business unit | Report the attribute's current stored code and resolved lookup Meaning for that exact ledger or business unit. Do not return the full lookup list unless separately requested. | Apply the general fresh-export rule, require exactly one matching entity row at the attribute's template-defined scope, and resolve its stored code through that attribute's declared lookup type. Never substitute a value from a different ledger, business unit, or entity scope. | resolve_existing_budgetary_control_setup |
| A request for a lookup-backed attribute does not name a ledger or business unit | List every enabled, effective LookupCode and Meaning from that attribute's declared lookup type. Do not select or report an entity-specific current value. | Query the exact lookup type live for each request. Do not use an exported entity row as the source of the available-value list. | resolve_existing_budgetary_control_setup |

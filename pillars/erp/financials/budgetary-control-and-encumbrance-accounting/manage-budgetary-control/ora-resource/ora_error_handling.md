# Manage Budgetary Control Error Handling and First-Go Import Gate

## Error Situations

| Situation | What Should Happen |
|---|---|
| Template metadata, technical code, or default is unresolved | Stop before package generation; resolve it from the declared evidence order. Never use a failed live import to learn it. |
| Existing-object result is absent, ambiguous, or differs | Stop create generation; report the identity or field differences and require explicit confirmation of the supported update scope. This confirmation does not authorize import submission. |
| Additional budgetary control liquidation validation is requested for enablement | Before preview approval, warn: Enabling Additional budgetary control liquidation validation is irreversible. Once enabled, it cannot be disabled. |
| Additional budgetary control liquidation validation is requested for disablement after enablement | Warn: Cannot disable Additional budgetary control liquidation validation because this feature was previously enabled. Once enabled, it cannot be disabled. Omit that change and continue with other requested Enterprise Option changes; stop before preview when no other requested change remains. |
| Ledger is unresolved or ineligible | Stop before preview and show: Cannot use ledger <LedgerName> because it does not resolve to exactly one eligible Fusion ledger. Provide the exact ledger name, then retry. |
| Ledger Budgetary Control enablement has conflicting projections | Stop before preview and show: Cannot enable Budgetary Control for ledger <LedgerName> because the Enabled Ledger and GL Attributes package rows are inconsistent. Set ORA_XCC_ENABLED_LEDGER.BcEnabledFlag, ORA_XCC_ENABLED_ATTRIBUTES_IN_GL.BcEnabledFlag, and ORA_XCC_ENABLED_ATTRIBUTES_IN_GL.EnableBudgetaryControlFlag to Y for that ledger, then rebuild the immutable package. |
| Cash controls are enabled for a ledger for the first time | Before preview approval, show: If you enable cash controls, a cash control budget is created for you with a defining status.<br><br>To enforce the cash control options, you must put the control budget in use on the Manage Control Budgets page after reviewing the control level, budget segments, and other settings. |
| Receivables receipt funds the cash budget is enabled | Before preview approval, show: You must enable Receivables in the Financials offerings and multifund accounting in the Manage Receivables System Options task before enabling this option. |
| An existing cash-control segment value is requested for disablement or deletion before permanent closure | Stop before preview, preserve the existing row, and show: You must permanently close the <CashControlBudgetName> cash control budget for ledger <LedgerName> on the Manage Control Budget page before you can disable or delete cash controls. Require fresh evidence that the cash control budget associated with the requested ledger has status Permanently Closed before allowing either operation. Do not apply this closure prerequisite when adding a new segment value with EnabledFlag Y or N. |
| Business unit is unresolved, inactive, or associated to a different ledger | Stop before preview and show: Cannot use business unit <BusinessUnitName> because it does not resolve to exactly one active Fusion business unit associated with ledger <LedgerName>. Provide the exact business unit and associated ledger, then retry. |
| Business-unit Budgetary Control default date rule is requested while Budgetary Control is disabled for that business unit | Stop before preview and show: Budgetary Control must be enabled for business unit <BusinessUnitName> before its Budgetary Control default date rule can be set. Do you want to enable Budgetary Control for <BusinessUnitName> and set <DateRuleField> to <LookupMeaning> together? Do not create or submit a date-only candidate. If approved, confirm the associated ledger remains Budgetary-Control-enabled and build one coordinated candidate. |
| Requisitioning Budgetary Control enablement omits a required dependent business function | Stop before preview and show the missing same-business-unit functions. Requisitioning requires Procurement, Receiving, and Payables Invoicing. If Expense Management is not already enabled, enable it the first time Requisitioning is enabled. Add the required rows and rebuild the immutable package. |
| Procurement Budgetary Control enablement is requested while Requisitioning is disabled | Allow Procurement to be enabled without enabling Requisitioning, but require Receiving and Payables Invoicing enabled for the same business unit. For Expense Management, use an explicit user request to enable or disable it first; otherwise retain the current same-business-unit BcEnabledFlag Y or N from the fresh export. Default EXPENSE_MANAGEMENT_BF to Y only when neither an explicit user choice nor an existing Y or N value is available. Never overwrite an explicit choice or existing value with the Procurement default. |
| Procurement Budgetary Control enablement omits Receiving or Payables Invoicing | Stop before preview and show the missing same-business-unit functions. Whenever Procurement is enabled, Receiving and Payables Invoicing must be enabled regardless of Requisitioning state. Add the required rows and rebuild the immutable package. For Expense Management, use an explicit user request to enable or disable it first; otherwise retain the current same-business-unit BcEnabledFlag Y or N from the fresh export. Default EXPENSE_MANAGEMENT_BF to Y only when neither an explicit user choice nor an existing Y or N value is available. Never overwrite an explicit choice or existing value with the Procurement default. |
| Business-function Budgetary Control enablement finds a disabled parent business unit | Stop before preview and show: Budgetary Control must be enabled for business unit <BusinessUnitName> before it can be enabled for business function <BusinessFunction>. Do you want to enable Budgetary Control for the business unit and business function together? Do not build or submit a function-only candidate. If approved, preserve the associated-ledger Budgetary Control enablement and build one coordinated package with the Business Unit row before the Business Function rows. |
| Project Accounting transaction type or subtype is supplied | Stop before preview and show: Project Accounting (`PROJECT_ACCOUNTING_BF`) has no transaction type or subtype. Provide only supported Project Accounting transaction source and document rows. Do not add or change other business functions. |
| Project Accounting transaction source or document is supplied while Project Accounting is disabled | Stop before preview and show: Budgetary Control must be enabled for Project Accounting (`PROJECT_ACCOUNTING_BF`) before transaction source and document rows can be provided. Enable Project Accounting first, then rebuild the source/document candidate. |
| Enabled Requisitioning or Procurement has an invalid Reservation Point | Stop before preview and require Approval / N or Submission / Y through the declared lookup. Accept either valid value; do not replace a valid Submission choice with Approval. |
| Reservation Point is requested while the business function has Budgetary Control disabled | Stop before preview and show: Cannot set Reservation Point for business function <BusinessFunction> because Budgetary Control is disabled for business unit <BusinessUnitName>. Enable Budgetary Control for that function first. Do not infer enablement. |
| Reservation Point is requested for a business function other than Requisitioning or Procurement | Stop before preview and show: Reservation Point can be set only for Requisitioning and Procurement. Do not set it for <BusinessFunction>. |
| Encumbrance Accounting is requested for an unsupported business function | Stop before preview and show: Encumbrance Accounting can be enabled only for Requisitioning and Procurement. It cannot be enabled for <BusinessFunction>. |
| Business-function Encumbrance Accounting is set while the parent business unit is disabled | Stop before preview and show: Encumbrance Accounting must be enabled for business unit <BusinessUnitName> before setting Encumbrance Accounting for business function <BusinessFunction>. Do not infer a parent change. |
| Business-unit Encumbrance Accounting disablement | Before immutable-package approval, display exactly: Encumbrance accounting will no longer be created for the business unit <Businessunitname>.\n\nIf you enable encumbrance accounting again, you will need to reinitialize balances to correct the encumbrance amounts. However, when you reinitialize balances, transactions may not be fully accounted and the downstream processing of transactions can cause errors. Require explicit approval of the warning together with the exact immutable package. |
| Business-unit Encumbrance Accounting disablement omits child-function disablement | Stop before preview and show: Cannot disable Encumbrance Accounting for business unit <Businessunitname> while Requisitioning or Procurement Encumbrance Accounting remains enabled. Disable Requisitioning first and Procurement second in the same coordinated package, then rebuild the immutable preview. |
| Procurement Encumbrance Accounting enablement is requested while Requisitioning is disabled | Stop before preview and show: Cannot enable Encumbrance Accounting for Procurement while Requisitioning has Encumbrance Accounting disabled for business unit <BusinessUnitName>. Enable Requisitioning Encumbrance Accounting first. Do not infer a Requisitioning change. |
| Procurement Encumbrance Accounting disablement is requested while Requisitioning is enabled | Stop before preview and show: Cannot disable Encumbrance Accounting for Procurement while Requisitioning has Encumbrance Accounting enabled for business unit <BusinessUnitName>. Disable Requisitioning Encumbrance Accounting first. Do not infer a Requisitioning change. |
| Any business function has Budgetary Control disabled | Before immutable-package approval, display exactly:<br><br>Disabling budgetary control for the business function also disables budgetary control for its transaction types.<br><br>If you enable budgetary control again, you will need to reinitialize balances to correct the funds available amounts. However, when you reinitialize balances, transactions may not be fully reserved and the downstream processing of transactions can cause errors. |
| Procurement Budgetary Control disablement is requested while Requisitioning is enabled | Stop before preview and show: Cannot disable Budgetary Control for Procurement while Requisitioning has Budgetary Control enabled for business unit <BusinessUnitName>. Disable Requisitioning first, take a fresh export after a separate change, or explicitly request one coordinated package that disables Requisitioning before Procurement. |
| Receiving or Payables Invoicing Budgetary Control disablement is requested while Procurement is enabled | Stop before preview and show: Cannot disable Budgetary Control for <BusinessFunction> while Procurement has Budgetary Control enabled for business unit <BusinessUnitName>. Disable Procurement first, take a fresh export after a separate change, or explicitly request one coordinated package that disables Procurement before <BusinessFunction>. |
| Ledger disablement finds an enabled business unit | Stop before preview and show: Cannot disable Budgetary Control for ledger <LedgerName> because these business units still have Budgetary Control enabled: <BusinessUnitNames>. Budgetary Control can be disabled for this ledger only after it is disabled for every associated business unit. Disable Budgetary Control for every listed business unit, take a fresh export, then retry. |
| Control Budget Filter update finds an enabled business unit | Stop before preview and show: Cannot update Control Budget Filter for ledger <LedgerName> because these business units still have Budgetary Control enabled: <BusinessUnitNames>. Control Budget Filter can be updated only after Budgetary Control is disabled for every associated business unit. Disable Budgetary Control for every listed business unit, take a fresh export, then retry. |
| Transactions without project attributes option is enabled with LEDGER / Ledger only | Stop before preview and show: Cannot enable Transactions without project attributes don't have a matching chart of account based control budget when Control Budget Filter is LEDGER / Ledger only. Select PROJECT / Project or BOTH / Ledger or project, or leave this option disabled. Also stop when the Enabled Ledger and GL Attributes CoaControlBudgetFlag values differ. |
| Budget Segment and Segment Value do not form a valid pair | When the prompt supplies Segment Value with Always use segment value from budget data, ignore it, serialize Segment Value as blank, and warn: Segment Value is ignored when Budget Segment is Always use segment value from budget data. When the prompt omits Segment Value with Use a specified value when not provided in budget data, retain the nonblank value from the exact existing segment row. If no nonblank existing value is available, stop before preview and show: A Segment Value is required when Budget Segment is Use a specified value when not provided in budget data. |
| Specified Segment Value does not resolve as existing and enabled | Stop before preview and show: The Segment Value <SegmentValue> must exist and be enabled for <SegmentCode> in the ledger's chart of accounts before it can be used. Create and enable the value, then retry. Do not submit an import to discover whether the value is valid. |
| Budgetary Control Journal Exceptions are requested while journal budgetary control is disabled globally | Stop before preview and show: Cannot define Budgetary Control Journal Exceptions for ledger <LedgerName> because Disable budgetary control for all journal sources and categories is Yes. Set this option to No, take a fresh export, and retry. Also stop when the Enabled Ledger and GL Attributes DisableBcJournalsFlag values differ or either required projection is missing or duplicated. |
| Journal source is unresolved or ineligible | Stop before preview and show: Cannot use journal source <JournalSource> because it does not resolve to exactly one eligible Fusion journal source. Provide the exact journal source key or display name, then retry. |
| Journal category is unresolved, ineligible, or lacks a source parent | Stop before preview and show: Cannot use journal category <JournalCategory> because its journal source is unresolved or the category does not resolve to exactly one eligible Fusion journal category. Resolve the journal source first, provide the exact journal category key or display name, then retry. |
| Business-unit Transaction Source is validated through a ledger Journal Source endpoint | Stop before preview and show: Transaction Source <TransactionSource> belongs to a business unit and must be resolved through the transaction-sources REST service. Do not use the ledger Journal Source LOV. |
| Business-unit Document is validated through a ledger Journal Category endpoint | Stop before preview and show: Document <DocumentType> belongs to a business-unit Transaction Source and must be resolved through the transaction-document REST service. Do not use the ledger Journal Category LOV. |
| Business-unit Transaction Source or Documents is unresolved | When the authenticated transaction-sources LOV returns no value, serialize the exact user-provided Transaction Source into the business-unit CSV and continue with its document scope; do not substitute a ledger Journal Source or Journal Category. Stop only when the user did not provide a source or multiple conflicting matches are returned. Keep the fallback detail internal to validation and omit it from FSM export/import execution messaging. |
| Ledger Encumbrance Accounting disablement finds an enabled business unit | Stop before preview and show: Cannot disable Encumbrance Accounting for ledger <LedgerName> because these business units still have Encumbrance Accounting enabled: <BusinessUnitNames>. Disable Encumbrance Accounting for every listed business unit, take a fresh export, then retry. |
| Fresh export has a populated Reserve for Encumbrance Account | Show the exact ResEncumCcidSegments value for ledger <LedgerName>, preserve it unchanged in the candidate, and continue without asking the user to provide an account. |
| Ledger or business-unit Encumbrance Accounting enablement has a blank Reserve for Encumbrance Account | Stop before preview and show: Cannot enable Encumbrance Accounting for ledger <LedgerName> because the Reserve for Encumbrance Account is blank. Define or provide the exact account combination in ResEncumCcidSegments, take a fresh export, and retry. |
| Journal source category scope conflicts with the request | Stop before preview and show: Cannot use All journal categories for source <JournalSource> together with specific journal categories. Remove the specific categories to use All, or set the source to specific categories and provide the validated category list. |
| Business unit enablement finds a disabled associated ledger | Stop before preview and show: Cannot enable Budgetary Control for business unit <BusinessUnitName> because its associated ledger <LedgerName> does not have Budgetary Control enabled. Enable Budgetary Control for that ledger first, take a fresh export, then retry. |
| Parent relationship fails | Stop the affected child package; verify or add the parent in declared dependency order. |
| Fusion rejects a preview or live import | Preserve redacted diagnostics, correct the exact issue, regenerate the immutable package, and obtain fresh approval. Do not retry automatically. |
| Authentication, authorization, or transport fails | Classify it separately from no match, preserve sanitized evidence, and stop without treating it as an empty result. |

## Import Readiness Record

| Required Item | Must Show | Blocking Rule |
|---|---|---|
| Package contract | Every required CSV, ASM_SETUP_CSV_METADATA.xml, header, and source evidence | Block if a member, column, or constraint is unknown. |
| Values and defaults | Every supplied value, generated technical value, default source, and unresolved item classification | Block on an unresolved technical lookup or default. |
| Existing-object comparison | Exact entity key, matched existing record or no-match evidence, field-by-field comparison, and update support | Block duplicate create and unapproved or unsupported update. |
| Ledger enablement projections | For each requested ledger BcEnabledFlag N to Y transition, exactly one companion GL Attributes row for the same LedgerName, all three candidate enablement flags set to Y, and metadata node-order evidence | Block preview on a missing, duplicated, or conflicting projection. |
| Relationships | Parent evidence for each enabled-ledger, journal, business, and transaction child relationship | Block any missing dependency. |
| Approval | Target, immutable package fingerprint, intended operation, and Core Data Loader approval receipt issued after those exact details are shown | Return `approval_required` to Core Data Loader and block live import until Core Data Loader records the user's direct approval of that exact package. Do not ask separately in this task workflow. Never assume approval from an enablement request, repeated request, `yes` to another question, request for a new session, or other contextual wording. |

## Disclosure Rules

| Gate | What Must Be Shown |
|---|---|
| Readiness | Complete readiness record, unresolved values, source evidence, and approval state. |
| Failure | Task code, target, process identifier when available, redacted diagnostic, and one safe next action. |

## Refusal Rules

| Situation | What Must Not Happen |
|---|---|
| Technical value, metadata, or existence evidence is unresolved | Do not generate or submit an import package. |
| Existing definition differs | Do not blindly create or update; require an explicit approved, import-supported action. |
| No Core Data Loader approval receipt for the exact final package | Do not mutate Fusion. Return `approval_required` to Core Data Loader and wait; do not ask separately or make assumptions from context or prior authorization. |
| Credential material | Do not store passwords, tokens, Authorization headers, or secrets in artifacts. |

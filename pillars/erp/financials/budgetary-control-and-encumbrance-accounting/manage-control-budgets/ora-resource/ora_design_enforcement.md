# Manage Control Budgets Design Enforcement

Evaluate every requested Control Budget header, budget segments, and assigned trees first. Collect every independent blocker across budgets, then decide the Control Budget gate before rule groups. After all budgets pass, evaluate Supplemental, Revenue Funding, and Override Rules as independent requested groups. Supplemental checks cover each rule header, Budget Segment Filters, Additional Segment Filters, Transaction Attribute Filters, and links; Revenue and Override checks use their Design contracts below. A failure in any group does not suppress independently checkable findings in another. Mark checks blocked by a missing prerequisite `not_evaluated`, with that prerequisite, while continuing independent checks. One final package gate consumes all requested groups' findings. Preserve the individual blocker rules below and defer only the target checks they already assign to Fusion import.

## Enforcement Order

| Sequence | Step | What Must Happen |
|---|---|---|
| 1 | Control Budget phase | Validate and resolve every requested budget's header, budget segments, and assigned trees; collect all independent findings across budgets. |
| 2 | Control Budget gate | Continue only if every budget passes. Report one combined budget issue list and stop before all three rule groups on failure. |
| 3 | Supplemental Rule phase | For every supplied rule across budgets, validate and resolve its header, Budget Segment Filters, Additional Segment Filters, Transaction Attribute Filters, and links; collect all independent findings. |
| 4 | Revenue Funding Rule group | Validate every requested Revenue rule after the budget gate even if Supplemental findings exist. Collect all independent header, funding-target and Revenue-source findings; omit this group only when not requested. |
| 5 | Override Rule group | Validate every requested Override rule after the budget gate, regardless of Supplemental or Revenue findings. Collect all four sections and retain the declared target deferrals; omit this group only when not requested. |
| 6 | Final package gate | Require complete outcomes for every requested group and retain all findings. Block ZIP generation when any required check fails or is unresolved; no group's success is a prerequisite for checking another. |
| 7 | Compare and readiness | After the final package gate passes, preserve existing target comparison or reference-baseline exception and produce the first-go import-readiness record before preview or import. |

## Revenue Funding Rule Design

| Area | Required behavior | Resolver |
|---|---|---|
| Group independence | Control Budget pass precedes Revenue checks; Supplemental success is not a Revenue prerequisite. Validate all independent requested groups before final package gate. | resolve_revenue_rule_package_contract |
| Eligibility | Only Source Budget Type Other and enabled parent AllowRevenueFundingFlag gate Revenue creation. Preserve existing unrelated Control Budget checks. | resolve_source_budget_system_code |
| Source versus target | Source uses every selected source COA segment and its exact column; target combinations use parent budget segment order. Do not translate between them by guessed ordinals. | resolve_revenue_source_coa |
| Source row order | After the Revenue-source COA metadata input check passes, sort source Condition rows and source Detail groups by ascending numeric sequenceNumber. Preserve returned columns/role labels, entered value order and leading zeros, and All/no-Detail behavior. Rule request order remains unchanged; target condition and Details remain last in target request order. Never infer sequence from response position or column suffix, renumber codes, or alter Control Budget/Supplemental order. | resolve_revenue_source_coa |
| Roles | Both qualified source roles are always Specific; other segments default All. Source labels, metadata keys, and returned columns agree. | resolve_revenue_source_segment_roles |
| Codes | Both limits use current lookup output; source condition codes use segmentColumnName; target uses the user-approved literal. No copied example lookup codes or physical column assumptions. | resolve_revenue_limit_type_code |
| Required fields | Validate positive amounts, required scenarios, mutually exclusive estimate choices, target shape, and positive percentages with exact total 100 before rows are consumed. | resolve_revenue_rule_package_contract |
| Membership boundary | Preserve user source/target values; Fusion import validates their membership. Never use an unavailable value lookup to block this user-confirmed import-deferred path. | resolve_revenue_rule_package_contract |
| Package scope | Revenue rows share the parent package with any requested Supplemental rows. Preserve all other template members and existing package behavior. | resolve_revenue_rule_package_contract |

## Override Rule Design

| Applies When | Severity | Required Lookup | Blocking Condition | Recommendation | Fix Allowed? |
|---|---|---|---|---|---|
| Override rules requested | Blocker | resolve_override_rule_package_contract | Parent is unresolved, not ORA_CONSUMPTION, or final AllowOverridesFlag is not Y | Correct the supported parent/explicit enablement; do not add Cash support or silently enable the parent | Yes, with corrected input |
| Every requested Override rule | Blocker | resolve_override_rule_package_contract | Name is blank/overlength/duplicated, description or flag is malformed, or required local sections are missing | Retain indexed findings across all rules; do not rename or deduplicate input | Yes, with corrected input |
| Every requested Override rule | Blocker | resolve_override_type_code | Type has no unique supported current lookup result | Resolve the explicit supported choice; do not guess codes | Yes, with corrected input/evidence |
| Amount validation | Blocker | resolve_override_rule_package_contract | Insufficient Funds amount is not finite and positive, Closed Period has an amount, supplied header maximum is negative/nonfinite, or enabled Insufficient Funds has no positive covering maximum under the declared signed Java intValue comparison | Keep decimal positivity exact, emulate signed 32-bit source comparison only for the cap, and serialize original numeric amounts unchanged | Yes, with corrected input |
| Transaction applicability | Blocker | resolve_override_transaction_type_codes | All/Specific selection is malformed, Specific is empty, or a type is unsupported/unresolved/duplicate | Require All or supported unique Specific values; all five unique supported values normalize to All | Yes, with corrected input |
| Journal selection structure | Blocker | resolve_override_rule_package_contract | Explicit selections conflict with the state matrix, Specific values are structurally empty/malformed, or Specific categories lack exactly one Specific source in the editable case | Correct the selection state without changing raw values; do not treat target-value identity as a local blocker | Yes, with corrected input |
| User assignment structure | Blocker | resolve_override_rule_package_contract | Any rule lacks at least one nonblank raw username, or an assignment is not a string | Request the missing raw usernames; do not resolve names or validate duplicate users locally | Yes, with corrected input |
| CSV mapping | Blocker | resolve_override_rule_package_contract | Any of four members, ordered headers, parent keys, flags, child-row shape, or lossless CSV representation is unverified/inconsistent | Verify the same-task contract and map all requested rows; no orphan/type rows for All and no Journal rows for All sources | Yes, with verified contract/corrected mapping |
| Source/category/user target business checks | Import-deferred |  | Identity, excluded values, membership, active-user status, or duplicate acceptance has not been checked locally | Preserve raw strings and duplicate rows, record the three allowed deferrals, and consume Fusion import diagnostics through the approved Data Loader route | Do not alter values automatically |
| Allow Overrides Y with no requested Override rules | Warning |  | No Override rule was requested | Disclose that no rules were supplied; preserve existing header/default behavior and add no rows | No rule generation |

Run `scripts/prepare_override_rules.py` for deterministic local checks and mapped rows. Its `rule_header`, `transaction_types`, `journal_conditions`, and `user_assignments` results must appear in the request-wide `overrideRules` validation input for every requested rule. Preserve rule and raw-value request order. Membership deferral IDs are only `journal_source_membership`, `journal_category_membership`, and `override_user_membership`. Do not invent a source/category/user lookup or treat a deferred business check as passed locally.

The four-member Override package shares the existing immutable package with any requested Supplemental and Revenue rows. Preserve metadata XML, parent header/segment rows, and every unrelated member. All-category Journal CSV fields are truly empty as evidenced by the same-task exports; the model's single-space convention must not leak into CSV. CSV escaping preserves the exact raw source/category/username strings, including duplicate values, while local parent-key and row-shape validation stays mandatory.

Use the source and precedence table in ora_input_validation.md: user instructions supersede the Confluence page's target-value checks, and exported CSV evidence governs serialization. This enhancement configures Override rules; it does not request, approve, or apply an override on a business transaction.

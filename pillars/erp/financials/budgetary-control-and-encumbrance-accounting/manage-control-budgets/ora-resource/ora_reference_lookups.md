# Manage Control Budgets Reference Lookups

Apply header, budget-segment, and assigned-tree lookups for every requested Control Budget in the first request-wide phase. Do not begin Supplemental, Revenue, or Override lookups until every budget passes that gate. Within the active phase, resolve all independent requested fields and the Supplemental transaction-specific values that have declared lookup sources; preserve Revenue and Override entered-value membership for import as specified below; a failed match does not end checks of other budgets or values with available evidence. Record each unmatched, ambiguous, excluded, unavailable, or blank-code value separately with its source and sanitized evidence. Mark only prerequisite-dependent checks `not_evaluated`. The tables below retain their existing exact-match and import-deferred boundaries; each instruction to stop means block ZIP generation after the active phase's independent checks are collected.

### Segment Tree Lookup

Keep the user's selected tree text separate from the CSV `TreeCode`. Reuse the current-target COA row already matched for that budget segment's `SourceSegmentColumnName`; this does not require a second BOSS request. A unique exact match ignoring case to that row's `treeName` or `treeCode` resolves to its returned technical `treeCode`. Preserve that returned code's case in the CSV. For example, a selected `All VF Accounts` matches `ALL VF ACCOUNTS` and serializes `ALL VF ACCOUNTS`.

If the user did not select a tree, skip this resolver and leave the segment's `TreeStructureCode`, `TreeCode`, and `DefaultTreeRollupValue` empty. A selected tree does not require Tree Details rows. If the selected tree differs from the matched COA row's tree, stop before generating the ZIP; obtain authoritative evidence for the selected tree or corrected input rather than substituting the COA row's different tree.

Populate `EnabledFlag` on every requested rule row. An omitted enabled choice means `Y`; preserve an explicit disabled choice as `N`. Do not leave the CSV field empty.

For Control Budget Segment Filters, take the parent control budget's segment rows in ascending `DisplaySequenceNumber` order. Create one condition per segment in that same order: `FilterConditionType=BUDGET_GL_COA_SEGMENT` and `FilterConditionCode=SEGMENT_VALUE<i>` where `i` is its one-based position, regardless of its COA segment column name. The user supplied this exact mapping; derive it from the parent segment order without a condition-code lookup or a user-entered code. Verify that the parent rows have a complete, unambiguous order and that every inherited segment appears once. A separate additional COA segment condition does not use this mapping automatically.

For Additional Segment Filters, reuse the effective ledger's resolved ChartOfAccountsId and current-target `getChartOfAccountDetails` result. Match each requested additional segment to exactly one COA `segmentName`; require its returned nonblank `segmentColumnName` to be outside that parent set. Write `FilterConditionType=GL_COA_SEGMENT` and `FilterConditionCode` equal to that matched `segmentColumnName` unchanged. A type lookup that is unavailable, incomplete, has duplicate codes or ambiguous display names, or cannot establish its order blocks ZIP generation after the remaining independent Supplemental Rule checks. Match every user-supplied type to exactly one returned code or meaning; report each unknown type separately. For each code write `FilterConditionType=TRANSACTION_ATTRIBUTE`, empty tree fields, and the exact rule/condition parent keys from the current template. The current five codes are `P2P_BUS_FUNCTION`, `JE_SOURCE`, `JE_SOURCE_CATEGORY`, `NATURAL_ACCOUNT_TYPE`, and `DESTINATION_TYPE`.

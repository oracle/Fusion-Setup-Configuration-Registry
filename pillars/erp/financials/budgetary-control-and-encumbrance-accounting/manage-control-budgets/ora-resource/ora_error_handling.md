# Manage Control Budgets Error Handling and First-Go Import Gate

## Control Budget and independent rule-group failure report

Report every requested Control Budget header, all budget segments, and assigned trees as the first request-wide validation phase. Collect every independently checkable failure across budgets before deciding its gate. On any budget failure, return one combined report and stop before all three child groups. Only after every budget passes, evaluate all requested Supplemental Rules, Revenue Funding Rules, and Override Rules as separate independent groups. Supplemental Rules retain their existing header, Budget Segment Filter, Additional Segment Filter, Transaction Attribute Filter, and Specific transaction-value checks. Revenue Rules use their local check producer and required-input/shape checks, with source-value, target-account, and scenario membership deferred to Fusion import. Override Rules use their four local sections with source/category/user target business checks deferred to Fusion import. A failure in any group does not skip independently checkable findings in another. The final readiness gate stops before candidate ZIP generation, preview, or import if any requested group fails.

For the active phase, persist ordered findings with the budget and rule identity, field/filter path, supplied value where applicable, failed Check, failure class, sanitized lookup or template evidence, and correction. Mark a check that cannot run because a prerequisite failed as `not_evaluated` and name that prerequisite; do not label it passed. Keep checks already assigned to Fusion as `deferred_to_fusion`, not as pre-import successes. Preserve existing specific Check-to-reason mappings and single-failure outcomes. If multiple checks fail, retain one deterministic primary `actualReason` from the first failed finding in budget request order and, within a budget, Control Budget header → budget segment → assigned-tree order, or Supplemental Rule request order with header → Budget Segment Filter → Additional Segment Filter → Transaction Attribute Filter order. Every other issue remains in the findings list. Use `resolve_supplemental_rule_package_contract` as the terminal reason only when no more specific Check governs that package failure.

The Child performs the semantic checks for every requested budget, every applicable input, and every supplied Specific value, then explicitly calls `scripts/validate_units.py` once for the complete request as directed by the task `SKILL.md`. Data Loader does not call this helper automatically. The helper checks the declared outcomes and section coverage and enforces the two request-wide gate decisions; it cannot prove that omitted budgets or input/value checks were actually performed or repeat current-target lookups. If a test-suite Child result is required, split the report's `task_rule:<Check>` string into the structured `actualReason` source `task_rule` and code `<Check>` while retaining the full findings list in `actualIssues`, including each budget's identity.

## Error Situations

| Situation | What Should Happen |
|---|---|
| Required technical default or code is unresolved | Stop before package generation; resolve it from the declared evidence order. Accepted currency input or Summary UOM inheritance awaiting its declared CB.LOOKUP step is pending, not an earlier-stage missing-code error. |
| Required Detail currency input is absent | Classify as input validation and ask for the currency name. Do not require the user to know its code, infer ledger currency, or populate a default code. |
| resolve_currency_code returns no unique enabled match or conflicting input identities | Classify as reference lookup or input consistency failure, report the specific stage and supplied input, and ask for a corrected currency name or selection. Do not generate a package or guess a code. |
| Currency lookup fails or cannot complete pagination | Distinguish authentication, authorization, transport/environment, and Fusion API failures from no match. Preserve sanitized diagnostics and use only shared-client bounded auth recovery. If unresolved, stop without applying STAT/non-STAT defaults or bypassing the resolver with a baseline. |
| Required non-STAT Default Rate Type is absent or malformed | Classify as input validation under ora_input_validation.md. After final currency resolution, identify Default Rate Type (UserConversionType) and the resolved currency; for Detail/Master, ask the user for a nonblank rate. For Summary, identify the linked Master and obtain a corrected baseline or complete its atomic-Master input; a Summary-only substitute is not permitted. Stop before package generation, without choosing a rate or submitting another import. |
| STAT Default Rate Type is missing, supplied, or inherited | Not an input-validation or technical-lookup error under ora_input_validation.md. Apply ora_defaulting_rules.md by setting UserConversionType to the actual empty string; retain a supplied or inherited value only as preview evidence, never in the CSV. Continue the mandatory UOM checks. |
| Detail/Master STAT UOM input is missing | Classify as input validation and ask which UOM name should be used for that Detail/Master STAT budget. Stop before generation; do not silently apply a blank default. Never ask this question for Summary, which inherits its Master's code. |
| Summary UOM inheritance is unresolved or conflicting | Classify as baseline/output validation failure. Identify the linked Master and missing, malformed, or conflicting UnitOfMeasure evidence. Obtain its current export or completed atomic-Master resolution result, or correct the supplied Summary code; do not ask for a Summary UOM name or run its own name lookup. Stop before generation if the required code or consistency check remains unresolved. |
| resolve_unit_of_measure_code reports no match, multiple matches, an inactive UOM, or a missing code | Classify as a reference lookup failure, report the specific reason and entered name, and request a valid exact name or clarification. Retain sanitized evidence and stop before package generation; do not guess a code or retry with a different name automatically. |
| Detail/Master STAT UOM lookup fails, returns malformed data, or cannot complete pagination | Preserve the sanitized failed stage and classify authentication, authorization, transport/environment, or Fusion API failure separately from no match. Use only the shared client's bounded authentication recovery; if unresolved, stop Master and dependent Summary preparation without generation or import. Summary cannot bypass a failed Master result with a separate name lookup. |
| Detail/Master SourceSegmentName is missing, does not exactly match the resolved ledger's COA metadata, matches more than one result, or returns a blank segmentColumnName | Classify as input validation or reference lookup failure. Report the supplied source name, resolved ledger/COA ID, sanitized match count, and failure stage; ask for the exact source segment name in that ledger. Do not substitute a control-budget segment label, another ledger's segment terminology, an ordinal, or a literal `SEGMENTn`. |
| BOSS source-segment lookup is unauthorized, malformed, or fails | Classify authorization, authentication, transport/environment, or Fusion API failure separately from no match. Preserve redacted diagnostics and stop the affected Detail/Master and dependent Summary preparation; do not bypass the lookup with an earlier mapping, a reference baseline, or import-time validation. |
| Selected tree has no unique exact match on its source segment's current-target COA row or returns a blank treeCode | Classify as reference lookup failure. Report the selected tree, source segment, and sanitized match evidence. Stop before ZIP generation; request corrected input or authoritative tree evidence. Do not use a different tree, copy a display name into TreeCode, or defer this declared resolver to import. No selected tree requires no tree lookup. |
| Supplemental Rule filter uses the wrong segment set | Classify a Budget Segment Filter outside its parent budget, or an Additional Segment Filter that overlaps the budget, is absent from the effective ledger COA, or is duplicated, as input validation or reference lookup failure. Report the rule, filter section, selected segment, and matched ledger/COA evidence. Stop before ZIP generation; do not silently move a filter between sections or borrow another ledger's segment code. |
| Selected Additional Segment Filter tree does not match that segment's current-target COA row or returns a blank treeCode | Classify as reference lookup failure. Report the rule, source segment, selected tree, and sanitized match evidence. Stop before ZIP generation; do not use another segment's tree code, serialize a display label, or defer selected-tree resolution to Fusion import. An additional filter without a selected tree requires no tree-code lookup. |
| Supplied Supplemental Rule has no exact same-task package contract or applicable other-condition mapping | Classify missing members/headers as catalog mismatch, malformed user-supplied segment values as input validation, and unresolved other condition codes or optional tree fields as a reference lookup gap. Derive inherited segment codes from parent order and defer valid specific segment-value membership to Fusion import. Stop before ZIP generation only for the applicable blockers; do not omit the rule or invent other technical values. |
| Transaction Attribute Filter discovery or value validation fails | Classify an unknown type, malformed selection, excluded Business Function value, or Natural Account Type value absent from the filtered BOSS `lookupLists` response as input validation; classify inaccessible, malformed, or ambiguous current-target lookup results as a reference lookup gap. Report the rule, type, supplied value, and failed source without writing an unverified code. Stop before ZIP generation; do not omit a discovered type or silently replace Specific with All. |
| Supplemental Rule parent links, inherited segment order, or all/selected-values rows are malformed | Classify as input validation. Report the affected rule/condition and exact failed link, segment coverage/order, or row-shape check. Default an omitted inherited segment value selection to All; require corrected explicit Specific values. Do not turn an unsupported `No value` into `All`, copy a budget-segment tree, or submit a partial rule. |
| Source budget system display value has no exact XCC_CB_SRC_BUDGET_SYSTEM match, has more than one match, or the standardLookups request fails | Preserve sanitized lookup evidence, classify the failure, and stop before package generation. A case-only exact match may resolve automatically; a close-match suggestion requires explicit user confirmation and a fresh lookup. Do not write the display value as SourceBudgetSystemCode or retry automatically. |
| Supplied Summary Funds Release Timeframe has no exact ORA_XCC_CB_FUNDS_REL_TIMEFRAME match, has more than one match, returns a blank code, or the standardLookups request fails | Classify as reference lookup failure, preserve sanitized lookup evidence, and stop before package generation. A case-only exact match may resolve automatically; a close-match suggestion requires explicit user confirmation and a fresh lookup. Do not serialize the display value, inherit the Master value, or guess a code. |
| Master/Detail Funds Release Timeframe is omitted or supplied | This is not a lookup or input-validation failure. Serialize `RELEASE_IMMEDIATELY` and retain a supplied value only as non-CSV preview evidence. |
| Summary Control Budget source linkage is incomplete or inconsistent | Stop before package generation if SourceBudget or MasterCb is absent, if they differ, or if the named master/detail control budget cannot be resolved exactly once from the current same-task data export or an explicitly requested atomic archive. |
| Summary Control Budget source type is not `Control Budget` | Stop before package generation; require the `Control Budget` display value and the exact resolved SourceBudgetSystemCode. |
| Summary Control Budget inheritance or segment subset validation fails | Stop before package generation if LedgerName, CurrencyCode, UserConversionType, or ChartOfAccountsName conflicts with the linked master/detail baseline under ora_input_validation.md; an accepted blank STAT rate is not a conflict. Also stop if the Summary calendar or period range is incomplete; if the atomic master does not precede the Summary; if a requested source segment is outside the master/detail source-segment set; or if the key segment does not equal SEGMENT_VALUE followed by the Summary display sequence. Fusion import validates the supplied Summary calendar and period values. |
| Tree-version row is incomplete | Stop before package generation only when a supplied tree-version row lacks StartPeriodName, EndPeriodName, TreeVersionName, or LabelName; is duplicated or mismatched; or exists without a matching tree assignment. A segment may have a TreeCode with no tree-version row. |
| Import-time target validation fails | Preserve the Data Loader or Fusion import diagnostic for an existing object, target reference, segment, hierarchy, or technical-code failure; correct the package and require fresh approval before resubmission. |
| Package metadata is incomplete | Stop and obtain the current same-task template/spec export; do not discover columns through a failed import. |
| Template export fails | Preserve the Process Log, classify the failure, and stop. Do not automatically substitute a ledger-scoped data export or retry the export. |
| Live import fails unexpectedly | Preserve redacted process status/log, classify it, correct the unexpected issue, rerun readiness, and obtain fresh approval before retry. |

## Error Classifications

| Result Category | When Used | Next Action |
|---|---|---|
| Input validation | Required values, formatting, names, sequences, or relationships are invalid | Correct the definition before package creation. |
| Reference lookup | The source budget system display value does not resolve to exactly one LookupCode, a close-match suggestion is not confirmed, or its read-only request cannot complete | Show display-value suggestions only when available; require explicit confirmation for a near match, then rerun the lookup and readiness before package generation. |
| Detail/Master STAT UOM resolution | Required Detail/Master UOM input or resolve_unit_of_measure_code fails | Report the Master resolver diagnostic, obtain corrected Master input or restore lookup access, and rerun Master validation before package generation or dependent Summary inheritance. |
| Source-segment column resolution | Required Detail/Master SourceSegmentName or resolve_source_segment_column_name fails | Obtain the exact source segment name for the resolved ledger or restore BOSS access, then rerun the Master resolver before package generation or dependent Summary inheritance. |
| Selected tree-code resolution | A selected tree cannot be matched to the same source segment's nonblank technical treeCode | Obtain corrected input or authoritative tree evidence and rerun the lookup before ZIP generation. An unselected tree needs no lookup. |
| Supplemental Rule contract or condition resolution | A requested rule lacks exact current-template members, a resolved control level, applicable other condition codes, or optional condition-tree evidence; or supplied specific segment values are malformed | Derive inherited segment codes from parent order; copy locally valid user-supplied specific segment values and defer membership to Fusion import; obtain current-target evidence for other conditions or correct malformed input. Stop before ZIP generation for unresolved contract or other mappings and preserve sanitized provenance. |
| Supplemental Rule linkage | Inherited segment rows do not cover every parent segment once in header order, or rule, condition, or detail rows are orphaned, duplicated, or inconsistent with the All default or explicit Specific values | Correct the candidate rows and rerun local validation; no partial Supplemental Rule package or live import. |
| Summary funds release timeframe resolution | A supplied Summary Funds Release Timeframe does not resolve to exactly one nonblank ORA_XCC_CB_FUNDS_REL_TIMEFRAME LookupCode | Obtain a corrected or explicitly confirmed display value, rerun the lookup, and regenerate readiness before package generation. |
| Summary UOM inheritance | Required Master code, baseline provenance, or Summary code consistency fails | Correct the Master baseline or Summary input and reapply inheritance checks without a Summary name-to-code lookup. |
| Currency resolution | Required resolve_currency_code or currency output/consistency validation fails | Obtain corrected input or restore lookup access, then rerun currency resolution before UOM/default checks and package generation. |
| Summary baseline validation | A linked master/detail control budget is missing, ambiguous, mismatched, incorrectly ordered in an atomic archive, or conflicts with Summary Control Budget inherited ledger, currency, default-rate-type, or chart-of-accounts values under ora_input_validation.md; source segments; or sequence-derived key segments. An accepted blank STAT rate is not a baseline failure. | Correct the linked name, archive order, source segment, sequence-derived key segment, or supplied values, rerun the baseline lookup, and regenerate readiness before package generation. |
| Import validation | Fusion import rejects an existing object, target reference, segment, hierarchy, or technical code | Correct the exact returned issue and regenerate the package; do not retry automatically. |
| Approval blocker | Live import lacks explicit approval for the reviewed immutable package | Stop after readiness. |
| Process failed | Shared FSM import reports an unexpected failure | Persist redacted diagnostic and remediate without automatic retry. |

## Import Readiness Record

The readiness record includes the completed request-wide Control Budget phase and each requested independent Supplemental, Revenue, and Override group. Each includes ordered failures, `not_evaluated` checks with prerequisites, and documented `deferred_to_fusion` checks. After budget pass, failures in any rule group do not suppress checks in another. A blocked group cannot be represented as import-ready, and the final package gate prevents candidate ZIP generation while any required check is blocked.

| Required Item | Must Show | Blocking Rule |
|---|---|---|
| CSV files and metadata XML files | Every required member and source template-export evidence | Block if any required member is unknown or missing. |
| Columns and local values | Every required column, supplied value, generated value, and local package default | Block if a required value is absent, malformed, or inconsistent with the template contract. |
| Source budget system lookup | Supplied display value, XCC_CB_SRC_BUDGET_SYSTEM LookupCode, exact-match count, and sanitized lookup timestamp | Block if the LookupCode is absent or the match count is not exactly one. |
| Funds release timeframe | Master/Detail: the forced `RELEASE_IMMEDIATELY` value and any discarded supplied input. Summary omitted: the literal default. Summary supplied: display value, matched Meaning, ORA_XCC_CB_FUNDS_REL_TIMEFRAME LookupCode, exact-match count, and sanitized lookup timestamp. | Block only if a supplied Summary value does not resolve to exactly one nonblank LookupCode. Do not inherit a Master value. |
| Summary master/detail baseline | Linked master/detail Name, inherited LedgerName, CurrencyCode, UserConversionType with its conditional validation result, Master UnitOfMeasure and its provenance, ChartOfAccountsName, matched source segments, sequence-derived key segments, and the user-supplied Summary calendar and period range | Block if the linked budget is absent or ambiguous, either linked field differs, an inherited value conflicts under ora_input_validation.md, the Summary calendar or period range is incomplete, an atomic master is not ordered before the Summary, any Summary source segment is outside the baseline set, or a key segment is not sequence-derived. An accepted blank STAT rate is not a blocker. |
| Default Rate Type | Final resolved CurrencyCode, UserConversionType as supplied or inherited, its source, and the completed Default Rate Type check from ora_input_validation.md; record a blank STAT value as optional, not unresolved | Block until the owning input contract passes after currency and Summary baseline resolution. A missing non-STAT rate blocks generation; an omitted STAT rate does not. Retain supplied-value and CSV-column validation, plus unchanged UOM checks. |
| Tree assignment and optional versions | For each selected tree: user input, matched current-target source segment, returned technical treeCode, matching CSV TreeCode, TreeStructureCode, and any supplied matching tree-version rows | Block when a selected tree is unresolved or CSV TreeCode differs, or a supplied tree-version row is partial, duplicated, mismatched, or orphaned. Do not block merely because an assigned tree has no tree-version row. No tree selection needs no tree lookup. |
| Supplemental Rules | For each supplied rule: parent budget, ordered parent segments, RuleName, optional Business Unit copied to header `Name` or `""` when omitted, the same `Name` in condition and Detail parent links, `EnabledFlag` `Y` from omission or explicit enabled choice versus `N` from explicit disabled choice, resolved control level, supplied tolerance, one inherited `BUDGET_GL_COA_SEGMENT` / `SEGMENT_VALUE<i>` condition per parent segment, budget filter membership, additional filter COA membership and exclusion of parent segments, derived `GL_COA_SEGMENT` / source-column codes, selected additional-tree code evidence, inherited All/Specific choices and detail counts, exact three-member template contract, and provenance | Block package generation and preview if any requested budget filter is outside the parent budget, any additional filter is outside the effective ledger COA or overlaps the budget, any selected tree code is unresolved or mismatched, or any condition mapping, parent link, or row shape is unresolved. Defer only locally valid specific segment-value membership to Fusion import. Mark the three members as header-only when no rules were requested. |
| Target technical code and relationship evidence | Periods, manager, existing-object state, and hierarchy relationships not covered by declared resolvers | Defer to Data Loader/Fusion import validation; preserve any returned diagnostic. Ledger/COA identity and Detail/Master source-segment columns require their declared pre-generation resolvers. |
| Currency resolution | Successful resolve_currency_code evidence defined in ora_reference_lookups.md and final output/consistency validation; for inherited-only Summary currency, show baseline provenance and resolver not applicable | Block generation and preview if an applicable lookup or currency check is unresolved; an entered name or unverified code is not a resolved currency. |
| UOM resolution or inheritance | Detail/Master STAT: final currency and successful resolve_unit_of_measure_code evidence. Summary: linked Master UnitOfMeasure, source provenance, and successful inheritance/consistency checks; mark the live UOM resolver not applicable because its code is inherited. | Block generation/preview for unresolved Detail/Master STAT lookup or failed Summary inheritance. STAT always requires a nonempty code; known blank inherited UOM is allowed for non-STAT. Resolve currency and Summary consistency first; do not demand original Master name evidence from an existing export. |
| Source-segment column resolution and Summary subset | Every segment: effective ledger/COA ID, SourceSegmentName, matching returned segmentName/segmentCode, nonempty segmentColumnName, and sanitized BOSS evidence. Summary: linked Master source-segment provenance and subset check using its Master-derived effective COA. | Block generation/preview when a lookup is unresolved or a Summary source segment is outside its Master. Do not accept a literal or inferred `SEGMENTn`, a segment name from another ledger, or a COA result that is not validated against the Summary's Master. |
| Unresolved target items | Target values without a supported pre-import lookup; excludes applicable currency resolution, a supplied Summary Funds Release Timeframe, required Default Rate Type input validation, Detail/Master STAT UOM resolution, source-segment-column resolution, selected-tree-code resolution, and required Summary UOM inheritance/subset validation | Do not block immutable package preparation for these deferred items; import validates them after approval. |
| Existing-object comparison | Fusion import result and action decision | Defer comparison to import; do not retry a rejected import automatically. |
| Approval | Target environment, immutable package fingerprint, intended import, and explicit approval | Block live import without current approval. |

## Disclosure Rules

| Gate | What Must Be Shown |
|---|---|
| Control Budget validation | All independently detected header, budget-segment, and assigned-tree issues across every requested budget in one report, with each budget's name and request index; any dependent checks marked `not_evaluated` with their prerequisites; request-wide gate pass or block. On block, no Supplemental Rule checks or ZIP. |
| Supplemental Rule validation | After every budget passes the request-wide gate, all independently detected issues across every requested rule header and filter section, including each Specific value; any dependent checks marked `not_evaluated`. Preserve these findings while evaluating requested Revenue rules independently; any required failure blocks the final package gate and no ZIP is generated. |
| Revenue Funding Rule validation | After budget pass, all independently detected Revenue header, target and source issues, even when Supplemental findings exist; documented import deferrals and dependent checks remain explicit. Return both groups' findings and one deterministic primary reason. |
| Override Rule validation | After budget pass, all independent rule_header, transaction_types, journal_conditions, and user_assignments findings across every requested rule, regardless of Supplemental/Revenue findings. Show raw-value deferrals, conditional amount results, and any source-aligned signed Java intValue comparison separately from original serialized amounts. Return all requested groups and one deterministic primary reason. |
| Readiness | The complete Import Readiness Record and whether the package is approved for live import. |
| Failure | Environment, task code, process identifier when available, status, redacted diagnostic, and one safe next action. |

## Refusal Rules

| Situation | What Must Not Happen |
|---|---|
| Missing local package contract or malformed local values | Do not generate or submit an import ZIP. |
| Supplemental Rule contract, filter-section membership, parent segment order, specific-value shape, additional source-column code, selected tree code, other condition code, or parent link is unresolved | Do not generate or submit an import ZIP, silently omit a rule or inherited segment, move a segment between filter sections, guess a code, change explicit `No value` to `All`, or copy another condition's tree. A locally valid user-supplied specific segment value is not blocked merely because target membership awaits Fusion import. |
| Summary master/detail baseline is unresolved or does not pass inherited-header, Summary-calendar-and-period completeness, archive-order, source-segment-subset, and sequence-derived-key validation | Do not generate or submit an import ZIP. |
| Detail/Master STAT UOM resolution is incomplete | Do not generate or submit a package, use a blank default, replace the required Master lookup with an unrelated baseline, or treat its display name as an import code. |
| Detail/Master source-segment resolution is incomplete | Do not generate or submit a package, treat the control-budget segment label as a source selector, infer a `SEGMENTn` ordinal, reuse a different ledger's mapping, or defer the required lookup to import. |
| Supplied Summary Funds Release Timeframe resolution is incomplete | Do not generate or submit a package, serialize the display value, use a near match, inherit the Master value, or guess a LookupCode. |
| Summary UOM inheritance is incomplete | Do not submit or generate the dependent Summary package, guess its code, substitute another Master, silently overwrite a conflicting supplied Summary code, or run a separate Summary name-to-code lookup. |
| Required Default Rate Type input validation is incomplete | Do not generate or submit a package, silently default a non-STAT rate to blank, choose a ledger/example/prior-budget rate, replace missing Master data with a Summary-only rate, or reuse an old preview/approval after correction. |
| Applicable currency resolution is incomplete | Do not generate or submit a package, write a name as CurrencyCode, guess from ledger or example data, default UOM to blank, or treat an unresolved currency as non-STAT. |
| Cross-instance reference baseline | Do not bypass the final immutable-preview and explicit import-approval gate. |
| Rejected import validation | Do not retry automatically; preserve diagnostics, correct the package, and obtain fresh approval. |
| No approval | Do not import, update, or create in Fusion. |
| Credentials or tokens | Do not store them in repository or project artifacts. |
| Failed import | Do not retry a write automatically. |

## Revenue Funding Rule Errors

| Situation | What Should Happen | What Must Be Shown | What Must Not Happen |
|---|---|---|---|
| Control Budget phase has failures | Report every independent budget finding; mark all requested rule groups not_evaluated; stop before rule lookups and candidate ZIP | Budget name/index, failed Check, dependent status | Validate a child group or import a partial budget |
| Revenue required-input or local design failures | Collect all independent rules/fields and the independent Supplemental findings; mark only dependent checks not_evaluated; block candidate ZIP | Unit revenue_funding_rules, budget name/index, rule name, field path, supplied value, failed Check, class and correction | Stop at first independent field, generate partial rows/ZIP, or replace the primary reason with a resolver name |
| Lookup, role, or package evidence is unresolved | Classify auth/authz, transport/environment, catalog mismatch, or input validation as applicable; preserve sanitized evidence; report the gap | Source identity, missing mapping or member, requested selector, recommended action | Guess codes/roles, add a UI or REST fallback, or auto-enable funding |
| Revenue source sequenceNumber is missing, invalid, or numerically duplicated | Record each sequence metadata finding and preserve independent rule findings; block candidate ZIP before consuming mapped rows | Source COA identity, indexed coaSegments path, supplied sequence value, failed metadata Check, class and correction | Fall back to response order, guess from column suffix, renumber codes, defer ordering to import, or add a metadata join/lookup |
| Supplied Specific value or scenario membership not checked locally | Record the documented Fusion deferral after required inputs/shape pass; ZIP can be generated when all local groups pass | Deferred check and basis, exact preserved entered value | Mark membership passed locally or block on an unavailable value LOV |
| Import fails or outcome is uncertain | Preserve status/ProcessLog and partial outcomes using the existing Data Loader diagnostic route; corrected package requires existing approval workflow | Environment, process/request identifiers, last status, error and next action | Retry or resubmit automatically |

Primary reason ordering stays unchanged for old requests. For combined requests, Control Budget failures precede all three groups; after budget pass, existing Supplemental ordering precedes Revenue budget/rule/header/target/source ordering, followed by Override budget/rule and its four-section order. Preserve every issue with group attribution even when another group supplies the primary reason.

## Override Rule Errors

| Situation | What Should Happen | What Must Be Shown | What Must Not Happen |
|---|---|---|---|
| Override local required-input or shape failure | Classify input validation; collect every independent field/rule plus Supplemental and Revenue findings, mark only dependent checks not_evaluated, and block candidate ZIP | Unit override_rules, parent/rule names and indexes, section, field path, suppliedValue, failed Check, recommendedAction, and group result | Stop at the first independent issue, omit a rule, generate partial mapping, auto-enable parent, or replace the failed Check with a resolver name |
| Override type/transaction code has no unique supported result | Classify input validation or catalog mismatch; auth/authz or transport/environment applies to failed requests. Continue independent checks and retain sanitized lookup evidence | Requested selector, lookup identity, source/time, match result, returned unsupported/blank code if any, and correction | Guess a code, accept an excluded transaction type, hide a failed lookup with a default, or add an undeclared external route |
| Amount fails positivity, type conditionality, header minimum, or enabled coverage | Classify input validation and report the specific amount check with the existing independent findings | Original rule/header decimal values and conditional result; for coverage, comparison values after signed Java intValue conversion, including wrap when relevant | Round/truncate/wrap the CSV values, claim a decimal-exact cap comparison, or make header maximum universally required for closed-period-only/disabled rules |
| Source/category/user target identity or business acceptance has not been checked | Record deferred_to_fusion under journal_source_membership, journal_category_membership, or override_user_membership; preserve supplied raw values and duplicates | Deferred check, raw value, local shape result, and target-validation boundary | Claim target membership passed, block on an unavailable LOV/account lookup, reject duplicate users/sources/categories as a local business rule, or normalize their identity |
| Empty/malformed username assignments | Keep the latest required-input gate: each rule needs at least one nonblank string. Continue all other independent findings and block candidate ZIP | Indexed user_assignments path and the missing/non-string/blank value | Treat a required raw username as an optional target-membership issue or invent a user |
| Override package member/header/link/flag/row shape is inconsistent | Classify artifact persistence for a write failure or catalog mismatch/input validation for contract/mapping defects; retain independent group findings and block ZIP | Contract identity, exact member/column/link, expected versus actual shape, and correction | Synthesize missing schema, modify metadata XML, leak the model single-space category marker into CSV, or alter other rule groups |
| Allow Overrides Y but no Override rules requested | Record a warning only; leave Override group not_applicable and preserve header defaults/template members | Parent identity, enablement, and no-rule warning | Fail solely for absent rules or generate a default rule |
| Fusion import rejects a deferred raw value or outcome is uncertain | Use existing Data Loader diagnostics; persist returned status/ProcessLog, IDs and partial outcomes; corrected package requires the authoritative approval workflow | Environment, request/process IDs, last status, redacted error, immutable artifact reference, and next action | Retry a live write/import automatically, silently correct values, or represent a partial/unknown import as success |

The Confluence source analysis is not deployed-runtime evidence. Explicit user decisions override its source/category/user business validation; see ora_input_validation.md. Preview and approval still govern the reviewed immutable package through the existing Core Data Loader workflow; configuring rules grants no authority to request or apply a transaction override.

# Manage Control Budgets Dependency Readiness

Every requested Control Budget header, budget segments, and assigned trees form the first request-wide dependency phase. Resolve every independent dependency across budgets and collect its failures; mark only checks whose prerequisites are missing `not_evaluated`. Every budget must pass the Control Budget gate before Supplemental, Revenue, or Override dependencies or lookups begin. Then resolve each requested group's dependencies independently: Supplemental headers and three filter sections; Revenue headers, funding targets and source segments; and Override headers, transaction types, journal selection structure, and raw user assignments. Retain all three groups' findings even if another fails; only the final package gate decides readiness. Preserve the existing required lookup sources and import-deferred checks.

## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---:|---|---|
| 1 | Request definition | Validate header and segment inputs. Tree-version rows are optional; validate every row supplied for a tree assignment. |
| 2 | Same-task template export | Export the Manage Control Budgets CSV template/spec package. Do not require a ledger-scoped data export. |
| 3 | Source budget system lookup | Resolve the supplied display value to one XCC_CB_SRC_BUDGET_SYSTEM LookupCode. |
| 4 | Summary master/detail baseline | For a Summary Control Budget, match the named master/detail header and its segment set from a current same-task data export, or the preceding master/detail rows in the same immutable archive when the user explicitly requests an atomic archive. Make this candidate baseline available for currency resolution; do not wait for the currency-dependent rate check to complete before resolving currency. |
| 5 | Summary funds release timeframe | For a Summary, default an omitted value to `RELEASE_IMMEDIATELY`; resolve a supplied display value to one `ORA_XCC_CB_FUNDS_REL_TIMEFRAME` LookupCode. A Master/Detail always uses the literal default and does not run this lookup. |
| 6 | Currency resolution | Complete resolve_currency_code for Detail currency input and any supplied Summary currency input after baseline resolution; validate the returned code and Summary consistency. With inherited-only Summary currency, retain baseline evidence instead of requesting a name. |
| 7 | Default Rate Type input contract | After final currency and applicable Summary baseline resolution, apply the Default Rate Type contract in ora_input_validation.md before defaults or package generation. Keep applicability pending until those inputs are resolved; do not defer a missing required rate to import. |
| 8 | UOM resolution or inheritance | For Detail/Master final STAT currency, complete resolve_unit_of_measure_code. For Summary, validate and inherit Master UnitOfMeasure through resolve_master_control_budget_baseline without another live UOM lookup. A required unresolved Master result blocks readiness, not initial Summary intake. |
| 9 | Selected tree code | Only when a segment has a selected tree, use its exact matched current-target COA row to resolve the technical `treeCode`. Stop on no match, ambiguity, or a blank code. No selected tree requires no tree lookup. |
| 10 | Control Budget gate | Require every requested budget's header, budget segments, and assigned-tree checks to pass. Report every independent failure and dependent `not_evaluated` check across budgets in one result. Stop before Supplemental, Revenue, and Override group resolution on failure. |
| 11 | Supplemental Rule contract | Only after the Control Budget gate passes and only when rules are requested, verify the three same-task CSV members and resolve each rule control level. Derive one `BUDGET_GL_COA_SEGMENT` / `SEGMENT_VALUE<i>` condition per parent budget segment in header order; copy locally valid user-supplied specific segment values without target-membership lookup. For selected Additional Segment Filters, resolve the effective ledger COA, exclude parent budget segments, derive `GL_COA_SEGMENT` / matched `segmentColumnName`, and resolve selected trees against that same COA segment. Discover all Transaction Attribute types from `XCC_TRX_ATTRIBUTE_FILTER_CODES`, default omitted values to All, and resolve every supplied Specific value through its type-specific source. For `NATURAL_ACCOUNT_TYPE` Specific values, use the current-target BOSS `lookupLists` response filtered by `lookupType='ACCOUNT TYPE'` and `lookupCategoryId=101`, and require a unique match with nonblank `lookupCode`. Resolve remaining condition codes from applicable evidence. Keep display selectors pending through CB.SUPP.RESOLVE; report unresolved mappings at CB.SUPP.LOOKUP. |
| 12 | Supplemental Rule relationships | Validate all rules' header → condition → detail parent keys, complete inherited segment and discovered Transaction Attribute coverage and order, and the all-values versus selected-values row shape. Default omitted segment and Transaction Attribute values to All with no Detail rows. Retain all independent failures without suppressing the Revenue group; the final package gate blocks generation on any failure. Do not add rule data rows when none were requested. |
| 13 | Revenue Funding Rule group | After the budget gate, resolve every requested Revenue rule's dependencies under Revenue Funding Rule Dependencies below, regardless of Supplemental findings. No Revenue dependencies are required when no Revenue rules were requested. |
| 14 | Override Rule group | After the budget gate, resolve every requested Override rule's dependencies under Override Rule Dependencies below, regardless of Supplemental or Revenue findings. No Override lookups or rows are required when no Override Rules were requested. |
| 15 | Package shape and final gate | Require complete outcomes from all three requested groups and the budget gate before generation. Verify required CSV and metadata XML members, columns, header order, local defaults, resolved codes and all applicable rule rows. Any required failure or unresolved evidence blocks the package. |
| 16 | Import-time target validation | Validate existing-object state, ledger, chart of accounts, periods, manager, segments, value sets, optional tree versions, and remaining rule references during the Data Loader/Fusion import step. |
| 17 | Readiness and approval | Produce an import-readiness record and obtain approval before a live import. |

## Dependency Classification

| Result Category | When Used | Can Run Lookup/Create? |
|---|---|---|
| Satisfied | All required evidence is exact and complete | Lookup yes; create only after approval |
| Technical lookup gap | Required metadata, code, identifier, member, or column is unknown | Lookup yes; create no |
| Business decision | Existing definition differs, or a control/tolerance/override choice or required Default Rate Type input is unresolved | Lookup no; create no |
| Approval blocker | A live import lacks approval bound to its reviewed immutable package | Lookup yes; create no |
| Reference-backed | A configured cross-instance reference baseline supplies package or setup evidence | Other lookups optional; applicable currency, supplied Summary Funds Release Timeframe, Detail/Master STAT UOM, Detail/Master source-segment-column, and selected-tree-code lookups remain mandatory. Summary UOM and source segments use linked-Master inheritance evidence, not another live lookup; create only after approval |

## Revenue Funding Rule Dependencies

The Revenue group depends on the Control Budget gate only. Run it even when the independent Supplemental group has findings. A request without Revenue rules does not resolve Revenue dependencies or change existing defaults.

| Dependency ID | Dependency | Mandatory | Applies When | Status | Value Source | Resolver | Why | User Guidance | Values to Fill |
|---|---|---|---|---|---|---|---|---|---|
| CB.REVENUE_LIMIT_TYPES | Maximum and minimum type codes | Conditional | Revenue rules requested after budget gate | Lookup | Current target ORA_XCC_REVENUE_LIMIT_TYPE | resolve_revenue_limit_type_code | Both explicit choices must map to exact returned codes | Supply both choices; block unresolved lookup or both estimates | Supplied choices, matched meanings/codes, sanitized source/time evidence |
| CB.REVENUE_SOURCE_COA | Revenue-source ledger and complete COA | Conditional | Revenue rules requested | Lookup | Existing declared ledger/COA and BOSS detail resolutions on the selected Revenue source | resolve_revenue_source_coa | Source may differ from parent; source conditions cover this full COA | Supply source ledger; retain all exact source segment columns and authoritative sequenceNumber values through the existing resolver; satisfy the Revenue-source COA metadata input check before mapping | Source ledger/COA identity, complete source segment metadata including sequenceNumber, and Condition/Detail mapping in the design-required order |
| CB.REVENUE_SOURCE_ROLES | Primary Balancing and Natural Account roles | Conditional | Revenue rules requested | Verify | segmentLabels and segmentColumnName from the current selected-source COA BOSS detail response already obtained by resolve_revenue_source_coa | resolve_revenue_source_segment_roles | Both roles must be Specific independent of display names | Use exact returned label tokens; no separate metadata join or export. | CB.REVENUE_PACKAGE | Revenue rule package contract | Conditional | Revenue rules requested | Verify | Current same-task template or configured approved same-task reference contract | resolve_revenue_rule_package_contract | No guessed members, headers, technical mappings, or parent keys | Require all three Revenue members and local required-input checks | Header/condition/detail contract, normalized inputs, mapped rows, local checks and explicit target deferrals |

Scenario names and entered source/target values undergo presence and local shape checks before ZIP generation. Their existence and target membership remain import-deferred; no value-membership or scenario LOV is introduced. Do not add a budget-flexfield assignment, processing type, currency comparison, or live setup mutation as a Revenue prerequisite. Header AllowRevenueFundingFlag defaults remain unchanged: a requested Revenue rule cannot silently enable its parent.

## Override Rule Dependencies

The Override group depends on the Control Budget gate only; Supplemental and Revenue success are not prerequisites. Resolve independent type/catalog and package dependencies at CB.OVR.LOOKUP even when local rule findings already exist. Do not require any Override rule merely because parent Allow Overrides is Y; record that situation as a warning and preserve existing header defaults.

The Override path selects no journal source/category LOV, worker/user-account lookup, existing-user export, or duplicate-user business query. Those are not missing dependencies. Preserve user strings, including duplicate assignments, in candidate rows after local required-input and CSV checks. Import diagnostics own the corresponding target acceptance. No external mutation or alternative integration is authorized by these dependency rows.

# Manage Ledger Sets Reference Lookups

Live calls use core.fusion-api.rest-api-client only when the active FSCR workflow selects them. These are GET contracts. No ledger-set write endpoint has been established; writes belong to core.data-loader's FSM route. Fusion UI access is prohibited for every lookup, check, task operation and verification. Missing endpoint/export facts do not permit browser inspection, an invented endpoint or ad hoc SQL.

## Lookup Execution Rules

For FSM create, resolve_ledger_set_create_profile uses the packaged authoring contract, not a profile from another project or controlled import. Record field dispositions and current template compatibility. This establishes FSCR preparation readiness, not Oracle acceptance or automatic defaults. A simple create derives direct/effective membership from the request and resolved leaf ledgers; existing-set evidence is needed only for nested members or affected update/review facts. No runtime step requires searching previous runs.

The standard duplicate policy is a fresh negative precheck through the declared GETs. Record no_conflict_observed, queried scope and visibility limitations; do not invent a certificate of global uniqueness. Known conflicts, restrictions, failed reads and incomplete paging remain blockers. If the user or project explicitly requires globally complete evidence, obtain that stricter scope through a declared FSCR endpoint/export or an already configured and declared report adapter; otherwise report missing_framework_evidence. UI evidence is never a fallback. Do not assume an import is create-only or that a unique database index prevents an FSM upsert: a known matching Name always stops creation, and an uncertain prior import must be reconciled before a retry.

The short-name query and its 20-character contract are documented by [dataAccessSetLedgersLOV](https://docs.oracle.com/en/cloud/saas/financials/26c/farfa/op-dataaccesssetledgerslov-get.html).

The direct reference contracts are documented by [chartOfAccountsLOV](https://docs.oracle.com/en/cloud/saas/financials/26b/farfa/op-chartofaccountslov-get.html) and [accountingCalendarsLOV](https://docs.oracle.com/en/cloud/saas/financials/26c/farfa/op-accountingcalendarslov-get.html). Verify the current target contract before use when a linked documentation release differs.

| Situation | What Happens |
|---|---|
| Query construction | Escape embedded quotes for Oracle q syntax and URL-encode query values through the core client; never concatenate raw labels into a URL. |
| Template record layout | Read actual CSV headers and metadata-declared XML types. Do not assume a second CSV type row, a fixed column count or a fixed metadata sequence from a previous package. A one-header CSV must retain its first data row; parse logical records with a CSV library. |
| Pagination | Follow hasMore/offset or documented next links to completion before zero/one decisions; report incomplete paging as transport/environment failure. |
| Lookup visibility | Preserve the returned visibility scope. Complete paging is required but is not proof of tenant-wide visibility. A failed/auth-rejected query is never a zero match. Known restrictions that invalidate the selected setup check require access correction. |
| Namespace without a full task export | Run both exact-name sources and the independent exact-short-name source under the standard negative-precheck policy. Fresh successful zero results permit preparation with scope disclosure. Additional facts for a specific conflict/restriction or explicitly requested stricter coverage must use declared FSCR endpoint/export/report contracts; no UI source. |
| Structural fields without a full ledger-set export | Acquire the resolved primary ledger's scoped Manage Primary Ledgers export, then run resolve_ledger_set_structural_profile. Packaged rules supply ledger-set initialization. A separate COA export is conditional on a named required structural gap, not ordinary creation. |
| Import reference values | Resolve member identity first, then selected COA/calendar and any required balancing column through the declared GETs. Do not require an existing ledger-set export for fields these endpoints return. Keep absent management/value-set metadata and internal create initialization separate; these LOVs do not expose every FSM column or prove importer defaults. |
| Nested members | Direct normalized assignments differ from flattened assignments. Expand the proposed final graph, merging the requested delta with the fresh current graph; detect self-reference and back-edges using the active recursion path. De-duplicate effective leaves by stable ledger identity without discarding direct L/S relationships. A shared descendant reached by two valid paths is not itself a cycle. |
| Data-access duplicates | Different AccessSetId rows can represent the same LedgerId. Do not misclassify these as distinct ledgers; conflicting object facts still block. |
| Omitted COA versus omitted calendar | The declared COA resolver accepts the common member COA ID when no chart label is supplied. The current calendar resolver accepts an exact selected display name only; ask for that missing selection. Do not add an internal-name query or equate internal/display names without a declared, qualified contract. |
| Unavailable write endpoint | Do not POST/PATCH a LOV or table. Execute changes only through core.data-loader with the FSM task package. |
| 401/403 on permitted read | Refresh a cache-managed token once through core auth if allowed, then retry the identical GET once; otherwise stop with auth/authz. |
| Transient GET failure | At most two further identical idempotent-read attempts with bounded backoff; no lookup fallback that bypasses the active workflow. |

## Structural Field Extraction

Match the resolved primary Name exactly in GL_PRIMARY_LEDGER.csv and its GL_SECONDARY_LEDGER.csv alias, requiring one logical PRIMARY row with consistent common fields. Validate actual headers and XML types. Retain the primary LedgerId/scope receipt separately; neither alias name nor a display label supplies an internal ID.

| Fields | Handling |
|---|---|
| StructureInstanceCode, PeriodSetName, UserPeriodSetName | Cross-check scoped values against the declared selected COA/calendar lookup results and effective-member tuple. Use the lookup-resolved keys; any nonblank source disagreement blocks. |
| BalSegColumnName, BalSegValueSetCode | Extract the nonblank pair from the exact selected PRIMARY row. Require selected-COA agreement and compare the physical column with any current member lookup values. When the lookup completed successfully with no match, use the validated ledger-scoped export pair and record that the lookup cross-check was unavailable. Preserve exact value-set code; no fixed SEGMENT1 or value-set guess. A missing required balancing value is a named gap for conditional metadata acquisition. |
| MgtSegColumnName, MgtSegValueSetCode | Use a coherent nonblank pair only when current evidence establishes that it describes the selected chart's management role. A primary's default management column alone does not prove a GL_MANAGEMENT assignment. Otherwise apply the base profile's explicit blank policy; retain uncertainty without asserting that no management role exists. If current contract/request requires the role or pair, acquire conditional COA role metadata. |
| BalSegDescription, MgtSegDescription | Apply the packaged display-descriptor omission policy; a value-set code or segment name is not an established description mapping. No extra export merely to replace optional blank descriptors. |
| All other source fields | Do not copy. User inputs own business choices; MLS_FSM_CREATE_V1 owns ledger-set initialization. Primary category/type, CurrencyCode, FirstLedgerPeriodName, flags, segment value options, future periods, identities, account combinations and audit fields are not ledger-set defaults. |

Record each field's source or explicit omission and any unresolved required value. The normal route needs no separate COA export when this extraction, declared lookups and packaged rules cover the current create contract. Export success does not establish Oracle import acceptance or prove omitted fields default individually.

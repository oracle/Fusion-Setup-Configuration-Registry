## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| A value came from an Oracle UI LOV | Treat the FDoS input as untrusted free text until the exact resolver or authoritative same-release UI or scoped-export evidence validates it. |
| Source ledger is a primary ledger | Resolve its exact numeric LedgerId before export acquisition and use that identifier, as a string, as the PRIMARY_LEDGER_ID AttributeValue; never send the ledger Name. |
| Scoped export request is ready for serialization | Construct the root in the exact insertion order TaskCode, SetupTaskCSVExportCriteria, SetupTaskCSVExportProcess and inspect the serialized JSON before POST. The generic REST client preserves caller order for both body modes; do not apply generic key sorting or send a process-first object. |
| Scoped export create succeeds | Retain its one ProcessId and hand only that ID to shared.setup-export.fsm-csv-export for polling and download; do not submit another create request in the same run. |
| Downloaded export has the process-first three-member signature | Reject a package containing only ORA_GL_PRIMARY_LEDGER_CONFIG.csv, GL_PRIMARY_LEDGER.csv, and ASM_SETUP_CSV_METADATA.xml as broad or incomplete evidence. Preserve the request order and ProcessId for diagnosis, and obtain explicit approval before any fresh criteria-first POST. |
| First Opened Period is omitted | This is valid for Journal or Subledger. Extract the source FirstLedgerPeriodName and its PeriodSetName and AccountedPeriodType from the exact scoped physical row, then run resolve_first_opened_period and show the derived value and evidence in preview. |
| accountingPeriodsLOV field mapping | Filter by PeriodSetNameId and PeriodType, match exported FirstLedgerPeriodName to PeriodNameId, retain EnteredPeriodName as display evidence, and extract only fields actually returned. Do not query nonexistent PeriodSetName or PeriodName response attributes and do not claim the endpoint returned period status. |
| Exact scoped export and live lookup disagree | Classify catalog mismatch, disclose both sanitized identities, and stop; never prefer whichever value is convenient. |
| No eligible match | Return the original input, resolver, filters, and eligibility reason; do not convert it to a default. |
| More than one eligible match | Return candidate business keys and request a more precise identifier; never select the first row. |
| Result paging applies | For resolve_rounding_account, stop at the first exact full-vector account match and validate its flags; complete paging only to establish no match. Other resolvers retain complete pagination before concluding zero or one match. |
| 401 or 403 on an authorized read | Refresh an existing cached token once when the active workflow permits, retry the identical GET once, then classify auth or authz and stop. |
| 429, timeout, or recoverable 5xx GET | Use bounded backoff only for the idempotent read; after the bound classify transport or Fusion API failure. |
| Endpoint access is forbidden but the current task UI or same-release scoped export contains the exact LOV pair | Record the evidence type and release and accept only the exact exported or displayed key and value; do not generalize to another value. |
| A historical package or chronology file is consulted | Use it only to establish a proven UI behavior or experiment shape; the current same-release package and 2026-08-27 closure govern conflicts. |
| Same currency is returned | Mark it eligible, show the design advisory, and require the user to confirm the intended business value. |
| Lookup fails | Do not write files, authorize an import, or report not found unless the server returned a valid complete zero-match result. |

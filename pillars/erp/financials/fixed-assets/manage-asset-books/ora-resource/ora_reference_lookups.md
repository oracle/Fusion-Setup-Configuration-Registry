## Lookup Execution Rules

New-book `Book Control ID` is resolved at import runtime per `ora_defaulting_rules.md`. Do not require a pre-creation ID lookup or block because a new-book row is blank. Resolve existing identity through supported read-only lookup for updates, and verify new identities after import. Do not inspect exported rows for IDs.

| Situation | What Happens |
|---|---|
| Fresh FSM template/spec export is available | Read only its CSV member names, headers, and structural metadata as the import contract; do not inspect data rows or use them to generate defaults or a ZIP. |
| User explicitly requests existing-book verification by setup-data export, or approves it after the BOSS route is unavailable | Use one `shared.setup-export.task-level-export --data` export for exact requested Asset Book Code matching only. Retain sanitized match/no-match evidence; do not expose, copy, or derive from unrelated rows. |
| A documented read-only Fusion metadata endpoint is available in the target environment | It may supplement export evidence; retain request, match, and result evidence in the readiness record. |
| Ledger account derivation is required | Query `ledgersLOV` for the COA, `chartOfAccountsLOV` for its structure, and `accountCombinationsLOV/describe` for segment metadata. Find `GL_ACCOUNT`, resolve its value set, and use the returned code-keyed child-values link. Page the entire value set until `hasMore` is false before concluding zero, one, or multiple matches. Select exactly one enabled/effective/non-summary Natural Account by case-insensitive word-order-independent tokens: NBV Gain/Loss = field `Gain`/`Loss` + `NBV`/`Net Book Value` + `Retirement`/`Retired`; Proceeds Gain/Loss = field `Gain`/`Loss` + `Proceeds` + `Sale`; Proceeds Clearing = `Proceeds` + `Sale` + `Clearing`; Cost Removal Gain/Loss = field `Gain`/`Loss` + `Cost` + `Removal`; Deferred Expense/Reserve = field `Expense`/`Reserve` + `Deferred` + `Depreciation`. Do not use an existing book as a source for any account field. For a ledger-derived book account, the uniquely matched valid Natural Account is sufficient; do not construct a full account combination. Account Defaults follows its separate supplied-input or omitted-value derivation rule below. |
| Account Defaults is supplied | Preserve the supplied value exactly. Check only required input and the selected COA segment format/serialization using structural metadata. Do not query accountCombinationsLOV for the supplied full combination or require its existence, combination-level enabled/effective/posting/summary validation, a dynamic-creation flag, or a waiver. Do not request replacements or prerequisite combination creation solely because the full combination is absent. Record it as customer-supplied, not target-validated; Fusion may still reject it during import. When omitted, retain the existing selected-ledger derivation of one valid complete Account Defaults combination. |
| An Account Defaults input contains a visible placeholder | Replace only the placeholder with the value explicitly visible in the current inputs, such as a displayed Primary BSV value. Preserve the resulting combination and apply the supplied Account Defaults rule above. |
| Other book-level account mappings | Derive every required retirement, proceeds, cost-of-removal, and deferred-depreciation account from the selected ledger's COA and Natural Account value set. When the user supplies a mapping, validate its Natural Account in the selected ledger; otherwise apply the uniquely resolved ledger-derived Natural Account without requesting a separate user confirmation. Request an accounting-policy mapping only for an unresolved or unsuitable fallback. |
| User overrides a derived book-level account proposal | For supplied Account Defaults, apply the supplied-input rule above without a complete-combination search or existence blocker. For any other book-level account, resolve it only through the selected ledger's Natural Account value set; require enabled, effective, non-summary evidence and retain the user's stated purpose. Do not reject a valid override merely because it does not match the automatic description tokens. |
| No documented source resolves a required value | Record the field and source gap as unresolved; do not generate a package or submit an import. |

## Evidence Fallback for Dependency Readiness

When a BOSS API request fails, route to the equivalent task-level **template/spec export** for the active task. Poll an existing same-target template export before starting another one. Use it only for CSV member names, headers, and structural metadata. If the user explicitly requests existing-book verification through export data or explicitly approves it, start one task-level `--data` export after the template/spec contract is available. Its sole permitted use is exact requested Asset Book Code matching.

| BOSS lookup outcome | Required fallback | Evidence to persist | Resulting readiness state |
|---|---|---|---|
| Transport failure, HTTP 404, unsupported resource, or incompatible BOSS response | Use `shared.setup-export.task-level-export` for the active task without `--data`; do not retry an invented or alternate BOSS path. If the user explicitly requests existing-book verification through export data or separately approves it, create one `--data` export after the template/spec result is available. | **Internal only:** sanitized BOSS diagnostic, template-export ProcessId, ZIP path, member names, header bytes, metadata-inspection summary, and, when authorized, exact-match-only data-export evidence. | Continue import-contract validation. Keep the existence dependency unresolved unless the authorized data export returns a complete exact-match/no-match classification. |
| A current same-target template export is already available | Poll or inspect that export rather than creating a duplicate export process. | Existing ProcessId and refreshed structural-inspection summary. | Continue import-contract validation; keep the affected lookup dependency unresolved. |
| Template export fails, times out, or has incomplete structural metadata | Do not create a package or start an import. | Process status/log, elapsed wait, and missing structural evidence. | Blocked. |

The template/spec export is an equivalent **structural-contract** fallback, not
evidence that a requested book is absent, identical, or different. Retain the
book-existence dependency as blocked after a template/spec export unless the
documented BOSS route returns a complete result or the user-authorized data
export provides a complete exact-match/no-match classification. Do not infer
absence from a template, generate a book CSV row, or use data-export rows for
any purpose beyond the permitted existence classification.

## User-Facing Failure Suppression

Treat a BOSS failure as an internal routing event, not a user-facing workflow
failure. Persist the sanitized diagnostic in the project workspace, invoke the
required template/spec fallback automatically, and report only the resulting
business outcome:

- When the fallback supplies the required structural evidence, report that the
  import contract was validated; do not mention BOSS, an endpoint, HTTP status,
  or the diagnostic path.
- When a dependency remains unresolved after all approved fallbacks, report the
  concise business blocker (for example, `target asset-book existence evidence
  is incomplete`) and the required next action. Do not expose the internal
  endpoint failure, HTTP status, trace data, raw response, or implementation
  route.
- Never surface an internal BOSS diagnostic in a user-facing preview, Run Book
  dashboard, final readiness summary, or package-approval request unless the
  user explicitly asks for diagnostics.

Use only user input, approved policy, supported read-only lookups, or structural metadata. If a required dependency still cannot be resolved, block the package.

## Asset Book Reference Validation Preview

Before package preparation, render a business-only `Reference Validation
Preview` covering existing book state, ledger, depreciation calendar,
fiscal-year/current-period basis, required accounts, reference data sets,
tax/corporate relationship, and the current import contract. Any unresolved
required dependency blocks package preparation. Keep `BookControlId`, internal
identifiers, raw account combinations, endpoint details, metadata fields, and
other values marked `Internal: Yes` out of the customer-facing preview.

Render the selected depreciation calendar, selected fiscal year, and current
depreciation period. Keep Initial Date and its preceding-period derivation
internal; do not show either in previews.

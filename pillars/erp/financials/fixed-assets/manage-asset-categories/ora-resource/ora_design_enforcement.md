# Design Enforcement

## Enforcement Rules

| Rule | Applies when | Enforcement |
|---|---|---|
| Require System Controls | Customer requests a category create, check, update, or assignment. | Resolve `CatStructureInstanceCode` from current target System Controls, then match it to one enabled CAT# instance in the current Key Flexfields export before category-component validation or package preparation. |
| Keep category combinations within Manage Asset Categories | Customer requests a category create, check, update, or assignment. | Author this task's category combination only after its prerequisites pass. Missing or disabled CAT# values require their own approved prerequisite action before category authoring resumes. Do not use another enabled CAT# instance. |
| Map category components before package authoring | Package authoring needs category components. | Require the validated component-to-KFF-segment mapping for the System Controls-selected CAT# instance. Derive package positions from that mapping; do not ask the customer for technical KFF identifiers or positions. |
| Reject duplicate data rows | Package preview is built. | Require unique business keys for category, category-book, default-rule date range, and translation language rows. Conflicting duplicates block preview until the customer identifies the authoritative row. |
| Hold cross-structure category collisions | Category-header creation is requested. | Require complete candidate evidence across structures for the exact ordered category components. An identical combination in another structure blocks create readiness under the conservative workflow policy; do not reinterpret selected-structure absence as permission to create. Keep the conflicting category separate and do not assign its identity to the requested structure. |
| Validate an explicitly reduced retry scope | The customer requests remaining categories after a failure. | Reconcile fresh target state first. Exclude held headers and all corresponding book/default rows together, retain every included parent, and disclose included and held combinations in the full business review. Run all task validation stages for the subset and require a new Data Loader preview and approval. Do not infer committed rows from per-row error counts. |
| Require category parent rows | A package contains a category-book or category-book-default row. | Include exactly one matching `FA_ASSET_CATEGORY` parent row in the same ZIP before every child row is submitted. For a requested category create, serialize the parent as the validated category-header create row. Do not generate child-only packages. For an existing category, use only the parent identity/action form confirmed by the current target export. |
| Validate category package hierarchy | Before ZIP-creation approval for proposed rows; after approved ZIP creation, before Final ZIP Preview and immediately before Data Loader handoff. | Validate proposed parent/child rows before creation approval, then apply the same checks to the actual immutable ZIP after approved creation. Reject a missing parent, mismatched parent/child linkage, parent action conflicting with the requested category scope, or duplicate parent. Regenerate the immutable preview and require fresh approval after correction. |
| Preview accepted header values | Before ZIP-creation approval. | Show every nonblank category header value. Present Category Type and Ownership with the documented UI wording; present Capitalized and Enabled as Yes or No. Retain paired stored values in package evidence. For lookup-backed fields, show both the accepted stored value and display label; do not omit supplied or defaulted Description, Property Type, or Property Class. |
| Select preview mode by quantity | Before ZIP-creation or import approval. | Count distinct requested category combinations after duplicate checks. For every quantity, render the complete **Detailed** preview inline: each applicable category header, book assignment, every populated account role/complete combination, and every populated default-rule value/reference set. For 6–25 categories, also show a **Summary** with scope count, one row per category with book/method/life/conventions/start date, account-role exceptions, and validation status. For more than 25 categories, also show an **Aggregate** with total counts by action/book/default profile, all exceptions or blockers, and validation status. Summaries and linked detailed artifacts are supplementary; they never replace or shorten the complete inline preview required by the parent. Approval covers every row and the exact immutable package. |
| Keep book assignment explicit | A category-book row is created, updated, or removed. | Require one exact asset book and an explicit action. Use removal only when the customer explicitly requests it. |
| Resolve assignment category first | A category-book row is created, updated, removed, or preserved. | Resolve exactly one existing category from the supplied category identifier before validating the book row. The category-book action does not authorize creation or alteration of category-header fields. |
| Derive ledger account combinations by default | A category-book role has no complete customer account selection. | Automatically run `resolve_category_book_accounts` for the role. Derive only from the selected book's ledger, COA, Natural Account values, and selected-book account skeleton; never reuse another category or category-book mapping. Accept the result when exactly one role-specific segment vector with resolved Natural Account and valid COA format resolves. |
| Apply conditional account-role rules | Category-book account derivation is performed. | Set blank Bonus Depreciation Expense and Bonus Depreciation Reserve respectively to their validated depreciation counterparts, then validate the copied roles. Derive CIP Cost, CIP Clearing, and Unplanned Depreciation Expense from the selected book ledger. Derive impairment and revaluation roles only when their respective book features are enabled; derive lease roles only when Category Type is `LEASE`. |
| Handle non-unique ledger results | Natural Account derivation returns no suitable value or multiple candidates, or the selected-book skeleton is unresolved. | Ask only for the missing account selection or skeleton decision. Do not search full combinations or block because the assembled combination does not exist. Do not use a donor category to resolve ambiguity. |
| Show complete account review before readiness | Account derivation is attempted, including a blocked lookup or dependency. | Require the Account Review Disclosure in ora_error_handling.md for every required or supplied account role. Preserve resolved results and disclose unresolved ones; a blocked review is not an executable package preview or approval request. |
| Block unresolved account assignments | A required or supplied role lacks a complete supplied or uniquely derived segment vector, or fails format/serialization checks. | Apply Category-Book Account Preparation in ora_reference_lookups.md without full-combination existence verification. Preserve optional-field omission decisions and never write unresolved status text into account cells. |
| Enforce category-book account serialization | Before ZIP-creation approval using proposed data; after approved ZIP creation, before Final ZIP Preview and immediately before Data Loader handoff. | Run validate_category_book_account_serialization for every populated account field using its stage-specific source and Category-Book Account Format in ora_reference_lookups.md. A proposed-data failure blocks ZIP-creation approval; an actual-ZIP failure blocks Final ZIP Preview and handoff. Preserve all value, blank-position, multiline-quoting, terminator, and CSV field-count checks. |
| Enforce default depreciation expense combination | Before ZIP-creation approval and immediately before Data Loader handoff. | When populated, `DefaultExpenseCcidFlag` must be exactly `Y` or `N`. Map the customer-facing value Yes/No before serialization. Never serialize `YES`, `NO`, selected, or cleared. |
| Require impairment accounts when enabled | The assigned book has `AllowImpairmentFlag` enabled. | Require complete Impairment Expense and Impairment Reserve vectors under Category-Book Account Preparation in every category-book mapping. Block preview, package generation, and import when either is absent or unresolved. |
| Keep default rows date-scoped | A category-book default row is authored. | Prevent overlapping effective-date ranges for the same category and book. |
| Require Use Straight-Line Retirements in ZIP rows | A category-book default row is prepared for a ZIP. | Require a nonblank `UseStlRetirementsFlag` value of `YES` or `NO`. Block ZIP creation when the field is blank or invalid; do not serialize a blank default-rule value. |
| Block incompatible default-rule reference sets | A category-book default row is authored. | Accept any valid Common Set method or convention without reference to book assignments. For a non-Common method, require the book's `FA_DEPRECIATION_METHODS` (Depreciation Methods) set; for a non-Common prorate or retirement convention, require `FA_PRORATE_CONVENTIONS` (Prorate Conventions). Do not compare a method with the Prorate Conventions set or a convention with the Depreciation Methods set; do not replace a supplied value with another value. |
| Reuse populated export formatting | A package includes a category-book or default-rule row. | Use the current task export only to preserve quoting, date format, yes/no values, and optional-field representation. A same-book donor may provide formatting evidence only; it must not supply depreciation defaults, account values, account segments, or an account skeleton. Header-only template shape is insufficient. |

## Ownership Boundary

This file owns package integrity, preview-mode selection and completeness, selected-ledger account
derivation and account-preparation gates, explicit package actions, and donor formatting limits. CAT# and value readiness belong to
`ora_dependency_readiness.md`; input and field validation belong to
`ora_input_validation.md`; lookup and account-resolution mechanics belong to
`ora_reference_lookups.md`; and default values and optional-field behavior
belong to `ora_defaulting_rules.md`.

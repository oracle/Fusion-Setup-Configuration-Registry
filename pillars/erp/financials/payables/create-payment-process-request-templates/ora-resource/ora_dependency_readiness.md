# Dependency Readiness

Apply the field mappings and resolver rules in [Reference Lookups](ora_reference_lookups.md).

This resource evaluates prerequisite status for the supplied candidate; it does not invoke setup creation, imports or arbitrary reference APIs. Named resolver definitions live only in Reference Lookups. The [acceptable-input policy](../references/acceptable-input-values.md) takes precedence: direct-user-input fields are not reference-verification dependencies, and one or more matching REST rows satisfy a supported REST check. Only applicable rows affect a candidate. A Blocked evidence-only business-field row may become an explicitly accepted application-validation dependency for an eligible UPDATE; proof closure is not the only path. Record exact field/candidate/operation acceptance and the preview warning without relabeling the contract supported. Keys, audit/target identity, malformed packages, proven-invalid values, source-proven unsupported behavior and mutation authority remain protected.

## Package preparation

Use the task entrypoint, `python3 scripts/fsm_task_adapter.py --help`, from the
skill folder for supported commands. It binds this task's descriptor and
validation rules to the local package primitives. Keep the descriptor's relative
dependencies and `runtimeDependencies` byte bindings intact when packaging the
skill. Task-specific validation bindings must remain isolated from other tasks.

The lower-level primitives require an explicit contract when used unbound; they
do not replace the task adapter's validation or provide an alternate execution
route. A bound runtime must reject a different contract, and a supplied
`--workspace` must constrain every output path. The invoking workflow owns
project selection, output paths, token-usage tracking and rule evaluation.
Package preparation performs no network access, authentication, import,
polling or live retry. The active Run Book and Data Loader retain their preview,
approval and execution gates.

## Dependency Classification

| Result Category | When Used | Can Run Lookup/Create? |
|---|---|---|
| Satisfied | Required package context and literal/fixed source contract have been supplied and evaluated | No additional lookup or master creation is implied |
| Verify | Apply only the declared reference check for a supplied value. A matching REST receipt satisfies that check; partial source evidence does not add another preparation gate. Known mapped fields without a required public preflight use the declared FSM validation authority | Use the selected read or normal approved FSM route. Do not add a helper-revision, setter-order or future-persistence proof request; never create the reference master |
| Blocked | A requested transformation/raw-ID use depends on the exact named unresolved contract and no eligible exact-field UPDATE acceptance has been recorded; identity/lifecycle protection remains nonoverrideable | No substitution or invented ID; close the source gap or offer only the eligible governed application-validation choice |
| Not Applicable | The reference/branch is not used or affected by this candidate | No lookup is required for that unrelated field |

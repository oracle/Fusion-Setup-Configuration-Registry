# Reference Lookups

These contracts document FSM import resolution and fixed package choices. Evaluate only the supplied candidate through the active Run Book; internal import mechanisms are not callable REST endpoints. Public preflights supply supporting evidence and do not replace the authoritative FSM resolver. The [acceptable-input policy](../references/acceptable-input-values.md) controls local validation, including configured-label defaults and direct-user-input exceptions, ahead of import mechanism descriptions below. Transaction Calendar, First Approver/PersonNumber and Funding Card Account import mechanics are documentary: do not turn them into local lookups, pairing checks or companion derivations. Calendar assignment support remains a separate serialization boundary.

## Lookup Operations

For all task REST reference responses, use the
[REST acceptance policy](../references/acceptable-input-values.md): a successful
response with at least one matching row passes, and multiple matching rows are
accepted. Source-level first-row and duplicate behavior below describes Fusion;
it does not impose a REST uniqueness gate. Retain the supplied portable CSV value
and field-bound `restResult` evidence. Unknown import-time membership/enablement
or duplicate handling does not block an otherwise matched reference.

`fields=BusinessUnitName,BusinessUnitId`. For supplied currency members, GET

`finder=CurrencyCodeAllRowsFinder;CurrencyCode=<CSV CurrencyCode>` and

`RES-PPR-ORA_PPR_CURRENCY_GROUP-CURRENCYCODE` as the currency receipt resolver.

apostrophe as two apostrophes in the business-unit filter value. Do not guess
finder escaping for a currency code containing finder delimiters. A successful response with
one or more exact matching rows passes, including duplicate matches. Retain the
supplied CSV value rather than selecting an ID. Follow advancing pages until a
match or confirmed exhaustion. An incomplete response, inaccessible service,
or failed request makes validation unavailable; an exhausted successful
response without a match requires correction. The business-unit LOV does not
establish the FSM resolver's enterprise context or import eligibility. Retain
the authenticated request context and response provenance separately.

## Supplier Type REST fallback

Resolver: resolve_supplier_type_rest. Apply only when a supplied nonblank SupplierType does not match the default names in acceptable-input-values.md. This is the declared secondary read route for Task Hook reference evaluation; all calls use core/fusion-api/rest-api-client/scripts/fusion_rest_client.py and REST-Framework-Version: 9. The offline task adapter does not make network requests.

1. GET /fscmRestApi/resources/11.13.18.05/genericLookups with finder=LookupTypeFinder;LookupType=POZ_VENDOR_TYPE,ViewApplicationId=0, fields=LookupType,ViewApplicationId and onlyData=false. Confirm returned LookupType and integer ViewApplicationId against that context. Use only returned lookupCodes child links from matching parents; do not construct genericLookups_Id from the lookup name or use a parent from another view. Multiple matching parent rows are permitted; do not impose uniqueness.
2. GET the returned lookupCodes child URL with fields=Meaning,LookupCode, q=Meaning='<supplied name>' and onlyData=false. Escape a literal apostrophe as two apostrophes in the ADF q expression and let the Core client URL-encode query parameters. Do not interpolate raw input into a URL or a shell command. Read matching-parent/code pages until an exact Meaning match exists or all applicable filtered pages are exhausted. Missing child links or incomplete/nonadvancing pages are evidence failures.
3. A successful response with at least one exact Meaning match passes; several matching rows also pass. Preserve that exact Meaning in the candidate; never select an arbitrary LookupCode or internal ID. A parent match alone or an unrelated code row does not validate the name. Do not add uniqueness, enabled/date, SetId or import-time eligibility gates after the matching name is found.
4. Attach the receipt described in acceptable-input-values.md with operationId, exact entity/field/resolver, lookupContext, evidence and restResult containing the matching code rows. Keep the current request, environment, observation time and response artifact in the owning project workflow. The offline adapter checks receipt shape and matching contents; it does not prove remote provenance. Do not claim this route ran when only local evidence tests ran.
5. Exhausted successful no-match fails name validation. Authentication, authorization, transport, missing lookup visibility or malformed data are validation-unavailable outcomes. Return the exact cause and next action rather than treating them as invalid names or bypassing the secondary check with an FSM fallback.

The importer resolve_supplier_type mechanism remains the final FSM mapping from Meaning to VendorTypeLookupCode. This secondary API read validates an unlisted input name and does not replace import-time validation or grant submission authority.

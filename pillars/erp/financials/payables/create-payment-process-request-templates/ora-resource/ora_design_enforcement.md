Apply the field mappings and resolver rules in [Reference Lookups](ora_reference_lookups.md).

This file owns pre-execution business-combination and operation-effect checks. It uses supplied candidate/reference results and source rules; it does not perform an import, inspect post-import state, synchronize a Run Book or own execution approval.

Apply the established task contracts to supported create/update preparation.
Internal framework-source availability or a consumed dependency label is not
an additional input gate. Qualify uncertain behavior through applicable source
evidence or controlled import/readback evidence for that exact behavior. This
does not supply a missing CSV mapping, authorize a protected operation, or
establish collection replacement from omitted rows.

## Enforcement Order

| Sequence | Step | What Must Happen |
|---|---|---|
| 10 | Apply input and reference results | Use the owning input/reference/dependency/default outputs without redefining their checks or lookup mechanics. |
| 20 | Evaluate applicable business combinations | Apply the conditional rules below only when their fields/branches are affected. |
| 30 | Disclose known effects and exact gaps | Show related clears and selection-row effects; isolate unresolved field/aggregate semantics. |
| 40 | Return pre-execution result | Forward acceptable create/update candidates to the separate handoff gate; return actionable issues otherwise. |

## Design Rules

| Applies When | Severity | Required Lookup | Blocking Condition | Recommendation | Fix Allowed? |
|---|---|---|---|---|---|
| Any intended operation | Blocker | | Deleting a template, renaming a keyed template, writing referenced masters, or asserting collection replacement/removal without a supported contract | Use bounded root create/update and task-owned membership operations. Root create/update support does not imply arbitrary child synchronization. | No silent operation substitution |
| A child membership is created | Blocker | | The owning root row is absent from the ZIP, or implicit parent context differs from the current baseline | Include one full retained parent row with empty audit cells, unless the reviewed design already supplies an explicit root operation. Show the serialized context in the preview; preserve explicit root changes and do not add unrelated children, defaults or root operations. Import acceptance and preservation still require independent readback | Only exact retained context or the explicit reviewed root operation |
| An update changes group selection | Review effect | | A known ALL setter removes related selected rows but the proposed business effect has not been shown | Show affected selection rows in the candidate comparison. Do not turn setter behavior into omission-based deletion/merge semantics. | Only an explicit reviewed business change |
| OuGroupOption or CurrencyGroupOption is INVOICE/PAYMENT | Blocker | | The corresponding supplied/retained selection group has no child row | Provide the intended BU/currency membership. Error identifiers: AP_PAY_SPECIFY_OPERATING_UNITS, AP_PAY_SPECIFY_PMT_CURRENCIES. | Correct the business selection |
| LeGroupOption or PayGroupOption is SPECIFY | Blocker | | The corresponding selection group has no child row | Provide intended LE/pay-group membership. | Correct the business selection |
| SourceGroupOption is SPECIFY | Blocker | | No source child row is present | Provide intended source membership; do not infer this specific validator for EXCLUDE. | Correct the business selection |
| Both payment priorities are nonnull | Blocker | | HiPaymentPriority (From) is greater than LowPaymentPriority (To) | Require Hi <= Low; keep From/To labels correct. Error identifiers: AP_PAY_ENTER_HIGHER_PRIORITY. | Requester-corrected priorities |
| Every create; update supplying BankAccountName, PaymentDocumentName or PaymentMode | Blocker | | Effective BankAccountName is not selected but PaymentDocumentName is nonempty | User-directed input rule: Payment Document must be blank without a Disbursement Bank Account. Merge supplied and retained values; do not silently clear the document or invent a bank. Unrelated updates preserve retained values | Supply a bank or explicitly clear the document |
| InactiveDate is supplied/changed | Blocker | | The proposed new date is earlier than current date under the current-date rule | Apply newValue >= currentDate. This is retirement by update, not physical delete. Error identifiers: FND_CMN_END_DTE_ERLY_EQ_TDAY. | Requester-corrected date |
| PaymentDateOption is ED | Blocker | | AddlPaymentDays is null | Supply the intended offset. No additional minimum is inferred from an error name. | Requester supplies the required offset |
| PaymentDateOption changes to RD | Review effect | | Clearing AddlPaymentDays by the source setter is hidden from preview | Disclose the known clear; source defaults/side effects are owned by Defaulting Rules. | Explicit reviewed business change |
| Payment conversion type is serialized | Blocker | resolve_payment_conversion_rate_type | Mandatory PaymentExchangeRateType would remain null because the business alias is explicitly blank or unresolved | On create, apply Corporate only when omitted and disclose the declared default in preview. Preserve an explicit nonblank alias; an explicit blank needs correction. On update, preserve omission and never replace an explicit value with Corporate. | Correct only the affected explicit input |
| Method and selected BU/LE are supplied | Authoritative Fusion validation | resolve_payment_method_code | Source IBY method applicability validation fails for the chosen context | Retain source error/context and correct method/criteria; no generic existence API replaces task validation. | Correct the selected combination |
| Profile and method/account/BU/currency are supplied | Authoritative Fusion validation | resolve_payment_profile_name | Source IBY profile applicability validation fails for the chosen combination | Correct the combination; no profile-name uniqueness or arbitrary first-result selection is implied. | Correct the selected combination |
| Printed profile/instruction or explicit payment document is used | Authoritative Fusion validation | resolve_payment_document_name | Required profile/bank/document context or default printed document is absent under the evidenced IBY conditions | Preserve IBY_APSUB_NO_DEFAULT_PMT_DOC / IBY_BUILD_MISS_PMT_DOC_REL_PAR conditions. Do not make the document universally mandatory. | Supply the applicable related context |
| Payment-mode fields are affected | Blocker | | Virtual card has blank FundingCardAccount or PaymentProfileName, or nonempty BankAccountName; blank/nonvirtual mode has nonempty FundingCardAccount | Apply [payment-mode account and profile rules](../references/acceptable-input-values.md#payment-mode-account-and-profile-rules) to the effective template. Retained values count; nonvirtual bank/profile remain optional. Funding contents are taken as-is without verification. An unrelated update does not reopen this combination | Request missing values or an explicit incompatible-account clear; no silent clearing/defaults |
| Resolved PaymentMode branch is selected | Review effect | | Forced CreateInstrsFlag Y or bank clearing would be hidden | Show the documented source effects separately from the structural input check. Funding Card Account uses supplied input directly; no local resolver, eligibility or virtual-card-program check. | Disclose applicable effects in the preview |
| A requested direct field write has an unverified operation contract | Field-scoped decision | | A requested OrgId, TransferPriority or legal-entity display Name update lacks its declared exact-field acceptance | Offer the existing governed UPDATE path with its preview warning, normal Data Loader approval, one submission and fresh readback. A supported mapped field or a passed reference check does not need this exception for unknown internal implementation details. Key/audit mutation, missing mappings and unsupported operations remain excluded. | Apply the decision only to the affected direct write; preserve ordinary supported operations |
| A supplied currency or BU membership has matching REST evidence | Proceed with normal validation | | The declared reference check returned one or more exact matches | Preserve the supplied portable value and field-bound receipt. No uncertainty override, helper-revision proof or separate import-time enablement/duplicate-policy proof is required. Fusion applies remaining configured eligibility. | Continue ordinary candidate preview and approval after other known checks pass |
| A source-proven supported field/combination passes applicable checks | Proceed to governed handoff | | No applicable input, identity, transformation or business-design issue remains | Return candidate-specific results to the invoking Run Book/Data Loader; this pre-execution design node performs no import, monitoring or persisted-state verification | No direct write |

## Design Lookup Requirements

Direct-user-input fields have no local lookup requirement. Funding Card Account
is checked only for presence/availability under the payment-mode rules; its
import resolver is documentary.

| Resolver | When Required | Values Needed | Source File |
|---|---|---|---|
| resolve_payment_conversion_rate_type | A root conversion alias is supplied/retained for import | Applicable resolver result/declared FSM fallback; use Corporate only for an omitted create input under Defaulting Rules; preserve updates and reject an explicit blank | ora_reference_lookups.md |
| resolve_payment_method_code | A selected method/BU/LE combination is evaluated | Applicable task method validation context/outcome | ora_reference_lookups.md |
| resolve_payment_profile_name | A selected profile combination is evaluated | Applicable task profile context/outcome | ora_reference_lookups.md |
| resolve_payment_document_name | Printed instruction/document dependency applies | Source-owned related bank/profile/document context/outcome | ora_reference_lookups.md |

# Dependency Readiness

## Required Dependency Order

| Sequence | Dependency | What Must Happen |
|---|---|---|
| 1 | Invoice business unit | Confirm the request provides BuName. For a create, resolve one active exact BU through `finBusinessUnitsLOV`; resolve EnterpriseId from an explicit requester value, current-run default, or exactly one distinct nonblank value in the fresh FSM export. |
| 2 | Payment terms | Supply all three required term names independently (`TermName`, `PrepaymentTermName`, and `EmployeeTermName`) and allow the documented FSM import hook to resolve their corresponding term IDs. |
| 3 | Terms Date Basis | Supply `Current` (System date), `Goods Received` (Goods received date), `Invoice` (Invoice date), or `Invoice Received` (Invoice received date). The adapter validates it locally; no REST call is made. |
| 4 | Accounting Date Basis | Supply `CURRENT` (System date), `GOODS RECEIVED/CURRENT` (Goods received or system date), `GOODS RECEIVED/INVOICE` (Goods received or invoice date), or `INVOICE` (Invoice date). The adapter validates it locally; no REST call is made. |
| 5 | Pay Date Basis | Supply `PayDateBasisLookupCode` with a supported system code. The adapter validates it locally; no REST call is made. |
| 6 | Budget Date Basis | Supply `BudgetDateBasis`: `ACC` (Accounting date), `INV` (Invoice date), or `SYS` (System date). Fusion validates the submitted code during import. |
| 7 | Controlled page LOVs | Validate currencies and immutable system values with task-owned rules. Preserve submitted Pay Group codes unchanged for Fusion import validation. Validate Account Derivation Method and Accounting Preference against their documented system values. |
| 7a | UI-required create controls | Before candidate generation, require nonblank InvoiceCurrencyCode, PaymentCurrencyCode, PaymentPriority, TermName, and WhenToAccountPmt. The task derives SOBName and BaseCurrencyCode from the exact BU primary ledger and injects only source-proven date-basis defaults. |
| 8 | Interest-invoice setup | When Create Interest Invoices is Y, provide positive InterestToleranceAmount, InterestSegments, and SOBName. Validate the effective ledger and account through the task-owned read-only GL helper before candidate generation; require an existing CCID. |
| 9 | Payment-owned values | For an Invoice Options setup update, merge the request delta with the baseline and validate every resulting Payment-owned AP_SYSTEM_PARAMETER value through the sibling Manage Payment Options field contract. For a new Invoice Options setup row, validate every submitted Payment-owned value without inventing optional Payment values. |

## What These Statuses Mean

| Status | Plain Meaning | What Happens Next |
|---|---|---|
| Verify | A specific receipt, resolved value, or sibling task contract must be present and consistent before candidate generation. | Obtain or correct the required evidence/value. The candidate is blocked until verification succeeds. |
| Local validated | The adapter can deterministically validate the value against a task-owned rule without contacting Fusion. | Correct an invalid value before candidate generation. A valid value can proceed without a read-only lookup receipt. |
| FSM import validated | The submitted value is preserved for Fusion's authoritative import-time validation because this task has no safe local validation for it. | Data Loader can prepare an immutable preview; Fusion validates the value only after the normal import approval. |
| Partial | A supporting read-only preflight records corroborating evidence. A readable zero-result is blocking. Multiple results or an unavailable endpoint are advisory when no CSV value must be derived. | Correct a readable zero-result. Preserve the submitted value with a warning for multiple/unavailable outcomes and let Fusion Import validate it. The create-time BU/ledger derivation remains blocking because it supplies required CSV values. |
| Block preview | The supplied combination is known to be contradictory or unsafe and must not produce a candidate package. | Correct or remove the conflicting values, then validate the revised request. |

## Existing Business Unit Create Path

| Situation | What Must Happen |
|---|---|
| A requested existing business unit has no AP_SYSTEM_PARAMETERS_ALL row | Permit a create operation only after exact BU preflight and deterministic EnterpriseId resolution under the documented precedence. The operation creates the invoice-options row; it must not create or alter the business unit. |
| A matching AP_SYSTEM_PARAMETERS_ALL row already exists | Reject the create operation as a duplicate target and use the separate update operation when the requested change is intended. |

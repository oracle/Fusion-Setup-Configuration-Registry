## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| Root identity | IBY_PAYMENT_SYSTEM.Suffix and Name | Stop affected root | Supply unique system code and name; retain existing Suffix on update | root create or serialized update |  |
| Account identity | ORA_IBY_PAYMENT_SYSTEM_KEY.Key1 and owning system | Stop affected account | Use parent Suffix and account Key1; never use option code globally | account operation |  |
| Setting identity | AccountOptionCode and owning system/account | Stop affected setting | Join definition on owning system and option code before value handling | setting operation |  |
| Definition | AccountOptionCode, AccountOptionDatatype, DisplayOrder, AccountOptionName | Stop definition create | Supply reviewed canonical values; do not infer UI defaults | definition create |  |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Independent operation contracts | Validate only explicitly supported fields for the selected create or update operation. Preserve unsupported versus unresolved distinctions in field-contracts.json. Key retention is not key mutation. | all requests |  |
| Canonical types | Use strict ISO calendar dates for typed date fields; require valid real calendar dates. Preserve exact string types for generic option values. Reject non-scalar identities. | all inputs |  |
| Date ordering | Root EndDate must be greater than or equal to StartDate; format StartDate must be strictly before EndDate. Root no-end sentinel 4712-12-31 is explicit. | typed dates |  |
| Root URL | When nonblank, Baseurl must use http or https and satisfy the source length greater than 10. | Baseurl supplied |  |
| CSV structure | Preserve the captured same-task metadata bytes and exact header ordering, complete field counts, explicit trailing blanks, RFC CSV quoting and relationship closure. NodeSequence is export-local under the source-backed descriptor policy: positive integers and no collision within an authoritative XML file/hierarchy level; numbers may differ across valid exports. Never infer a sparse update from blank cells. | package validation |  |
| Enums | BepType uses Gateway or Processor; datatype VARCHAR2/NUMBER/DATE; flags use canonical Y/N where source proves that domain. Display meanings require supported resolution. | applicable fields |  |

## Mandatory input scope

Use the entity-qualified `references/create-input-policy.json` during design normalization.
Matching keys do not by themselves make a create complete. Supply root Name,
StartDate and EndDate; format StartDate and EndDate; account Ownertype; definition
AccountOptionDatatype, AccountOptionName and DisplayOrder; and translation SourceLang,
AccountOptionName and the owning-definition context. Existing key and relationship
checks still apply. BU_NAME supplies BuName for import resolution; other reviewed
ordinary account options supply their canonical AccountOptionValue and bound evidence.
Sensitive or unknown value rows remain manual and are excluded before these checks.

Do not infer dates, owner type, display order, language or lookup choices. Only the
documented new-definition SecuredFlag=N default is materialized when absent and
recorded in the preview; explicit input is preserved. Mandatory fields explicitly
written as blank are rejected. Ordinary updates need only their requested values
and safe preserved baseline, not all create inputs repeated. Full package operations
require the normalized policy digest; changed policy requires fresh normalization.

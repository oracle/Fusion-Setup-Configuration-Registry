## Qualified Preflight Contracts

Use the shared Fusion REST client through the selected Data Loader workflow for
these GETs. Send REST-Framework-Version: 9, onlyData=true, an explicit fields list,
and follow hasMore/offset pagination. Escape query string literals and URL-encode
parameters; require a complete response and exact local equality before choosing.
BU and ledger visibility do not prove the user's permission to import this task.

Issuer evidence must belong to the selected environment and have recorded export
process provenance. Inspect approved local exports only; acquiring another export
uses shared.setup-export.task-level-export and its approval gate. Reject incomplete
headers, malformed CSV widths and missing identities. Never copy an entire issuer
export into a program import. Resolving PartyNumber does not qualify site selection,
party creation, or the two party CSV ownership contracts; those remain independent.

The 26D operation pages were unavailable during source review. The
[26C business-unit contract](https://docs.oracle.com/en/cloud/saas/financials/26c/farfa/op-finbusinessunitslov-get.html)
and [26B ledger contract](https://docs.oracle.com/en/cloud/saas/financials/26b/farfa/op-ledgerslov-get.html)
are source references for the selected workflow, not evidence of validation on any
particular environment. Issuer resolution also requires the supplied CSV contract
and ISSUER-RESOLVER. No successful import is implied.

Account preflight follows the repository's
[Reporting Currencies dynamic account resolver](../../../general-ledger/manage-reporting-currencies/ora-resource/ora_reference_lookups.md).
Resolve an enabled COA using chartOfAccountsLOV with
q=StructureInstanceNumber={ChartOfAccountsId}. If the target returns a server
error for that documented filter, retain the diagnostic and use the same
read-only collection without q, with bounded complete pagination and exact local
StructureInstanceNumber matching. Do not change framework version or infer an
enabled COA from a failed response. Discover its account attributes
through accountCombinationsLOV/describe with
polymorphicType=accountCombinationsLOV:{ChartOfAccountsId}. Use the target's
segment order and delimiter; never infer positions from JSON key order, assume
five segments, or substitute StructureInstanceId.

For a known same-target combination ID, use the documented PrimaryKey finder
and still compare every segment and COA. Otherwise query accountCombinationsLOV
with framework version 9, q=_CHART_OF_ACCOUNTS_ID={ChartOfAccountsId},
onlyData=true, limit=500 and offset pagination. This dynamic resource is the
exception to the explicit-fields rule: omit fields and collection polymorphicType
so target segment attributes are returned. Add exact segment predicates only when
the describe response marks them queryable. Stop at the first exact full-vector
match because the combination is unique within the COA; then validate all
eligibility flags and dates. Ambiguous segment metadata blocks. A failed query
is unavailable evidence, never proof that the account does not exist.

Oracle's [26D account combinations overview](https://docs.oracle.com/en/cloud/saas/financials/26d/faigl/overview-of-account-combinations.html)
confirms full-combination uniqueness and effective dates. The 26D REST operation
page was inaccessible during verification on 2026-11-17; the accessible older
[26A collection contract](https://docs.oracle.com/en/cloud/saas/financials/26a/farfa/op-accountcombinationslov-get.html)
is retained with that explicit documentation gap. Live response metadata must
qualify the selected target; a repository branch or documentation release does
not prove the target's shape.

## Lookup Execution Rules

| Situation | What Happens |
|---|---|
| An internal AM/VO resolver is known | Retain the source mapping, but do not call ADF, BOSS, SQL or an invented REST endpoint as a fallback. Complete the declared runtime contract first. |
| Authority or endpoint remains unknown | Preserve TBD in the owning resolver row and stop normal planning. No local data authority is inferred from user-supplied values. |
| Exporter omits internal identifiers | The name/code translation requires qualified reference evidence; export exclusion does not establish complete resolution or a public API (EXPORT-ID-EXCLUSIONS). |
| BOSS mapping metadata is available | EXM_MAP_TYPES_B and numeric identifiers describe storage only; they do not establish enabled target codes or import keys (BOSS-MAPPING-TABLE). |
| Lookup or pagination fails | Classify the actual failure; never translate transport, auth or parse failure into a zero-match result. |

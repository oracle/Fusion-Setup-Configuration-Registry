## Design Rules

| Applies When | Severity | Required Lookup | Blocking Condition | Recommendation | Fix Allowed? |
|---|---|---|---|---|---|
| Any requested operation | Blocking |  | Operation is not CREATE, type is not TRAVEL, or a supplied field is outside the executable allowlist | Apply references/create-contract.md and the package helper before handoff; preserve customer intent and reject unsupported scope | No silent conversion to update or deletion |
| Existing issuer/site is reused for program CREATE | Blocking |  | Prior resolve_card_issuer/resolve_issuer_site checks are incomplete, or either party CSV contains data rows, either member is missing, or company references are not resolved | Keep EXM_CORPORATE_CARD_ISSUER.csv and ORA_EXM_SETUP_PARTY_REFERENCE.csv with their exact template headers and zero data rows. Resolve company PartyNumber and address independently (EXISTING-PARTY-PACKAGE). | Header-only members; no issuer/site mutation |
| Creating or changing issuer/site data is requested | Blocking |  | Request exceeds this program-creation path | Route separately to Manage Corporate Card Issuers; shared party-stream mutation and duplicate-row behavior are not qualified here | No inferred issuer/site creation |
| Package authoring or preview is requested | Blocking |  | Local comparison against the selected target template and references/fsm-structure.md fails, or requested-field contracts are missing | Route acquisition through the declared shared export workflow and require catalog, identity, privilege and approval checks before external operations | No handcrafted template or header repair |
| BOSS metadata is used as evidence | Blocking |  | BOSS module access, unpublished flags or never-updateable fields are used to assign FSM behavior | Use BOSS only for the bounded domain/storage facts; qualify FSM contracts independently (BOSS-AUTHORITY) | No automatic contract conversion |
| Audit values, deletion or rename are requested | Blocking |  | Customer supplies audit fields or requests an operation other than CREATE | Reject before packaging. Keep audit headers empty in new rows and preserve exact template metadata; target-generated audit values are checked after import | No audit copying, deletion, rename or update |
| Payment options or runtime transactions are discussed | Blocking |  | UI labels are treated as machine codes, or unpaid-transaction actions are included in setup import | Use the confirmed BOTH and COMPANY codes only for the corresponding customer choices; preserve all other unresolved code mappings and keep unpaid-transaction processing outside this task (COMPANY-PAYMENT-CODES) | No inferred code/default or runtime action |
| Evidence or candidate contains protected values | Blocking |  | Credentials, encrypted-password values, tokens or private keys would enter repository/project files, customer rows would enter tracked/reusable artifacts, or live memory-only captures would be persisted | Follow the selected core retention policy. Keep authorized setup exports only in the active project untracked exports directory; keep reusable evidence sanitized and authentication caches outside the repository | No secret persistence, tracked customer data or session recovery files |

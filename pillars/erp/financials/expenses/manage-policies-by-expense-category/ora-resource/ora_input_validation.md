# Expense policy input validation


Use [ordinary Meals execution](../references/ordinary-meals-execution.md) for
the supported workbook and governed workflow.

## Required Groups

| Requirement Group | Accepted Fields | If Missing | How to Resolve | Applies When | Resolver |
|---|---|---|---|---|---|
| Identity | Exact Policy Name and full rate key including unchanged existing Start Date/End Date | Stop | Supply exact portable identity; no case alias, duplicate key or rename | Selected rows | |
| Create group | One parent and all required associated rates for the owning profile, applicable Currency Code, explicit category enforcement/active-control choices, enabled amounts or flight classes and effective periods | Stop | Supply complete owning-profile inputs; explicit UPPER derives disabled controls No and tolerances empty; rate-bearing profiles require at least one rate, while Entertainment count-only or attendee-information-only modes may omit rates; Airfare has no currency input | New policies | resolve_policy_currency |

## Field Validation

| Check | What Happens | Applies When | Resolver |
|---|---|---|---|
| Workbook | Reject unknown sheets/columns, formulas, duplicate identities, removed inputs and conflicting associations with cell diagnostics; allow multiple policy/rate rows | Parse | |
| Encoding | Boolean inputs use explicit Yes/No to Y/N; category-specific labels use their declared codes; rate date uses YYYY/MM/DD | Supplied fields | |
| Values | Finite decimals, own category name/description bounds and exact field domains; validate all resulting sibling rates, full/NoStart key uniqueness and source-defined inclusive periods after preserving omissions | Create/update | |
| Package | Exact task,19entities/634ordered columns, safe archive paths and row widths; non-target entities header-only in candidate | Baseline/candidate | |
| Entertainment choices | Explicit capture/display/rate-enable Yes/No choices; dependent attendee visibility uses Hidden/Optional/Required; threshold and all rate amounts finite and nonnegative | Entertainment | |
| Entertainment annual period | Yearly Limit requires month 01–12 and a valid day; February permits 1–28 | Entertainment yearly limit enabled | resolve_entertainment_period_month |
| UPPER disabled inputs | Explicit No/N or blank controls become No; blank tolerances become empty. Reject Yes or any nonempty tolerance, including zero, at its source cell. Explicit UPPER resets these five saved values on update; an omitted mode does not | Admitted UPPER policy rows | |

Business compatibility belongs to design enforcement. The fixed input schema is
[intake-fields.json](../references/intake-fields.json); encoding/identity evidence is
in [source notes](../references/source-notes.md).

## Task Nodes

| Rule ID | Node Type | Sequence | Action Type | Transitions | Prerequisites | On Failure | Applies When |
|---|---|---|---|---|---|---|---|
| POLICY.VALIDATE | step | 10 | validate_input | passed->POLICY.REFERENCES;failed->POLICY.RETURN_ISSUES | none | stop | This task is requested |

Airfare, Car Rental, Mileage, Miscellaneous and Per Diem may prepare reviewed
non-key updates to existing compatible records
only through [exact-field application validation](../references/field-uncertainty-validation.md).
Check full identity, retained values, all lookup evidence and resulting rules
first. Shared field-write behavior remains evidence_unresolved. Without exact
implementor acceptance of the displayed plan, return the plan and emit no ZIP.
Keep the uncertainty warning in the blueprint and native preview; this decision
is separate from native import approval. Each create profile has a separate
source-bound admission contract. Car Rental has a source-qualified
SINGLE create profile: include an exact parent and at least one ordinary daily
rate; supply Currency Code, Policy Enforcement and every warning/display/
prevention control explicitly. Validate enabled tolerances, each rate amount,
all operation-bound lookup/currency evidence and the resulting schedule.
Serialize its managed DRAFT/SINGLE/disabled-determinant values explicitly.
Empty cells use the reviewed explicit-null contract; keys and audit values are
server-owned. No live create acceptance is inferred from source qualification.

Airfare has a separate source-qualified no-determinant parent/CATCH_ALL rate
create profile. Require explicit enforcement, display-warning and flight-class
choices and a customer-supplied StartDate. Serialize DRAFT and disabled
role/type/duration flags explicitly; apply deliberate null to inactive role and
duration context instead of retaining EO defaults. Validate complete keys,
inclusive periods, operation-bound lookups, source recipes and exact association.
Server IDs/audits are not inputs. Native create acceptance remains pending.

Miscellaneous new groups require explicit active rate-mode, enforcement,
eligibility and limit controls, every enabled amount and annual reset values.
The ordinary rate identity deliberately leaves type/gender/raw currency empty;
managed DRAFT and disabled determinants follow the exact source recipe.
Mileage new groups require explicit currency, Unit of Measure, all eligibility
and add-on controls, a base rate and every enabled passenger/company rate.
Validate the complete sixteen-coordinate key, SINGLE/RANGE threshold context
and operation-bound dynamic company evidence; never infer a blank sentinel.

Per Diem new groups require explicit SINGLE/SUMUP/TIME_SINGLE/TIME_SUMUP formula,
includes, conversion, deductions and active business fields, exactly one ANCHOR
and every applicable component/range with matching customer dates. Validate
formula-derived time flag, ANCHOR VALID/other admitted rate DRAFT, source-backed
lower coordinates and exact task-owned deduction value companions. Internal
value creates are not workbook targets. New OTHER_STANDARD lower bounds,
equal-hour minute ties, new child/value rows for existing parents and dormant
time MEALS percentage-component creation remain pending with precise diagnostics.
The pinned Oracle-provider/no-child source proof does not prove target parity,
native create acceptance or persistence.

Use each category's own resulting-state validator. Miscellaneous checks all
three rate modes and five limits. Mileage retains its complete sixteen-part key
and base/passenger/company relationships. Per Diem checks policy/line/value
ownership and explicit dependent effects. On updates an omitted input preserves
its baseline value; it does not authorize clearing, generated keys or new rows.
New rows require the separate owning create profile and complete input group.

Accommodations follows the same task workflow with category-specific parent/rate
identities and currency evidence. Daily Limit? must remain Yes on every populated
Accommodations policy row; it is a grey workbook-only indicator, never a CSV
flag. Each resulting rate requires DailyLimit. Role, location, seasonal rate and
gender determinants are excluded; reject incompatible retained settings. Use
[Accommodations evidence](../references/accommodations-profile.json) for the
local authoring extension and its mandatory live reconciliation boundary.

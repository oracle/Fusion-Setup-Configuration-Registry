# Completing existing draft values


An existing policy/rate draft can be incomplete before an update. The
preparation path first establishes exact existing identity, ownership,
lifecycle and no-determinant scope. It then overlays the workbook's proposed
business values and validates the complete resulting parent and every retained
applicable child. Leaving a sibling invalid still prevents a candidate.

The earlier requirement that old editable amounts already be complete was a
local preparation restriction. The reviewed Mileage, Miscellaneous and Per
Diem service imports resolve existing alternate keys and call shared readXML;
they do not independently establish such a pre-existing completeness condition.
This distinction permits conditional preparation of an explicit correction. It
does not prove that a particular FSM update will be accepted by the backend.

Keys, associations, currency, dates, lifecycle/status, determinant scope and
unqualified generated-row behavior remain protected. The update route cannot
make a new row, infer a key/default, clear an InvalidCode, invent a percentage
value row or skip final sibling validation. Exact unresolved business-field
acceptance, native candidate approval and fresh persisted-state reconciliation
remain required.

Per Diem's active SINGLE Meals Calculation Method must resolve to RATE under
the no-ADFDi/no-first-last-day profile, even when Meals is not included. A
missing method can be corrected by an explicit RATE input. An inadmissible
active percentage/spreadsheet method cannot generate MEALS value effects.
Dormant methods in another formula remain preserved, not normalized.
